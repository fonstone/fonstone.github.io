## 1. 什么是 AI Agent

### 1.1 定义

基于 LLM 的智能体（Agent）是一个能够**自主理解环境、进行规划决策、并执行行动以达成特定目标**的计算系统。其核心特征是使用 LLM 作为"大脑"进行复杂的推理和决策。

与传统的 LLM 问答不同，Agent 具备**自主性**和**循环执行**的特点——它能主动地、持续地与环境或工具交互，直到完成任务。

### 1.2 四大核心组件

| 组件 | 作用 |
|------|------|
| **大脑/核心引擎** | LLM 作为认知核心，理解目标、感知环境、推理决策 |
| **规划模块** | 将复杂目标分解为可执行的子任务，动态调整计划 |
| **记忆模块** | 弥补 LLM 上下文窗口限制，分短期/长期记忆 |
| **工具使用模块** | 调用外部 API、执行代码、与物理世界交互 |

## 2. ReAct 框架

ReAct（Reason and Act）是 Agent 领域最基础、最重要的行为框架，通过让 LLM 协同生成**推理轨迹**和**任务相关的行动**来实现复杂任务。

### 2.1 工作流程

ReAct 模仿人类"**思考 → 行动 → 观察 → 思考...**"的循环模式：

1. **思考（Thought）**：LLM 分析当前任务目标和已有信息，生成内心独白
2. **行动（Action）**：LLM 决定并生成可执行的行动，格式化为 `Action: [Tool_Name, Tool_Input]`
3. **观察（Observation）**：执行器调用工具，将结果反馈给 LLM

### 2.2 与 CoT 的结合

ReAct 中的 Thought 本质上是一种**动态的、交互式的思维链**。传统 CoT 是一次性生成所有思考步骤再得出答案，而 ReAct 的思考是**每一步行动前**进行的、**基于最新观察结果**的思维链。这使得 Agent 能够：

- **处理动态环境**：根据工具返回的最新信息实时调整策略
- **进行错误修正**：行动失败可在下一步思考中分析原因并尝试不同方案
- **完成复杂任务**：将大任务分解为"思考-行动"子步骤

## 3. 规划能力

规划能力是衡量 Agent 智能水平的核心指标。目前主流方法从简单到复杂分为多个层次：

### 3.1 基于提示的隐式规划

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **CoT** | "Let's think step by step"引导线性思考 | 实现简单 | 线性不可回溯，一步出错全盘失败 |
| **ReAct** | 思考-行动-观察动态循环 | 鲁棒性强，支持纠错 | 需要工具执行环境 |

### 3.2 基于搜索的显式规划

**Tree of Thoughts（ToT）**：将规划过程构建为一棵"思维树"。从初始问题出发，LLM 生成多个并行的思考路径（树的分支），采用树搜索算法（广度优先或深度优先）探索最优解。允许模型进行**探索、评估和回溯**。

**Graph of Thoughts（GoT）**：对 ToT 的进一步泛化。思维过程是图状的，支持不同路径的**合并（Merge）**和**循环（Cycle）**，可整合多信息流、迭代优化方案。

### 3.3 基于任务分解的规划

训练或提示 LLM 充当"规划器"，将主任务显式分解为依赖图或步骤列表，再由"执行器"逐一完成子任务。结构清晰但预先分解的计划缺乏对动态变化的适应性。

## 4. 记忆系统

记忆模块是 Agent 打破 LLM 上下文窗口限制、实现持续学习和个性化的关键。

### 4.1 短期记忆

- **LLM 上下文窗口**：最直接的短期记忆载体
- **缓冲区管理**：ConversationBufferMemory（完整历史）、ConversationBufferWindowMemory（最近 K 轮）、ConversationSummaryBufferMemory（动态总结）
- **暂存器（Scratchpad）**：记录 ReAct 框架中的"思考-行动-观察"轨迹

### 4.2 长期记忆

长期记忆的核心是"**存储**"和"**检索**"，最主流的是 **RAG 范式**：

**工作流程**：
1. **存储**：使用嵌入模型将文本转换为向量，存入向量数据库
2. **检索**：将当前任务转换为查询向量，在向量数据库中进行相似度搜索
3. **使用**：检索到的记忆作为额外上下文插入 LLM Prompt

**关键工具**：
- **向量数据库**：Pinecone、ChromaDB、FAISS、Weaviate
- **传统数据库/知识图谱**：适用于结构化或关系型数据存储

## 5. Tool Use 与 Function Calling

LLM 调用外部工具的核心机制是 **Function Calling**，工作流程如下：

### 5.1 工具定义与注册

以结构化模式（如 JSON Schema）向 LLM 描述可用工具，包括：函数名称、函数描述（自然语言，LLM 据此判断何时使用）、参数列表。

### 5.2 LLM 决策与调用

LLM 分析用户意图，当觉得需要调用工具时，输出结构化的 JSON 对象：

```json
{
  "tool_call": {
    "name": "get_current_weather",
    "arguments": { "location": "Singapore", "unit": "celsius" }
  }
}
```

### 5.3 执行与结果整合

控制代码解析 JSON，在外部环境中实际执行函数，将结果格式化后再次发送给 LLM，LLM 生成最终的自然语言回答。

## 6. 主流框架对比

### LangChain vs LlamaIndex

| 维度 | LangChain | LlamaIndex |
|------|-----------|------------|
| **核心哲学** | 通用 LLM 应用"编排"框架，关注**工作流构建** | 专注外部数据的"数据"框架，关注**数据流管理** |
| **核心抽象** | Chains、Agents、Memory、Callbacks | Data Connectors、Indexes、Retrievers、Query Engines |
| **最擅长场景** | 构建复杂多步骤 Agent，多工具协作 | 构建高性能 RAG 系统，复杂数据索引与检索 |
| **应用举例** | 研究助手、客服 Agent、自动化流程 | 技术文档 QA、金融分析、个人知识管理 |

**选型建议**：
- **逻辑编排驱动**（需要复杂逻辑编排和多工具协作）→ **LangChain**
- **数据驱动**（需要构建强大知识库和问答能力）→ **LlamaIndex**
- **实际中常结合使用**：LlamaIndex 构建知识库检索工具，接入 LangChain Agent

## 7. 多智能体系统

### 7.1 相比单 Agent 的优势

1. **分工与专业化**：为每个 Agent 设定不同角色和专长
2. **并行处理与效率**：分解子任务同时处理，缩短总时间
3. **鲁棒性与冗余**：单 Agent 故障不影响整体系统
4. **视角多样性与创新**：不同 Agent 从多角度审视问题

### 7.2 引入的新复杂性

1. **通信协议与语言**：需要标准化通信协议和消息格式
2. **协调与协作机制**：任务分配、领导决策、冲突解决
3. **社会行为与动态**：信任、欺骗、联盟等复杂现象
4. **系统状态维护**：所有 Agent 对环境的一致认知
5. **信用分配**：评估各 Agent 在团队任务中的贡献

### 7.3 A2A 框架

A2A（Agent-to-Agent）框架与普通 Agent 框架的**关键区别**在于抽象层次：

- **普通 Agent 框架**关注"个体的实现"——如何构建能干活的个体（应用层）
- **A2A 框架**关注"群体的交互标准"——让所有个体互相交流的"社会规则"（协议层）

## 8. 安全与对齐

### 8.1 核心模型对齐

使用 **RLHF**、**DPO**、**Constitutional AI** 等技术微调基础 LLM，使其遵循"有用、诚实、无害"原则。

### 8.2 工具与权限管理

- **最小权限原则**：只给 Agent 完成任务所必需的最少工具和权限
- 工具白名单、读写执行权限控制、资源限制

### 8.3 人类在环（HITL）

高风险操作前 Agent 必须生成执行计划并暂停等待人类批准；人类可实时监控并随时干预。

### 8.4 沙箱化

Agent 生成的代码或命令在 Docker 容器或虚拟机等沙箱中执行，隔离破坏范围。

### 8.5 其他保障

- 明确的规则与护栏（硬编码规则、正则过滤器）
- 持续的红队测试与行为审计

## 9. Agent 评估体系

评价 Agent 的三大核心维度：

| 维度 | 指标 | 说明 |
|------|------|------|
| **任务成功率** | 最终结果达成比例 | 代码生成能否通过测试、问答准确率 |
| **过程效率** | Token 消耗、API 费用、延迟、步骤数 | 步骤越少越优 |
| **鲁棒性与可预测性** | 错误处理能力、一致性、安全评估 | 面对异常情况的表现 |

### 6.6 评测基准

Agent 评测主要关注两大类：

- **具身 Agent 基准**：如 ALFWorld、MetaWorld、Habitat（机器人控制、导航等）
- **软件 Agent 基准**：如 SWE-bench（代码修复）、WebArena/VisualWebArena（网页任务）、OSWorld（操作系统操控）、GAIA（通用 AI 助手）

基准构建通常包含：任务环境封装、评估指标定义、参考轨迹收集、自动化评分脚本。

---

## 10. 构建复杂 Agent 的主要挑战

1. **规划与推理的鲁棒性**：LLM 推理链条脆弱，容易迷失、陷入循环
2. **可靠且可复现的评估**：开放式任务无唯一正确答案，评估成本高
3. **成本、延迟与可扩展性**：复杂任务需数十甚至上百次 LLM 调用
4. **安全与可控性**：权限管理困难、提示注入攻击、行为不可预测
