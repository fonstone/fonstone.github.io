### 2.2 关键技术细节

**GPU 架构演进**：从 A100 到 H100/H200 再到 B200，每代产品的算力密度、显存容量和互联带宽都在指数级增长。B200 的 FP16 算力已达 4.5 PFLOPS，配 384GB HBM3e 显存。

**网络互联**：大规模分布式训练对网络带宽和延迟极为敏感。NVLink/NVSwitch 用于节点内 GPU 互联（900GB/s），InfiniBand/RoCE 用于节点间通信（400Gbps+）。

**存储分层**：训练数据从对象存储（冷）→ 分布式文件系统（温）→ 本地 NVMe（热）的分级存储策略，平衡容量和吞吐。

### 3.2 并行策略解析

**数据并行 (DP)**：每张卡持有完整模型副本，数据分片。通信量和 batch size 成正比。变体 ZeRO 将优化器状态、梯度、参数分片到各卡，降低显存占用。

**张量并行 (TP)**：单层的矩阵运算切分到多卡上并行执行。通信密集（每层前向/反向各一次 AllReduce），适合节点内高速互联（NVLink/NVSwitch）。

**流水线并行 (PP)**：模型按层切分到多卡，数据像流水线一样依次通过。气泡（bubble）是主要开销，可通过交错调度（interleaved 1F1B）缓解。

**3D 混合并行**：DP + TP + PP 的组合。Megatron-LM 和 DeepSpeed 的典型配置：TP 用于节点内，PP 用于节点间，DP 覆盖全局。

### 5.2 关键优化技术

**KV Cache 管理**：自回归模型生成的每一步都需要历史注意力 KV 对。KV Cache 是推理显存的主要开销。优化策略包括：PagedAttention（vLLM，虚拟内存式的分页管理）、KV Cache 压缩、Offloading 到 CPU/SSD。

**连续批处理 (Continuous Batching)**：传统静态批处理需要等最慢的请求完成。连续批处理在请求完成后立即注入新请求，大幅提升 GPU 利用率。

**量化推理**：INT8/INT4/W8A8 量化将模型参数从 FP16 压缩到更低位宽，显存占用减半甚至 1/4，吞吐量倍增。对精度的影响需要根据场景评估。

**流式输出**：Server-Sent Events (SSE) 逐步返回 token，让用户看到"打字机效果"，极大改善体验。

### 6.2 RAG 管道深度解析

RAG（检索增强生成）是让模型"知道更多"的关键技术。标准 RAG 管道如下：

1. **数据接入**：从 API、数据库、文档系统获取原始数据
2. **文档解析**：将 PDF/Word/HTML 等格式转为纯文本，保留结构信息
3. **分块处理**：将长文档切分为适合检索的片段（chunk），策略包括固定长度、递归分块、语义分块
4. **向量化**：使用 Embedding 模型（如 BGE、GTE、text-embedding-3）将文本转为向量
5. **向量检索**：在向量数据库中进行相似性搜索或混合搜索（向量 + 关键词）
6. **重排与融合**：使用 Reranker 模型对候选结果重新排序，结合多路召回的结果

### 7.2 关键概念解读

**Agent Runtime**：管理智能体的完整生命周期——创建、运行、暂停、恢复、销毁。维护 Agent 的状态机，处理异常和重试。

**Memory System**：短期记忆（当前对话上下文）和长期记忆（跨会话的持久化知识，通常存储在向量数据库中）。记忆是 Agent 实现"反思学习"的基础。

**Tool Orchestrator**：注册外部工具（API、数据库、搜索引擎等），规划工具调用顺序，处理工具输出的解析和错误恢复。

**Planner/Reasoner**：将复杂任务拆解为可执行的子任务序列，并在执行过程中根据反馈调整计划。

**Multi-Agent 协作**：多个专业化 Agent 组成团队，通过消息传递或共享记忆进行协作。常见模式包括：层级式（Manager-Worker）、对等式（讨论式）、流水线式（顺序传递）。

### 9.1 三大支柱

**监控告警 (Monitoring)**：采集系统指标（GPU 利用率、推理延迟、吞吐量、错误率），设定阈值告警。Prometheus + Grafana 是事实标准。

**日志管理 (Logging)**：集中收集各级别日志，支持全文检索和结构化查询。ELK Stack（Elasticsearch + Logstash + Kibana）是经典方案。

## 11. 总结

AI Infra 全栈架构的 8 层模型不是孤立的技术栈，而是一个有机整体：

- **自底向上**：基础设施层提供物理底座 → 训练层负责模型迭代 → 推理层提供服务能力 → 知识层增强领域能力 → Agent 层实现自主智能 → 应用层交付用户价值
- **横向支撑**：AI OS 提供跨层基础能力，可观测性贯穿全栈
- **设计原则**：高性能、高可用、高扩展、安全可信、成本优化、开放兼容

选择开源项目时，核心原则是：**先明确你处在架构的哪一层、解决什么问题，再选择最合适的工具。** 不要用 vLLM 做数据清洗，不要用 Ceph 跑向量检索。

| **Agent** | LangGraph / AutoGen | Agent 编排与多智能体协作 |
| **应用** | Dify / AnythingLLM | 低代码 AI 应用与私有化知识库 |
