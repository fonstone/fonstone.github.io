先看纵向。模型层决定要算多少。系统层决定这些计算排不排得开。芯片层决定每个字节值多少钱。再看横向。语言大模型最成熟，Agent 看 token 和状态，多模态看序列长度，物理 AI 看仿真和精度。

拿语言大模型这一列开个头。70B 的模型，权重按 FP16 每个参数 2 字节算，是 140GB，一张 80GB 的卡放不下。压到 4bit，每个参数半个字节，约 35GB，单卡能装下。

装得下和跑得快是两件事。权重从 140GB 压到 35GB，是四倍。Decode 每生成一个 token 都要把权重从显存读一遍，读一遍的时间下限约等于权重体积除以带宽。[端侧部署那篇](/knowledge/ai/edge-ai-deployment-challenges)给过一组量级，手机 SoC 的内存带宽 50 到 60 GB/s，3GB 的模型按 50 GB/s 读完一遍要 60ms。权重压到四分之一，这一段跟着压到四分之一。可一步解码里还有 KV cache 读写、算子下发、跨卡数据、排队同步，只压权重位宽，这些都没变。端到端时延不会按 4 倍往下走。

## 一、模型层，先把要算的量减下来

### 1. 模型结构，先决定算多少

**这一格在解决什么。** 128K 上下文跑解码，每一步都要看一遍前面全部 token。注意力的计算量随序列长度二次增长，KV cache 的显存随长度线性涨。长上下文里 KV 经常比权重还占地方。模型层能动的，是这两条曲线本身。

**原理。** 语言大模型这边有三条路。

第一条是混合注意力。DeepSeek-V4 的 CSA 每 4 个 token 压成 1 条记忆，再用 Lightning Indexer 挑 512 条来读。HCA 每 128 个 token 压成 1 条全读。SWA 是滑动窗口注意力，前两层只留 128 的窗口。压缩率不同，每层 KV 条目的大小和更新规则就不同，滑窗层还带自己的淘汰策略。PagedAttention 靠一个前提工作，每层 KV 长得一样，可以按固定 token 数切统一的页，一套页表管到底。混合注意力把这个前提打掉了。

第二条是线性注意力。表格里的 GDN 指 Gated DeltaNet。Kimi Linear 用 KDA 与全注意力 MLA 按 3 比 1 交错，把 GDN 那种每个头一个标量门控换成每个通道一个，报告 KV cache 最多省 75%，1M 上下文解码吞吐到 MLA 的 6 倍。留着四分之一的全注意力层，是因为固定大小的状态做精确检索仍然吃力。

第三条是改解码的形状。MTP 在预训练时挂几个未来 token 的预测头，推理时这些头直接当草稿。DLLM 指扩散语言模型，LLaDA 从零训到 8B，打平同尺寸自回归模型，LLaDA2.0 把 AR 权重转成 100B MoE 的扩散模型。

多模态这边，视频的 token 比文本多几个数量级，扩散 Transformer 的注意力又是二次的。DiT-MoE 把一部分 MLP 换成稀疏专家，16.5B 总参数只激活 3.1B。AR+DiT 让自回归模型先出粗粒度的视频 token，DiT 再逐段细化，ARLON 把 30 步降到 5 到 10 步。SLA 把注意力权重分成关键、次要、可忽略三档，关键走稀疏注意力，次要走线性注意力，95% 稀疏下注意力 kernel 快 13.7 倍。

物理 AI 这边，世界模型学环境怎么演化，VLA 把视觉、语言、动作放进同一个模型。它们把结构问题换成物理一致性和长时序误差累积。世界模型的预测 loss 低，不等于策略能完成任务，误差会随 rollout 的 horizon 累积。

**打个比方。** 搬家前先盘东西。CSA 把四件小件捆成一件，HCA 把一大柜封成一箱，SWA 只带眼前要用的几件；GDN 把越写越长的清单换成一页固定大小的记事本；MTP 让搬运工一次记住后面几件货，DLLM 让整批货同时装箱。多模态那边像先拍粗剪再逐段精修，DiT-MoE 按镜头类型分给不同小组，SLA 只精修关键镜头。物理 AI 那边像先在沙盘里推演，再把推演结果变成动作。这个比方只解释先决定带多少、按什么形状带，不解释注意力矩阵怎么算。

**落地与代价。** CANN 的 recipe 用双轨 Cache 接住混合注意力。state cache 按位置覆盖写，经典 KV 按 4 和 128 的最小公倍数分块，128K 序列正好 1024 块。代价是状态变多，prefix cache 命中时不能只读压缩 KV，还得向前补算 128 个 token 重建滑窗。V4.1 的 CSA2 把压缩比收到 1 和 2，靠跨层共享把省下来的量补回来，全局 KV 压到每 token 890 字节，约为 V4-Flash 的 1/4，落盘或放 host 的那份约 1/8。省下来的空间换成 Full、Reindex、Reuse 三种层模式，每个 kernel 的输入布局和 Cache 生命周期都要重写。线性注意力省下 KV，换来的是两种层各一套 Cache 规则，系统层的调度更碎。多模态的代价分别是专家通信、AR 误差累积、SLA 需要微调。

### 2. 强化学习，把偏好变成训练信号

**这一格在解决什么。** SFT 教模型像人一样说话，教不了它哪句更好。同一个问题，两个回答都通顺，一个更准、更合用户口味，SFT 的损失看不出差别。强化学习把这部分判断变成奖励或偏好，再往回改策略。

**原理。**

**三条偏好优化路线。** PPO 是 RLHF 里最常用的策略优化算法。Actor 生成回答，Critic 估价值，Reward model 打分，几套模型一起转。稳，但显存和工程都重。GRPO 把 Critic 拿掉，对同一个问题采样一组回答，奖励在组内减均值除标准差，谁比同组平均好就推谁。DeepSeek-R1 用的是这套。代价是同组样本要够多样，全对或全错的组标准差为零，advantage 全是零，梯度就没了。DPO 再省一步，直接用偏好对构造损失，不训奖励模型，也不在线采样。便宜，但它是离线方法，偏好数据覆盖不到的地方，策略还是会偏。

**VeRL。** 算法之外，RLHF 的工程难点在数据流。Actor、Critic、Reference、Reward 四个模型，各自的并行策略和显存占用都不一样。VeRL 的 HybridFlow 把控制流和数据流拆开，单控制器管模型之间的调度和数据重分片，多控制器管每个模型内部的分布式计算，3D-HybridEngine 负责 actor 在训练和生成之间换并行切分。

**QeRL。** QeRL 把 NVFP4 量化和 LoRA 一起放进 GRPO 训练，量化噪声抬高策略熵，反而让探索更好，rollout 快 1.5 倍以上，32B 模型能在单张 H100 80GB 上做强化学习训练。

**打个比方。** 请搬家师傅。PPO 派一个监工全程盯着，师傅每搬一件就打分；GRPO 不派监工，让几个师傅搬同一批货，谁搬得好大家心里有数；DPO 只看以前的评价单，不现场盯。VeRL 是调度这些师傅的工头，QeRL 是让师傅戴着更糙的手套练，手感变糙，反而逼出更稳的发力。这个比方只解释信号从哪来、要不要现场采样，不解释奖励模型怎么训。

**落地与代价。** PPO 的代价是显存和工程复杂度。GRPO 的代价是组内样本要够多样，全对或全错时梯度消失。DPO 的代价是离线，偏好数据覆盖不到的地方策略会偏。VeRL 把四套模型的并行切分和数据重分片接在一起，收益是 1.53 到 20.57 倍吞吐，代价是调度和显存管理更复杂。QeRL 只在 3B 到 32B 上验过，还得有能跑 NVFP4 的卡。量化噪声不是永远帮忙，噪声太大，策略学到的就是噪声。

Agent 这列的奖励来自环境，工具调用成功、任务完成、多智能体自博弈的胜负都能当信号。多模态这列用视觉语言奖励模型给生成质量打分，ImageReward 是代表性的开源奖励模型。物理 AI 这列还是 SAC、TD3 那一支，连续控制的探索和过估计各有各的解法。

### 3. 以训助推，训练时就把推理的约束吃进去

**这一格在解决什么。** 训练完再量化，低精度误差只能事后补。推理时要用什么格式、什么稀疏、几步去噪、草稿多长，训练阶段就把这些约束放进去，模型提前适应，比事后修补省事。

**原理。**

**QAT。** 量化感知训练 QAT 在训练时模拟量化，checkpoint 落地就是低精度。DeepSeek-V4 的主干走 FP8，路由专家权重走 FP4。

**投机训练。** MTP 和 EAGLE 都把草稿器的训练往推理分布上靠。MTP 在预训练时挂未来 token 的预测头，EAGLE-3 用 training-time test 让草稿器在训练时就吃自己反馈的输出，再融合目标模型多层特征。

**FA 稀疏。** 表格在语言模型这列还写了 FlashAttention 稀疏，也就是 FA 稀疏，在多模态这列写了 QAT+Sparse。训练侧能固定的稀疏模式，推理时 kernel 才能按这个模式跳过整块。

**步数蒸馏。** 多模态和物理 AI 这列的以训助推是步数蒸馏。扩散模型一次生成要几十步去噪，步数蒸馏把几十步压成几步。Self-Forcing 的第一阶段从约 30 步压到 4 步，接着在训练时做自回归 rollout 和 KV 缓存，让训练与推理看到同样的输入分布，最后用 DMD 做分布匹配蒸馏。

**Agent 预取。** Agent 这列的 KV 预取、FFN 预取放在以训助推一栏，落到工程上更像一个约定。训练让 Agent 的工具调用顺序和上下文模板稳定，服务端才敢提前搬下一轮要用的 KV 和权重。

**打个比方。** 按新房的电梯和门宽打箱。QAT 训练时就知道箱子要进多窄的门；投机训练让助手提前记住师傅常搬的几件；FA 稀疏训练时就把不搬的格子标好；步数蒸馏把来回跑十趟压成跑三趟。这个比方只解释训练时适配推理约束，不解释量化误差和蒸馏损失。

**落地与代价。** QAT 的好处是推理侧不用再跑一遍量化校准，坏处是 checkpoint 和硬件格式绑死。芯片不原生支持这个格式，就得反量化，性能和精度一起丢。投机训练的代价是草稿被拒之后 Cache 会脏，得靠环形缓冲回收、梯形掩码隔离，接受率还随数据集变。Self-Forcing 单张 4090 上 480P 流式生成约 10 FPS，首帧延迟约 0.8 秒，代价是超出训练时长的视频仍有质量下降，双向注意力让 KV cache 很难复用，Fast-dLLM 用块级缓存补这一段。Agent 预热错了，搬过来的数据白占带宽。

## 二、系统层，把省下来的时间拿到手

模型层把计算量减了，系统层要处理的是这些计算怎么排。CANN 那篇给过一个具体的反差，V4 把单 token 算力压到 V3.2 的 27%，KV 压到 10%，可 9.66ms 一步摊到 43 层，平均每层 225µs 的预算里，矩阵乘只占一段，剩下的耗在算地址、下发算子、等跨卡数据上。

### 4. 量化稀疏，先让模型装得下

**这一格在解决什么。** 70B 模型 FP16 要 140GB，INT4 后约 35GB，单张 80GB 卡从放不下到放下。这是量化对部署最直接的一次改变。可 4bit 只有 16 个格点，等距整数格点在离群值面前不够用，激活里的一个离群值就能把量程撑到端点，权重大多挤在原点附近，能用的档位没剩几个。

**原理。**

**位宽配方。** 表格里的 W4A4/C8V16 是一套混合配方。W 管权重，A 管激活，C 管 KV cache，V 一般指 attention 里保留高精度的向量状态。权重和激活压到 4bit，KV cache 留 8bit，Softmax 那一段留 16bit。再往下是 W4A4C4|F4，权重、激活、cache 都压到 4bit，attention 里的矩阵乘也走低精。WxAyCz 是这套写法的通用形式，x、y、z 分别是权重、激活、cache 的位宽。

**4bit 的格点。** SmoothQuant 把激活里的离群值平移一部分到权重侧，LLM.int8() 把离群列单独用高精度算。这些方法在 8bit 上很成熟，到 4bit 就不够用了。HiF4 把格点摆成非均匀的，用三层缩放把动态范围拉开。64 个元素共享一个 E6M2 块级 scale，8 元素和 4 元素级各带 1bit 细化因子，元素本身是 E1M2，合计约 4.5 bit 每个值。HiF4 在 Qwen3-8B 的 W4A4 RTN 下保留 BF16 的 96.5% 以上，openPangu-7B 是 97.0%。4bit KV 的压力测试里，MXFP4 在 openPangu-7B 上掉超 60%，HiF4 把 Qwen3-8B 的损失压在 3.15% 和 3.92%。

**attention 和格式转换。** 量化到 attention 里，QK^T 和 PV 两个矩阵乘都可以走 4bit，Softmax 的在线状态留在 FP16。HiFA4 的 C4V16-Aux 就是这么做的。跨芯片还要做格式转换，NVFP4 和 HiF4 都是 4bit，格点和缩放层级不一样，checkpoint 不能直接拷过去，要重新量化、重新校准。表格里写的 NVFP4 转 HiF4 就是这件事。

**稀疏模式。** 稀疏在这一格先回答哪些块可以不算。滑窗和固定块稀疏在训练或编译时定下模式，MoE 路由在运行时按 token 选专家，芯片层再按这些模式跳过。

**打个比方。** 换小箱子，按物品选填充。W4A4/C8V16 是重物用小箱、易碎品留厚垫、常用工具留中号箱；HiF4 是把箱子的刻度重新设计，让大小件都有位置；NVFP4 转 HiF4 是换搬家公司，箱子规格不通用，要重新装；WxAyCz 是每件物品单独定箱。这个比方只解释位宽和格式的取舍，不解释量化的数值误差。

**落地与代价。** 量化的代价是逐层精度回归。敏感层要留高精度，V4 的 RoPE 那 64 维就留在 BF16。上线前要拿自己的校准集重跑一遍，别把论文里的 96.5% 当成自己的模型。HiF4 的优化 kernel 还没做完，论文里拿 MXFP4 的 1.22 倍和 2.14 倍作下界估计。跨芯片格式转换要重新量化，性能和精度都可能掉一截。

Agent 这列的量化在状态和决策路径，多模态在跨模态联合量化，物理 AI 在数值计算的自适应精度。共同点在于先看哪一段对精度最敏感，把高精度留给那一段，其余压下去。

### 5. 调优优化，把脾气不同的活拆开

**这一格在解决什么。** Prefill 一次吃进整段提示词，算力密集，序列长。Decode 一步步吐字，访存密集，batch 小。两种负载挤在同一批卡上，彼此拖着。Decode 内部也不均匀，Attention 是访存瓶颈，FFN 和 MoE 专家是计算瓶颈。

**原理。**

**混合并行。** 混合并行寻优是把 DP、TP、PP、EP、CP、SP 几种切法按模型和阶段组合。TP 切矩阵，通信最密；PP 切层，气泡最多；EP 切专家，all-to-all 最重。CP 和 SP 切长序列，适合长上下文和多模态。没有一套切法通吃，模型大小、序列长度、卡间互联一变，最优组合就变。

**PD 和 AFD。** PD 分离把两阶段放到不同实例，KV cache 通过网络从 P 侧送到 D 侧，LMCache 和 MoonCake 这类存储后端专门管这一步。AFD 再往模型内部切一刀，A 组配高带宽卡跑 Attention，F 组配高算力卡跑 FFN 和 MoE 专家。Step-3 用 StepMesh 做 A2F 和 F2A 的点对点通信，MegaScale-Infer 用 MxN 通信库加 ping-pong 流水把通信和计算重叠起来。

**Agent、多模态和物理 AI。** Agent 这列的调优在多任务调度。多步推理、工具调用、多智能体消息把请求拉得很长，优先级队列、算力弹性分配、结果缓存复用都在这一格。多模态这列多了几个切法。SP 把长序列切到不同卡上，CPP 把 prefill 切成块送进流水线，块与块之间按计算量动态调整。EPD 分离，也就是表格里的 EPDD，再把编码、prefill、decode 三段分开，视觉编码器单独一组卡。物理 AI 这列的调优在数值算法，多重网格、共轭梯度、区域分解、自适应步长，都是把一个大求解拆成能并行的子问题。

**打个比方。** 把搬家拆成装车、运输、卸货。PD 分离是装车和开车各一组人；AFD 是搬重物和搬轻物分开；混合并行是不同楼层、不同电梯安排人手；SP/CPP 是把长走廊切成几段接力；EPD 是把打包、装车、运输分成三个工位。这个比方只解释阶段解耦，不解释 all-to-all 和流水气泡。

**落地与代价。** 每多切一刀，就多一笔传输和一个调度器，故障域也跟着变大。AFD 在 vLLM 里已经以实验插件出现，SGLang 也有实验实现，几套方案的硬件和 Attention 与 FFN 配比不同，吞吐数字不能横着比。EPD 论文报告峰值显存最多降到 1/15，批大小到 22 倍，TTFT 最多降 71%。NVIDIA 的测试里，文本请求的 TTFT 从 92.3ms 降到 53.3ms，图片请求从 289.9ms 降到 200.6ms，但输出变长之后，端到端收益从 20.3% 缩到 5.2%。图片少、输出长的时候，分离反而不划算。

### 6. 通信优化，把等待藏进计算

**这一格在解决什么。** 多卡训练里，GPU 之间的数据传输常常是最大的那块等待。梯度同步、张量并行的激活交换、MoE 的 all-to-all、PD 分离的 KV 传输，都在等网络。

**原理。** 按 GPU 拓扑排集合通信路径，让近的先传。梯度用低精度格式传，只传非零值，Top-k 稀疏化和 QSGD 都在压传输量。计算和后台传输排到不同流上重叠，把流水线并行的气泡填上。MoE 的专家并行走 all-to-all，每个 token 都要跨卡找专家，通信量随稀疏度上升，细粒度 EP 把 Dispatch、Linear、Combine 切成 wave，让计算、通信和结果发送同时走。

Agent 这列的通信在消息层，多智能体消息压缩、事件驱动通信、分层拓扑。多模态在特征层，跨节点特征压缩、按优先级分带宽、模态间流水线。物理仿真在边界层，区域分解只交换子域边界，异步通信加计算重叠。

**打个比方。** 搬家车队用对讲机。集合通信是统一喊话，低精/稀疏通信是只说关键信息，计算通信并行是边开车边对讲。这个比方只解释通信和计算怎么重叠，不解释 ring allreduce 的带宽模型。

**落地与代价。** 等待被计算盖住，通信占比能降多少，取决于模型、并行策略和互联。代价是流多了同步和资源争抢也多，低精度通信要做精度回归，稀疏通信要求稀疏模式固定。换一个集群，这些数字都要重测。

### 7. 预取算法，让数据比计算先到

**这一格在解决什么。** Agent 连着调十次工具，每一轮都要重新读系统提示词和前面几轮的 KV。前缀缓存没命中，整个 prefill 要重算。FFN 权重这一层用完就换，下一层要用时再搬。KV 页散落在显存里，一次读一小块，带宽吃不满。

**原理。** 前缀缓存命中直接跳过整个 prefill。KV 预取和 FFN 权重预取把下一轮要用的数据提前搬进高速缓存，KV 聚合访存把零散的小块访问并成连续大块。CANN 的 V4 recipe 给过落盘三档，Full 存全部滑窗 KV 零重算，Periodic 每隔 p 个 token 存一个窗口，Zero 完全不存、命中后重算尾部，按 SSD 带宽和前缀命中率选。

复用和淘汰是同一件事的两面。前缀缓存要按前缀树组织，淘汰时先扔冷门分支。KV 聚合访存要把分散的页拼成连续块，拼的时候多一次拷贝，读的时候少很多次小访问。FFN 权重预取更赌，MoE 路由没出来之前不知道下一层要用哪个专家，猜错了就白搬一趟。

**打个比方。** 提前把下一趟要用的箱子搬到电梯口。KV 预取是提前把对话历史放到门口，FFN 权重预取是提前把工具拿出来，复用/淘汰是常用的留在门口、不常用的放回楼上，KV 聚合访存是把散落的小件装进一个大箱。这个比方只解释提前搬运，不解释命中率和覆盖写策略。

**落地与代价。** Agent 的状态比单轮对话多得多，命中率直接决定服务成本。代价是预测错了白搬一趟还占带宽，Cache 生命周期跟着变复杂，V4 命中前缀后还要补算 128 个滑窗 token。前缀缓存按前缀树组织，淘汰策略偏了，命中率会掉得很快。

### 8. 投机推理，一次别只吐一个字

**这一格在解决什么。** 自回归解码一步一个 token，权重读一遍只换出一个字。权重读取是 Decode 的大头，一次只出一个字，等于把最贵的一段复用了一次。

**原理。** 投机解码让草稿模型先出一段候选，主模型一次并行验证，接受一致的前缀。MTP 是训练内置的草稿。DeepSeek-V3 用顺序因果链，每个 MTP 头以前一个头的输出为条件。V4 保留原生 MTP，高吞吐场景用 MTP1，低时延场景用 MTP3。EAGLE-3 把特征预测改回直接 token 预测，用 training-time test 让草稿器在训练时就吃自己反馈的输出，再融合目标模型多层特征。DFlash 把草稿从串行改成块扩散，一次前向填满整个块，起草延迟和草稿长度无关。DSpark 再把半自回归和置信度调度加上去，草稿块里用轻量串行头补前缀依赖，验证时按置信度和系统负载决定验多长。

多模态理解这列的投机省的是语言模型解码那一段，视觉编码器的开销不在这条链上。公开做法里，候选 token 由草稿模型先给，主模型验证。物理仿真的投机在时间步，预估校正法用大步长推测再修正。

**打个比方。** 老师傅带徒弟。MTP 是训练时就让徒弟学会猜下一批货，EAGLE-3 是徒弟看师傅的手法猜，DFlash 是徒弟一次填满一整箱，DSpark 是徒弟猜完后按把握大小决定验多少。这个比方只解释一次权重复用摊到多个 token，不解释接受率和树状候选。

**落地与代价。** 主模型调用次数少了，权重读取次数跟着少。代价是接受率随数据集变，草稿被拒之后 Cache 会脏，得靠环形缓冲回收、梯形掩码隔离。官方 benchmark 里 MTP3 平均 3 个草稿接受 1.44 个，MTP1 平均 1 个接受 0.7 个。EAGLE-3 论文报告最高 6.5 倍加速，比 EAGLE-2 高约 1.4 倍，SGLang 里 batch 64 的吞吐高 1.38 倍。DSpark 在 V4-Flash 的 80 tok/s/user 和 V4-Pro 的 35 tok/s/user 下，聚合吞吐分别提升 51% 和 52%。batch 一大，连续批处理把并行优势摊薄，加速比就往下走。DSpark 的置信度头还要校准，校准偏了，验多长都不对。

## 三、芯片层，把每字节的成本压到物理极限

软件量化只是模拟低精度。芯片得能原生吃下这个格式，省下的位宽才换成算力和功耗。

### 9. 低精计算，4bit 的难点在格点怎么摆

**这一格在解决什么。** ACL 2026 那篇昇腾低比特评测里，INT4 在 W4A4 下直接失效，连 SmoothQuant 和 SVDQuant 都救不回来。4bit 只有 16 个格点，等距整数格点遇到一个离群值，量程就被撑到端点，权重大多挤在原点附近，能用的档位没剩几个。

**原理。**

**HiF4 的格点。** 浮点格式用指数位换动态范围，原点密、两端疏。HiF4 把缩放拆成三层，64 个元素共享一个 E6M2 块级 scale，8 元素和 4 元素级各带 1bit 细化因子，元素本身是 E1M2，合计约 4.5 bit 每个值。在 Qwen3-8B 的 W4A4 RTN 下，HiF4 保留 BF16 的 96.5% 以上，openPangu-7B 是 97.0%。4bit KV 的压力测试里，MXFP4 在 openPangu-7B 上掉超 60%，HiF4 把 Qwen3-8B 的损失压在 3.15% 和 3.92%。HiF8 在昇腾上跑 Qwen3-30B-A3B，prefill 比 BF16 快 1.17 倍，decode 快 1.47 倍。

![INT4 等距格点、浮点 4bit 非均匀格点与 HiF4 三层缩放的对比，结构参数来自 arXiv 2602.12635](/images/ai-sandbox-engineering/lowbit-format.svg)

*图 4，同样 4bit，格点怎么摆决定模型能不能用。数轴是示意，位置不代表某一格式的精确编码。*

**矩阵乘和 FlashAttention。** 矩阵乘和 FlashAttention 是两条不同的低精路径。矩阵乘的低精在 Cube 这类矩阵单元上做，权重和激活都压到 4bit，累加留 FP32。FlashAttention 的低精更麻烦，QK^T 和 PV 两个矩阵乘可以压，Softmax 的在线状态不能压。HiFA4 的 C4V16-Aux 把 QK^T 和 PV 都压到 HiF4，Softmax state 留 FP16，辅助的 Q-Mean GEMV 只占 QK^T Cube 成本的 0.75% 以下。

**Softmax 近似。** Softmax 里的 exp 是超越函数，硬件直接算很贵。查表把 exp 换成 SRAM 里的一次查找，精度靠表的密度和插值。低精度 Softmax 很容易把模型打崩，DB-Attn 论文里 vanilla BFP 做 Softmax 让 LLaMA3 的零样本平均准确率掉了 33.81%，加查找表后 Softmax 提速 74%。

**内部代号。** 表格把 A6、A7 这档的低精格式写成 HiF4，A8 这档写成 P_HiF4。HiF4 有公开定义，P_HiF4 查不到对应解释，本文不展开。WxAyCz 是通用位宽配方，x、y、z 分别是权重、激活、cache 的位宽。

**打个比方。** 称重秤的刻度。HiF4 是把刻度做成中间密、两头疏；MM/FA 低精是称大件和小件用不同的秤；Softmax 近似是用查表代替现场算；P_HiF4 是另一种刻度；WxAyCz 是每件货单独定刻度。这个比方只解释数值格式怎么摆格点，不解释硬件乘加单元。

**落地与代价。** 低精计算的代价是格式绑定。芯片不原生支持，低精只省存储不省算力。HiF4 的优化 kernel 还没做完，论文里拿 MXFP4 的 1.22 倍和 2.14 倍作下界估计。敏感层要留高精度，V4 的 RoPE 那 64 维就留在 BF16。上线前要逐层做精度回归，别把论文里的 96.5% 当成自己的模型。

### 10. 稀疏计算，让零值真的不被算

**这一格在解决什么。** 软件稀疏只是存的时候省地方，硬件稀疏要算的时候直接跳过零值，这才拿得到加速。非结构化稀疏的零值位置随机，硬件得逐格判断有没有值，查询开销把省下的计算吃回去。

**原理。** 表格把 A6、A7 这档写成 Block 稀疏，A8 这档写成 4 比 2、8 比 4 这类结构化稀疏。公开材料里查不到 A6/A7/A8 的对应型号，能对上的是两种粒度。Block 稀疏按块剪，一个块全零就整块跳过，元数据少，但块大了，能剪的粒度就粗。4 比 2、8 比 4 是 50% 的固定比例，每 4 个或每 8 个连续权重里留 2 个或 4 个非零，硬件按固定节奏取数。2 比 4 的每个非零值用 2bit 位置元数据，一组两个值共 4bit。8 比 4 的组更大，每个位置要的位数更多，元数据也更长。

Ampere 的稀疏张量核认 2 比 4 这个节奏，每四个连续权重里两个为零，压缩后只存非零值，每个非零值旁边附 2bit 位置元数据。硬件按元数据从另一路输入里取对应的值做乘加，节奏固定，不用逐格判断。官方给的是 2 倍峰值吞吐，TensorRT 8.0 上超过 30% 的性能每瓦提升，ResNeXt 上实测 36%。

![2 比 4 结构化稀疏矩阵压缩为非零值与 2bit 元数据，参数与收益来自 NVIDIA Ampere 官方博客](/images/ai-sandbox-engineering/sparsity-24.svg)

*图 5，压缩前后的矩阵。右侧黄色小格是位置元数据，硬件靠它提前知道该取哪几个非零值。*

Block 稀疏的账不一样。块大，元数据少，硬件跳过整块的成本低。块小，精度好，元数据多。4 比 16 这种块粒度在 CNN 加速器上出现过，LLM 的权重块更大，块稀疏的精度损失要单独验。MoE 的路由结果是天然的稀疏激活，稀疏激活硬件调度按需搬专家权重。它和 2 比 4 不是一回事，前者跳的是整个专家，后者跳的是权重里的零值。

**打个比方。** 装车时按货架格子搬。Block 稀疏是整格空了就跳过；4 比 2、8 比 4 是每四个或每八个格子固定留几个非零，搬运工按固定节奏取货。这个比方只解释结构化稀疏怎么跳过零值，不解释元数据怎么编码。

**落地与代价。** 稀疏的代价是剪枝加重训，模式固定，换硬件可能白剪。稀疏形状如果不规则，硬件跳过零值省下的算力，可能被取元数据的开销吃回去。Agent 这列的稀疏在图结构和决策路径，多模态在注意力和卷积，物理 AI 在有限元刚度矩阵。有限元刚度矩阵很稀疏，直接存非零元，稀疏矩阵计算核配合预条件共轭梯度。

### 11. 近存与存内，把计算搬到数据旁边

**这一格在解决什么。** Decode 的能耗大头在把权重从 HBM 搬进计算单元，乘加本身反而不贵。内存墙的定义来自 Wulf 与 McKee（1995），处理器算力增长远快于内存带宽，数据搬运成为瓶颈。Transformer 推理是访存密集型负载，权重和 KV cache 的反复搬运让这堵墙格外显眼。

**原理。** 近存计算把计算单元放到存储旁边，HBM 堆在封装内，3D 堆叠 SRAM 放高频算子。Attention 的近存在 KV cache，长上下文里 KV 的读写是访存大头。FFN 的近存在权重，每个 token 都要把 FFN 的权重读一遍，专家越多，读得越散。存内计算更往前一步，直接在存储阵列里做矩阵乘，ISAAC 那类 ReRAM 原型把权重存进模拟阵列，省掉权重搬运。

Agent 这列的近存服务状态读写，工具调用路由表在 SRAM 里查表，Agent 状态存近处。多模态的近存服务特征提取，视觉特征和跨模态融合的计算放在近处。物理仿真的访存密度最高，网格数据放近存，稀疏矩阵运算和上一节的稀疏核配合。

**打个比方。** 把拆箱台搬到楼道口。Attention 近存是把常用的 KV 放在手边，FFN 近存是把工具放在手边，存内计算是直接在箱子里组装。这个比方只解释搬运距离，不解释模拟计算的器件误差。

**落地与代价。** 搬运的能耗和延迟从架构上减少，端侧和可穿戴设备的功耗预算才可能成立。代价在容量和工艺，精度也难控。近存的 SRAM 容量有限，放不下整个模型。存内计算的模拟阵列有器件误差和一致性难题，工具链几乎要从头搭。学术原型离量产还有距离。

## 四、四类场景各卡在哪一行

语言大模型的三层最完整，压缩注意力、投机解码、分页 KV、4bit 格式都有公开实现，卡点落在长上下文的访存和每层不一致的 Cache 规则上。

Agent 的钱花在 token 和状态。多步推理、工具调用、多智能体消息把上下文拉得很长，缓存命中率决定单次任务成本，端侧部署又把芯片层的低精度和功耗一并拉进来。Agent 这列的强化学习和调度，是四类场景里最依赖工程的一行。

多模态的序列长度是第一显存约束。视频的 token 数比文本多几个数量级，DiT-MoE 扩容量，AR+DiT 拆长视频，SLA 压注意力，EPD 把编码、prefill、decode 分开。每一步都在换一类开销。

物理 AI 的仿真吞吐决定研发周期。世界模型和 VLA 把感知、语言、动作放进同一个模型，对高带宽和高精度的需求也最强，芯片定制刚开始。这一行离成熟最远。

| 70B 从 140GB 压到 35GB，效果保留 95% 以上 | 140 与 35 是按 2 字节和 0.5 字节自算。96.5% 与 97.0% 来自 Qwen3-8B 与 openPangu-7B 的 W4A4 RTN | 两个数各自成立，拼成一句就换了模型和口径，且不含 KV、激活与框架开销 |
| 128K 长上下文显存降低 60% | V4 在 1M 上下文下 KV 是 V3.2 的 7% 和 10%，Kimi Linear 最多省 75% KV | 基线模型、精度、batch 都没给，两组数字口径不同，不能相加 |
| EAGLE-3 加速 6.5 倍 | 论文报告最高 6.5 倍，SGLang batch 64 吞吐 1.38 倍 | 最高值是特定任务和接受率下的，不能直接换成线上 TPOT |
| DSpark 提升 51% 到 52% | V4-Flash 在 80 tok/s/user、V4-Pro 在 35 tok/s/user 的 SLA 下 | 这是聚合吞吐，单用户速度和聚合吞吐要分开看 |
| EPD 显存降到 1/15，TTFT 降 71% | EPD 论文，图像密集、短输出场景 | 图片少、输出长时收益缩到 5.2%，不能当通用加速比 |
| 2 比 4 稀疏吞吐翻倍 | NVIDIA Ampere 官方博客，峰值吞吐 2 倍 | 峰值是硬件上限，ResNeXt 实测性能每瓦 36%，两者不是一回事 |
| A6、A7、A8 与 P_HiF4 | 公开资料里没有对应型号 | 本文按公开的 HiF4、2 比 4、4 比 16 讲，不套内部代号 |

还有一类数字容易被当成可叠加的收益。单算子加速比不能加到整网时延上，离线推理的吞吐不含 Serving 调度，MTP 的接受率随数据集变。CANN 那篇把这些限定列得很细，跨平台比吞吐还要看两边的精度方案是否一致。沙盘里的倍数先当方向，别当预算。

## 六、收口

判断一行值不值得做，先问它把瓶颈从哪一类搬到哪一类，又多留了哪类状态。压缩注意力把 KV 变小，多出来的是几套 Cache 规则和一次前缀补算。投机解码把权重复用摊薄，多出来的是草稿回滚和接受率。AFD 把两类计算分开，跨节点传输和流水气泡跟着进门。低精度格式则把自由度收走，checkpoint 从此跟着硬件走。

上线前拿自己的序列长度分布、batch、草稿接受率和逐层精度回归重跑一遍，再决定上哪一行。沙盘里那些倍数，先当方向。
