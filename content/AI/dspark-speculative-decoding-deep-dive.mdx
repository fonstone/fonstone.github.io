DSpark [1] 是 DeepSeek 刚开源的一个投机解码(Speculative Decoding)框架。论文的核心目标是解决当前投机解码技术中的两个主要瓶颈：**草稿质量衰减** 和 **验证效率低下**。简单来说，当前的 draft model 虽然能快速生成一长串候选 token，但由于缺乏上下文依赖，导致草稿越往后，质量越差，接受率迅速下降。同时，无论草稿质量如何，盲目地将整个长草稿交给目标模型进行验证，会在大概率被拒绝的 token 上浪费宝贵的计算资源。

针对这两个问题，DSpark 提出了两个互补的创新机制：**半自回归生成 (Semi-Autoregressive Generation)** 与 **置信度调度验证 (Confidence-Scheduled Verification)**。半自回归生成通过混合并行主干网络与轻量级串行模块，在保持生成速度的同时显著改善草稿后半部分的质量；置信度调度验证则训练置信度头预测每个草稿词元的接受概率，并由硬件感知调度器根据系统实时负载动态决定验证长度，在低负载时追求单用户速度，高负载时裁剪低置信度草稿以确保系统吞吐量稳定。

接下来我们先从投机解码的原理谈起，为什么一个草稿模型投机解码的结果和目标模型推理的结果是等价的。然后第一章对一些典型的投机解码模型的演进做一个回顾。再详细分析 DSpark，本文目录如下：

## 0. 什么是投机解码？

### 0.1 从一个通俗的故事讲起

想象一下你正在和一位学识渊博但打字很慢的专家(比如一位老教授)在线聊天。这位老教授就是我们的 **目标模型 (Target Model)**，比如 GPT-4。它的特点是：

- **权威**：每个字都深思熟虑，绝对正确。
- **缓慢**：生成每个字都需要消耗大量时间。

你问了一个问题，然后眼巴巴地看着他一个字一个字地往外蹦。为了加速这个过程，我们给他配一个反应飞快的博士生助手。这个助手就是 **草稿模型 (Draft Model)**，比如一个规模小得多的语言模型。它的特点是：

- **敏捷**：打字飞快，能瞬间生成一大段话。
- **不靠谱**：知识储备不如教授，经常会猜错或说错话。

投机解码(Speculative Decoding)就是这套"教授+学生"的协同工作流程：

1. **教授起草**：教授先写下第一个字。
2. **学生抢答 (投机)**：博士生看到开头，立刻"投机性地"猜出后面可能的内容，生成一串草稿。
3. **教授批改 (验证)**：教授拿到这份草稿。他不用自己一个字一个字地想了，只需要批改就行。他把学生的草稿和自己脑子里想说的话，在一次思考中(一次前向传播)进行并行对比。
4. **接受并修正**：教授会接受学生猜对的所有部分。在第一个猜错的地方，他会亲自写下正确的词。对于学生草稿中剩下的部分，则全部丢弃。
5. **完成一轮**：这一轮解码，系统最终输出了多个词。但请注意，教授只亲自"思考"了一次，却得到了多个词的输出。相比于他自己一个字一个字地思考多次，速度大大提升了。
6. **循环往复**：接下来，学生会根据新的结尾，再次进行抢答，开始新一轮的投机。

**核心思想**：用一个廉价、快速的草稿模型的大量猜测，来换取昂贵、缓慢的目标模型少量但高效的验证。只要草稿模型猜得越准，整体的加速效果就越好。

### 0.2 投机解码的数学原理

##### 基本设定

- *目标模型*：在给定前文的情况下，对下一个 token 的输出概率分布为 p(x)。我们简写为 p。
- *草稿模型*：在同样的前文下，输出概率分布为 q(x)。我们简写为 q。

我们的目标是，以某种方式从 p 中采样一个 token，但要尽量避免直接计算和调用昂贵的 p。这背后的数学原理是拒绝采样(Rejection Sampling)。

假设我们想从一个目标分布 p 中采样，但直接采样很困难。不过，我们可以很容易地从另一个提议分布 q 中采样，并且存在一个常数 M，使得对于所有的 x，都有 p(x) &lt;= M*q(x)。拒绝采样的步骤如下：

1. 从提议分布 q 中采样一个候选值 x。
2. 从均匀分布 U(0,1) 中采样一个随机数 u。
3. 如果满足如下条件 u &lt; p(x)/(M*q(x))，则接受样本 x。
4. 否则，拒绝 x，回到第 1 步。

可以证明，通过这个过程接受的样本，其分布 *恰好是* 目标分布 p。

在投机解码中，我们将这个思想应用到序列生成上。假设草稿模型生成了 K 个 token 的序列。目标模型需要对它们进行验证。验证过程从左到右：

1. 草稿模型在第 i 步生成了 token x_i，其概率为 q(x_i)
2. 目标模型在第 i 步如果自己生成，会以概率 p(x_i) 生成 token x_i
3. 我们进行一次"抛硬币"实验。以概率 min(1, p(x_i)/q(x_i)) 接受 token x_i。
   - 如果 *接受*，我们就继续验证下一个 token。
   - 如果 *拒绝*，那么验证过程立刻停止。我们不仅丢弃 x_i，还丢弃它之后的所有草稿 token。

##### 恢复目标模型分布证明

给定离散分布 p, 和一个从 q 中采样的草稿样本，令 x 为最终得到的样本。x 为真的情况有两种：我们要么采样得到 x 并接受它，要么在 y (无论其值为何)被拒绝后重新采样得到 x。

这等价于：

- **路径一："英雄所见略同" (草稿被接受)**：学生写 x 的概率是 q(x)。教授认可的概率是 min(1, p(x)/q(x))。两者相乘，这一路径的总概率是 min(q(x), p(x))。
- **路径二："另请高明" (草稿被拒绝，重新采样)**：发生拒绝的总概率乘以拒绝后选中 x 的条件概率，最终这条路径的总概率是 max(0, p(x) - q(x))。

**最终汇总**：两条路径的概率加起来正好等于教授最初想选 x 的概率 p(x)。账平了！

### 0.3 代码实现

例如在 DSpark 代码中 `deepspec/eval/base_evaluator.py` 中有一个常见的验证函数 `verify_draft_tokens`，它使用 target model 对 draft model 提出的候选 token 进行验证，算法流程：

1. 将 draft tokens 序列一次性送入 target model 做并行前向传播，得到每个位置的概率分布。
2. 对每个 draft token 位置，计算接受概率 `min(1, p_target(x)/q_draft(x))`，通过随机数与该概率比较决定是否接受。
3. 使用 cumprod 实现前缀截断语义：一旦某个位置被拒绝，后续所有位置均被拒绝。
4. 若存在被拒绝的 token，从残差分布 `norm(max(0, p_target - q_draft))` 中采样新 token；若全部接受，则从 target model 最后位置的分布中采样一个 bonus token。
5. 拼接被接受的 draft tokens + 新采样的 token 作为最终输出。

```python
# Step 1: Target Model 并行前向传播
draft_token_count = int(proposal.draft_token_count)
verify_length = draft_token_count + 1
verify_position_ids = position_ids[:, start : start + verify_length]

target_output = target_model(
    input_ids=proposal.verify_input_ids,
    position_ids=verify_position_ids,
    past_key_values=past_key_values_target,
    use_cache=True,
    output_hidden_states=True,
)

target_probs = logits_to_probs(target_output.logits, float(temperature))

# Step 2: Speculative Sampling
if draft_token_count > 0:
    proposed_tokens = proposal.verify_input_ids[:, 1:]

    selected_target_probs = gather_token_probs(
        target_probs[:, :-1, :], proposed_tokens,
    )

    selected_draft_probs = gather_token_probs(
        proposal.draft_probs, proposed_tokens,
    ).clamp_min(1e-8)

    accept_prob = torch.clamp(
        selected_target_probs / selected_draft_probs, max=1.0,
    )

    accept_mask = (torch.rand_like(accept_prob) < accept_prob).to(torch.int64)
    accept_prefix_mask = accept_mask.cumprod(dim=1)
    accepted_draft_tokens = int(accept_prefix_mask.sum(dim=1)[0].item())
```

### 0.4 核心参数三元组

Leviathan et al. 建立了完整的理论分析框架，揭示投机解码的性能被三个核心参数完全支配：

- **接受率 alpha**：衡量"草稿有多靠谱"。alpha = 1 - d_TV(p, q)，即目标分布 p 与草稿分布 q 之间全变差距离的互补。直觉上 alpha 等于两个分布的"重叠面积"。
- **成本比 c**：衡量"起草有多便宜"。c = t_draft / t_target，实践中 c 在 0.05-0.2 之间。
- **草稿长度 gamma**：衡量"每轮猜多少个"。

三者共同决定了端到端加速比：

```
speedup = E[K] / (gamma * c + 1)
```

分子 E[K] 是每轮期望接受的 token 数，分母是每轮的时间成本。

## 1. Draft Model 算法介绍

投机解码的演进可分为以下几个关键阶段。

### 1.1 自回归投机解码

#### 1.1.1 Speculative Decoding

从 2022 年底的论文《Fast Inference from Transformers via Speculative Decoding》开始，采用一个参数量远小于目标模型的独立自回归模型串行生成 gamma 个候选 token。在 T5-XXL (11B) 上使用 T5-small (77M) 作为草稿模型。

#### 1.1.2 Speculative Sampling

2023 年《Accelerating Large Language Model Decoding with Speculative Sampling》中，Draft Model 采用和 Target 模型同样的分布式部署，并构建了一个宽而浅的 Draft Model。虽然 Hidden-dim 和 Target 模型接近，但模型深度很浅只有 8 层，因此 draft 延迟低很多倍。

#### 1.1.3 BiLD

来自 2023 年的《Speculative Decoding with Big Little Decoder》。放弃了 Speculative Sampling 的概率无损要求，Draft Model 基于自身置信度决定何时"求助"Target Model。

- **Fallback 策略**：如果 max(q(x)) &lt; threshold，则回退到大模型。
- **Rollback 策略**：如果存在最小的 i 使得 d(p_i, q_i) > threshold，则回滚预测。

它允许微小质量损失(&lt;0.5 BLEU)，并首次引入*动态起草长度*概念。

#### 1.1.4 Self-Speculative

论文《Draft & Verify: Lossless Large Language Model Acceleration via Self-Speculative Decoding》采用原始模型"跳层"的方式做 Drafting。通过贝叶斯优化选择跳层方案，并引入自适应 Draft 退出机制。

### 1.2 树状投机解码

#### 1.2.1 SpecInfer

SpecInfer 同时考虑多条推测候选，并将它们组织为一棵 **token tree**。使用 **树并行解码机制**，在单次 LLM 解码步骤中并行验证 token tree 中所有候选序列的正确性。

Draft 模型通过直接使用同族预训练小模型 + Boosting 微调构建。Speculative Inference 阶段为每个 SSM 生成输出树(每个 token 取 top-k)，然后合并，并通过修改 mask 矩阵使模型可以一次验证多个 sequence。

### 1.3 多头/特征层

#### 1.3.1 Medusa

论文《Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads》在原模型最后一层 Embedding 后增加多个 Medusa Head 预测，然后组合构建成树，并通过 tree attention mask 在一次前向传播中验证所有候选。

Medusa 开创了利用模型自身进行投机预测的研究方向。

#### 1.3.2 Lookahead

《Break the Sequential Dependency of LLM Inference Using Lookahead Decoding》将自回归解码与雅可比迭代法联系起来。将整个生成序列看作一个大型非线性方程组的解，通过雅可比迭代并行求解。

#### 1.3.3 EAGLE 系列

EAGLE（Extrapolation Algorithm for Greater Language-model Efficiency）系列有三篇论文，核心思想是：在特征层(而非 token 层)进行自回归预测，并通过输入"提前一步的 token"来消除采样不确定性。

- **EAGLE-1**：在特征层做自回归再通过 LM Head 转换为 token，效果优于直接预测 token。把采样结果(token)作为额外输入告诉草稿模型，进一步大幅提升加速比。
- **EAGLE-2**：引入可动态调整的草稿树，通过 Expand 和 Rerank 两个阶段动态构建最优树结构。
- **EAGLE-3**：在输入特征上采用低、中、高层的特征序列融合处理。引入 Training-Time Test 改进，发现 Scaling Law——为草稿模型提供的训练数据越多，推理加速比就越高。

### 1.4 MTP 训练集成

#### 1.4.1 Meta MTP

Meta 的论文提出了一个问题：**为什么不在预训练阶段就赋予模型投机能力？** 通过添加 n 个独立输出头同时预测未来 n 个 token，实现了训练增强与推理加速的统一。

#### 1.4.2 DeepSeek-V3 MTP

DeepSeek-V3 将并行独立头改为**顺序因果链**（每步以前一步输出为条件）。将 MTP 定位为"训练为主、推理复用"——训练时密集化信号提升数据效率，推理时 MTP 模块直接作为草稿模型。

### 1.5 DFlash

前四个阶段的所有方法都受制于同一个根本性约束：**自回归串行起草**。即使 EAGLE 的草稿模型仅有 1 层，生成 gamma 个 token 仍需要 gamma 次串行前向传播。起草延迟随草稿长度线性增长。

论文《DFlash: Block Diffusion for Flash Speculative Decoding》的突破是：将草稿模型重新定位为一个 **并行的扩散适配器**，一次性填充所有位置。

#### 1.5.1 关键创新

**创新一：并行扩散起草**。输入是一个锚点 token 加上 (gamma-1) 个 [MASK] 占位符。块内所有位置使用 **双向注意力**，单次前向传播后一次性输出所有位置的预测。**延迟与 gamma 无关**，生成 16 个 token 和生成 4 个 token 的延迟几乎相同。

**创新二：KV 注入条件化**。让草稿模型在 **每一层** 都能直接"读取"目标模型的信息——从 Target 模型的等距分布的 5 层中提取隐藏状态，融合为上下文特征，然后在草稿模型的每一层将融合特征拼接到 Key 和 Value 中。

```python
# KV 注入的核心操作
k = torch.cat([k_ctx, k_noise], dim=1)  # [目标特征的Key | 草稿自身的Key]
v = torch.cat([v_ctx, v_noise], dim=1)  # [目标特征的Value | 草稿自身的Value]
```

#### 1.5.2 并行扩散起草过程

```python
自回归起草 (EAGLE-3):
  t=1: [anchor] -> token_1
  t=2: [anchor, token_1] -> token_2
  t=3: [anchor, token_1, token_2] -> token_3
  ...共需 gamma 次前向传播

块扩散起草 (DFlash):
  t=1: [anchor, MASK, MASK, ..., MASK] -> token_1, token_2, ..., token_gamma
  ...仅需 1 次前向传播
```

#### 1.5.3 训练过程

训练时采用随机锚点采样、稀疏注意力掩码和位置加权损失。关键设计包括共享嵌入层、共享 LM 头，只训练 Transformer 层。

### 1.6 DDTree

DDTree 在 DFlash 的基础上不丢弃 draft_logits 中的丰富信息，而是从中构建一棵 **草稿树**。采用 Best-First Heap 算法在固定节点预算 B 下选择最可能被目标模型接受的多条路径，利用 Tree Attention 实现单次并行验证。

### 1.7 JetSpec

JetSpec 通过 **树形因果注意力掩码** 在单次前向传递中同时实现并行预测和因果条件化。每个树节点可关注其祖先但不能关注兄弟分支，打破了"并行 = 牺牲因果性"的固有假设。

## 2. DSpark

DSpark 明确指出了三个努力方向：1) 让学生写得更快(降低 t_draft)；2) 让学生猜得更准(提高 alpha)；3) 让教授查得更巧(降低有效 t_verify)。

DSpark 的解法是：**融合并行和自回归两者优势，同时引入系统级调度来避免资源浪费**。

### 2.1 半自回归生成 (Semi-Autoregressive Generation)

采用一种半自回归结构，将草稿生成分为两个阶段：

- **并行阶段**：一个并行主干网络(DFlash)在整个块上运行一次前向传播，产生隐藏状态和基础 logits。
- **串行阶段**：为基础 logits 补充一个依赖于前缀的转移偏差，允许每个草稿位置以块内先前已采样的 token 为条件。

串行模块有两种实现：

**马尔可夫头 (Markov head)**：将依赖限制在紧邻的前一个 token 上，简化为低秩分解的一阶转移矩阵。默认 rank=64 使得存储和每步计算都保持很小。

```python
class VanillaMarkov(nn.Module):
    def __init__(self, *, vocab_size: int, markov_rank: int):
        super().__init__()
        self.markov_w1 = nn.Embedding(self.vocab_size, self.markov_rank)
        self.markov_w2 = nn.Linear(self.markov_rank, self.vocab_size, bias=False)

    def compute_step_bias(self, token_ids, hidden_states):
        prev_emb = self.markov_w1(token_ids.long())
        return self.markov_w2(prev_emb)

    def apply_step_logits(self, logits, *, token_ids, hidden_states):
        return logits + self.compute_step_bias(token_ids, hidden_states)
```

```python
def sample_block_tokens(self, base_logits, *, first_prev_token_ids, ...):
    sampled_tokens = []
    corrected_logits = []
    prev_token_ids = first_prev_token_ids.long()

    for step_idx in range(proposal_len):
        step_logits = self.apply_step_logits(
            base_logits[:, step_idx, :], token_ids=prev_token_ids,
        )
        corrected_logits.append(step_logits)
        next_token_ids = sample_tokens(step_logits, temperature=temperature)
        sampled_tokens.append(next_token_ids)
        prev_token_ids = next_token_ids

    return torch.stack(sampled_tokens, dim=1), torch.cat(corrected_logits, dim=1)
```

**RNN 头 (RNN head)**：通过维持一个循环状态累积块内的完整前缀历史，放宽了对长距离依赖的限制。

### 2.2 置信度调度验证 (Confidence-Scheduled Verification)

半自回归架构使 DSpark 能高效生成大的草稿块，但 **不加选择地验证整个草稿块会降低系统吞吐量**。DSpark 通过耦合一个预测前缀存活概率的 **置信度头**，和一个根据当前系统负载动态确定最优验证长度的 **硬件感知前缀调度器** 来解决这个问题。

##### 置信度头

为每个草稿位置输出一个标量估计值，建模的是在块内所有先前 token 都已被接受的条件下，位置 i 的草稿 token 能够通过目标模型验证的 **条件概率**。

```python
class AcceptRatePredictor(nn.Module):
    def __init__(self, input_dim: int):
        super().__init__()
        self.proj = nn.Linear(int(input_dim), 1)

    def forward(self, features):
        return self.proj(features).squeeze(-1)
```

**后处理校准**：引入 **序列化温度缩放 (STS)**，从左到右依次校准联合概率，使用 1D 网格搜索找到最优的温度标量，以最小化期望校准误差(ECE)。

##### 硬件感知前缀调度器

将验证长度选择问题形式化为一个 **全局吞吐量最大化问题**：

```
max_{s_i} E[accepted tokens] / (steps per second of B)
```

调度器的决策过程：
1. 收集所有请求的草稿 token 的(校准后)存活概率。
2. 全局排序：把所有请求的所有草稿 token 按存活概率从高到低排序。
3. 模拟"加人"：从最基本的验证开始，按排序不断加入 token，查硬件性能表计算总吞吐量。
4. 寻找峰值：当吞吐量开始下降时停止，采用当前方案。

为适应生产环境，作者引入了 **两步延迟的异步机制**：
- 决策什么(Which ones)：用最新的置信度分数排序
- 决策多少(How many)：用两步前的数据预测容量限制

这解决了时序冲突，同时意外地保证了算法无损性——因为截断长度决策与当前 token 内容无关，形成了一道"因果屏障"。

### 2.3 训练

训练目标由三项组成，都通过位置加权强调早期位置的重要性：

- **交叉熵损失**：训练起草模型预测正确的下一个 token
- **分布匹配损失**：惩罚草稿分布和目标分布之间的总变差距离
- **置信度损失**：二元交叉熵，训练置信度头预测软接受标签

训练时的系统级优化包括：
- **隐层状态通信**：只传递 LM 头之前的隐层状态而非全词汇表 logits，通信复杂度从 O(V) 降到 O(d)
- **基于锚点的序列打包**：从训练序列中采样固定数量的草稿锚点，将孤立预测块打包成密集训练批次

### 2.4 实验

#### 2.4.1 为什么并行生成能超越自回归？

并行起草模型(DFlash)通常能产生比完全自回归起草模型(Eagle3)更长的接受长度。原因在于：

- **位置 1 的容量优势**：并行起草模型可以负担更深的网络，第一个 token 准确率显著高于自回归模型(受延迟限制只能使用浅层网络)。由于投机解码是严格的前缀匹配生存过程，第一个 token 的拒绝会立即导致整个块失效，因此初始容量优势不成比例地提升了最终接受长度。
- **通过半自回归缓解后缀衰减**：DSpark 继承了深度并行起草模型的高初始接受率，同时其轻量级串行头缓解了并行生成典型的快速接受率衰减。

#### 2.4.2 置信度头的作用

置信度头能够识别价值较低的后缀 token。在聊天工作负载上效果最为显著——提高阈值可将接受率从 45.7% 提高到 95.7%。结构化任务(数学和代码)经历了较温和的修剪。

### 2.5 在线服务

在 DeepSeek-V4-Flash 和 DeepSeek-V4-Pro 的生产服务引擎中，DSpark-5 与 MTP-1 基线进行了评估：

- V4-Flash：在 80 tok/s/user 的 SLA 下，DSpark 提升 51% 的聚合吞吐量
- V4-Pro：在 35 tok/s/user 的 SLA 下，DSpark 提升 52% 的聚合吞吐量
- 在匹配的系统容量下，DSpark 将单用户生成速度加快了 57% 到 85%

核心机制：通过将物理执行与逻辑序列追踪解耦，推理框架在一个批次内高效支持可变长度的查询。

## 3. 结语

### 3.1 投机解码的性能模型

投机解码的加速比从第一性原理出发：

```
speedup = (gamma * t_draft + t_verify) / (t_draft * gamma + t_verify) * E[K]
```

其中 E[K] = sum(prod(alpha_j for j &lt; i))，对 alpha 极其敏感——从 0.7 提升到 0.9 时，E[K] 从 2.94 跃升到 5.22。

从性能公式出发，有且仅有三条路径：降低 t_draft、提高 alpha、降低有效 t_verify。

### 3.2 投机解码的数学模型

接受率与草稿分布和目标分布之间存在精确的数学关系：

alpha_i = 1 - d_TV(p_i, q_i)

其中全变差距离 d_TV(p, q) = 0.5 * sum|p(x) - q(x)|。

从最优传输(OT)视角，草稿模型训练的本质是最小化将 q 运输到 p 的代价，这等价于最大化接受率。

### 3.3 调度策略设计考量

调度策略的核心问题是：给定一批草稿 token，应该提交多少给目标模型验证？形式化为：

max E[accepted(B)] / time(B)

在高并发下，每个验证 slot 具有机会成本。DSpark 的贪心算法在边际收益 = 边际成本时停止准入。

## 附录 A：投机解码发展史 — 时间维度的全景分析

投机解码从 2022 年末的理论萌芽到 2026 年中大规模生产部署，仅用了不到四年，可划分为六个清晰的演进阶段：

### 第一阶段：奠基(2022.11) — 理论与框架的建立

Leviathan et al. 在 ICML 2023 上首次提出了完整的 draft-then-verify 框架，引入了三个支配全部后续研究的核心参数：接受率 alpha、成本比 c、草稿长度 gamma。

**根本矛盾**：草稿质量与草稿成本不可兼得。

### 第二阶段：探索与分化(2023.05-2023.12) — 多路径并行

验证侧：SpecInfer 引入树状推测，BiLD 引入置信度驱动的动态 Fallback/Rollback。
草稿来源多样化：自投机(Self-Speculative)、蒸馏增强、检索替代(REST)、Jacobi 范式(Lookahead/Ouroboros)、特征层预测(PaSS)、级联加速(Cascade SD)。

**根本矛盾**：草稿来源多样性带来选择困难。

### 第三阶段：系统化与质量突破(2024.01-2024.04)

Medusa(多头预测)、EAGLE(特征空间自回归)、Sequoia(最优树拓扑)三个里程碑出现。

**根本矛盾**：自回归起草器仍受 gamma 次串行约束。

### 第四阶段：训练集成与范式分裂(2024.04-2024.12)

Meta MTP 和 DeepSeek-V3 MTP 将投机能力融入预训练阶段，实现"免费午餐"。

**根本矛盾**：D=1 的保守设置限制了单轮加速潜力。

### 第五阶段：范式革命(2025) — 从串行到并行

DFlash 完成根本性范式突破：起草延迟从 O(gamma) 降为 O(1)。

**根本矛盾**：并行性牺牲了因果性，导致多模态碰撞和接受率快速衰减。

### 第六阶段：融合与落地(2026.01-2026.06)

四线交织：JetSpec(因果性+并行性统一)、DDTree(扩散最优树)、SSD(系统级调度优化)、DSpark(半自回归+自适应调度统一，首次大规模生产部署)。

### 演进主线总结

- **草稿来源**：独立模型 -> 模型自身 -> 检索/Jacobi -> 训练内置 -> 扩散适配器 -> 半自回归
- **验证方式**：单序列拒绝采样 -> 树验证 -> 最优树 -> 扩散树 -> 因果树 -> 硬件感知自适应调度
- **起草延迟**：串行 -> 并行 -> 并行+因果 -> 并行+依赖+自适应
- **系统集成**：离线 benchmark -> 训练-推理统一 -> 异步调度 -> 生产流量部署

## 附录 B：DSpark 训练代码解析

训练时的 `forward` 方法以 `Qwen3DSparkModel.forward` 为例，在一次调用中完成从锚点采样到损失所需全部输出的计算。

### 步骤 1：锚点采样

```python
anchor_positions, block_keep_mask = sample_anchor_positions(
    seq_len=seq_len, loss_mask=loss_mask,
    num_anchors=512, device=device,
)
```

从序列中随机选取 512 个有效锚点，每个锚点代表一个 block_size token 草稿块的起始位置。

### 步骤 2：创建噪声嵌入

```python
noise_embedding = create_noise_embed(
    self.embed_tokens, input_ids, anchor_positions, block_keep_mask,
    mask_token_id=self.mask_token_id, block_size=self.block_size,
)
```

每个锚点块构造：`[anchor_token, MASK, MASK, ..., MASK]`。锚点本身也作为第一个预测位置，因此 block_size 个输入产生 block_size 个草稿 logits。

### 步骤 3-4：位置编码和注意力掩码

草稿 token 的 position_id 与原始序列中的实际位置对齐。块内使用双向注意而非因果注意，使得并行主干在一次前向传播中就能产生所有位置的隐藏状态。

### 步骤 5：并行主干前向传播

```python
output_hidden = self._forward_backbone(
    position_ids=full_position_ids,
    noise_embedding=noise_embedding,
    target_hidden_states=target_hidden_states,
    attention_mask=dspark_attn_mask,
)
```

每一层的 `Qwen3DSparkAttention` 将 `target_hidden_states` 拼接到 Key/Value 中。

### 步骤 6-7：应用马尔可夫头

使用 teacher-forcing 方式，串行头在训练时看到的"前一个 token"是 ground truth，确保梯度稳定。

```python
draft_logits = self.compute_logits(output_hidden).reshape(
    bsz, num_blocks, self.block_size, -1
)

if self.markov_head is not None:
    draft_logits = self.markov_head.apply_block_logits(
        draft_logits, token_ids=prev_token_ids,
        hidden_states=output_hidden_4d,
    )
```

### 步骤 8-10：损失计算

```python
# 交叉熵损失
ce_loss = F.cross_entropy(flat_logits, flat_targets, reduction="none")

# L1 分布匹配损失(总变差距离)
draft_probs = torch.softmax(outputs.draft_logits.float(), dim=-1)
target_probs = torch.softmax(aligned_target_logits.float(), dim=-1)
l1_dist = (draft_probs - target_probs).abs().sum(dim=-1)

# 置信度损失
confidence_loss = F.binary_cross_entropy_with_logits(
    outputs.confidence_pred.float(), confidence_targets, reduction="none"

total_loss = ce_loss_alpha * ce_loss + l1_loss_alpha * l1_loss
            + confidence_head_alpha * confidence_loss
```
