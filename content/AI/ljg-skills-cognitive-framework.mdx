## 0. ljg-skills 是什么

lijigang/ljg-skills 是一个 Claude Code 自定义技能集，在 GitHub 上获得了 6k+ Star。它不是又一个 Prompt 模板库——它是一套**将 LLM 从通用聊天工具改造为高质量认知工具**的完整方法论体系。

传统 Prompt 只是告诉 AI "做什么"。ljg-skills 告诉 AI **怎么想**——用什么样的认知框架切入、怎么组织输出、用什么审美标准自检。每个技能不仅是执行脚本，更是一个**精心设计的思维模具**。

## 2. 方法论拆解：每个技能的"思维模具"

### 2.1 认知原子：改变你思考什么

#### ljg-learn：概念解剖

八个维度切开一个概念，最终压缩成一句"顿悟"：

<MermaidDiagram chart={`flowchart LR
    D1["历史维度<br/>概念的生与死"] --> D2["辩证维度<br/>正题/反题/合题"]
    D2 --> D3["现象维度<br/>概念在经验中如何显现"]
    D3 --> D4["语言维度<br/>词源/语义漂移/跨语言"]
    D4 --> D5["形式维度<br/>能否形式化表示"]
    D5 --> D6["存在维度<br/>不依赖此概念的世界是否可能"]
    D6 --> D7["美感维度<br/>概念的美学品质"]
    D7 --> D8["元反思维度<br/>此解剖框架自身的问题"]
    D8 --> OUTPUT["顿悟压缩<br/>公式 + 一句话 + ASCII 骨架图"]

    style D1 fill:#e1f5fe
    style D4 fill:#e1f5fe
    style D7 fill:#e1f5fe

这不是"解释概念"，而是**从八个哲学维度对概念做解剖**，最终产出一条不可再分的理解。输出用 org-mode 固定格式，包含公式、一句话和 ASCII 骨架图。

**方法论关键**：八维度不是并列的，而是有递进深度——从"外在历史"到"内在本质"到"对框架自身的怀疑"。最后一维是**元反思**，保证解剖过程不会变成教条式的机械分解。

#### ljg-think：追本之箭

单点深钻，每一层必须切换到更底层的解释框架。不问"为什么"，问"这个解释本身依赖什么"。终止条件：触及人性结构、物理定律、逻辑本身、存在论悖论四类底部标记。

**方法论关键**：每一层都是一个"坠落体验"——读者在逐层深入中感受到认知的坍塌和重建。这不是渐进加深，而是**范式跳跃**：每一层都让你重新理解上一层在说什么。

#### ljg-rank：降秩引擎

找一个领域背后不可再少的独立生成器。七步穿透：列现象 → 列候选 → 递归下降（关键步骤）→ 合并同源 → 裁切 → 反生成检验 → 预测+难变异检验。

**方法论关键**：借鉴 Deutsch《无限的开始》中的"好解释"标准——可生成、最小、独立、覆盖广、难变异。第五步"反生成检验"是质量守门员：从生成器能否反推出原领域现象？不能则说明还没有找到真正的底层。

#### ljg-plain：白话引擎

把任何内容改写到"聪明的十二岁小孩也能懂"。**结构自由**——形式跟随内容（类比、故事、问答、渐进举例……什么合适用什么），不强制用固定格式。

**方法论关键**：九条红线中最核心的是"口语测试"：如果换成跟朋友聊天你不会这么说，那就重写。这不是简化，而是**用母语节奏重新思考**——中文重写规则要求"用母语的浑然天成，不用翻译体的精密机器"。

### 2.2 输入增强：改变信息进入你大脑的方式

#### ljg-paper：论文阅读（7 拍故事脊柱）

不是"摘要"，而是**把论文讲成七个节拍的故事**：主角、困境、旧路（要求给出基线率）、转折、解法、结局、核心。产出一个"速读卡"：一句话 / 大想法 / 三件要记住的事。

**方法论关键**：十二道红线中最有特色的是**"基线率标尺"**——论文宣称的提升，必须对照不提升的基线来理解。没有基线率的"我们提升了 30%"是废纸。另外还有"指纹测试"：去掉作者名和机构，你能认出这是谁的工作吗？不能则说明摘要太通用。

#### ljg-paper-river：论文溯源

不是一篇论文的阅读，而是**追溯一个问题从源头到现在的演化史**。递归向后挖前序论文（最多5层）+ 最新进展，以问题为中心叙事，不是以论文为中心。

**方法论关键**：这是ljg-paper的"考古模式"。单一论文只是问题演化树上的一个节点，paper-river给你整棵树的截面。

#### ljg-book：拆书（五要素 + ASCII 参考系）

以"问题"为轴心一条线：作者答什么问题 → 之前共识怎么答 → 他挪动了什么（delta）→ 结论 → 一个要带走的东西。第六要素是一张 ASCII 参考系图：用真实辩论维度做轴，把各学派和作者钉在同一张图上。

**方法论关键**：三道质检关卡——**替换检验**（换一个作者能得出相同结论吗？能则 delta 为零）、**指纹检验**（去掉作者名能认出谁的吗？）、**delta 检验**（delta 是否微小到可以合并进已有学派？）。三关全过才是一本真正贡献了新认知的书。

#### ljg-read：伴读

最复杂的技能之一，分六阶段：全局地图 → 段落翻译（信达雅三层）→ 灯光标注（三种打光方式）→ 循环与节奏控制 → 全文回顾 → 理解轨迹输出。

**方法论关键**：三种"打光"方式极为精妙——**等距光**（同构对照）、**侧光**（对手视角）、**背光**（谱系追溯）。这不是简单的"高亮重要句子"，而是用不同的光照方向揭示文本的不同层次。

#### ljg-qa：信息提问机

把内容抽成 Q-A 链。但不是 FAQ——Q 必须切要害，A 必须四段式（结论 / 形式化 / 步骤 / 边界）。Q 链本身有方向，不是随机问题的堆叠。

### 2.3 输出铸型：控制输出的形态

#### ljg-card：内容铸卡（7 种模具）

这是 ljg-skills 中工程复杂度最高的技能——7 种可视化模具，通过 Playwright 截图生成 PNG：

| 模具 | 参数 | 用途 |
|-----|------|------|
| 长图 | `-l` | 长篇幅内容的竖版卡片 |
| 信息图 | `-i` | 结构化信息的可视化图表 |
| 多卡 | `-m` | 一组内容的系列卡片 |
| 视觉笔记 | `-v` | 编辑风格的视觉笔记 |
| 漫画 | `-c` | 漫画风格的叙事卡片 |
| 白板 | `-w` | 白板风格的思维导图 |
| 大字 | `-b` | 一句话的大字海报 |

**方法论关键**：ljg-card 不只是"画图"，而是有自己的审美标准——`references/taste.md` 中定义了"反AI生成感"的设计原则：避免渐变、避免图标堆砌、避免模板感。追求的是**手绘的粗糙感和精确的信息密度并存**。

#### ljg-library：借书卡

不只是书评的视觉化——它提取一本书独创的"取景框"（framing lens），然后生成一张实体卡片风格的 PNG，包含真实封面、作者头像、书目信息，动态从封面提取强调色。

**方法论关键**："取景框"是 ljg-library 的核心概念——所谓取景框，就是这本书给了你一种**全新的看世界的方式**，而不仅仅是"讲了什么内容"。

#### ljg-present：演讲铸造器

从 org/markdown 大纲到视觉呈现。核心哲学：**大纲即真理，技能即渲染器**。never 重写、重排、总结大纲——只渲染，不改内容。

三种主题对应三种表达态度：黑底（沉思）、红底（宣言）、黄底（反讽），另加赛博绿（终端风）。字号根据内容长度自动调整。

### 2.4 网络通达与写作引擎

#### ljg-roundtable：圆桌讨论

选3-5位真实历史/当代人物做代表，主持人求真导向，不搞虚平衡。有定义轮、对话轮、主持综合（带 ASCII 思想框架图），用户可随时说"继续/挖深/引入新人物"。

**方法论关键**：不是角色扮演式的"假如孔子遇见苏格拉底"，而是**每个发言都必须有真实引用依据**的结构化辩证。主持人的综合不是"各打五十大板"，而是指出真正的分歧点。

#### ljg-relationship：关系分析

五层结构诊断 + 精神分析：交换结构、权力结构、边界结构、阶段结构、叙事结构。模式检测包括移情、无意识模式、阻抗。哲学是"不给建议，只提问"——让你"看见"关系的真实结构。

#### ljg-writes：写作引擎

"手术刀式写作"——一层一层剥到底。五步法：放上桌面 → 切第一刀（为什么/怎么运作/反过来说）→ 切第二刀（更深）→ 切到底 → 回看。最高准则："你会对聪明的朋友这么说吗？不会就重写。"中文重写规则要求用母语节奏，不要翻译体。

#### ljg-travel：旅行研究

输入城市名，输出深度文化研究文档 + PNG 卡片。六维度：历史地层、博物馆亮点、古建筑、考古发现、文化脉系、深度内容发现。方法论借鉴考古学的 Desk-Based Assessment（DBA）。

#### ljg-invest：投资分析

只问一个问题：这项目是"秩序创造机器"还是"秩序搬运机器"？五节结构：是什么、秩序机器判定、创造公式、市场与我们的看法、交易决策。反废话规则：禁用"市场广大""团队优秀""前景光明"。

### 2.5 系统运维与流水线

#### ljg-skill-map

扫描 `~/.claude/skills/` 中所有已安装技能，渲染 ASCII 可视化总览——五类标记对应五类技能。

#### ljg-push

把本地技能同步到 GitHub，双分支（master：org-mode，md：Markdown）。**硬门禁**：如果本地技能列表与 README 不一致，推送被阻止。这是质量守门员。

#### ljg-paper-flow / ljg-word-flow

流水线技能：先跑分析技能，再自动调用铸卡技能。论文可以并行处理，每篇串行（先读再铸卡）。

### 原则一：思维模具 > 执行脚本

每个技能不是一个"提示词模板"，而是一个**精心设计的认知框架**。ljg-paper 的"7拍故事脊柱"不是"请用7个段落总结论文"，而是"把论文讲成一个有主角、困境、转折的故事"。前者是格式约束，后者是**思维方式的重塑**。

### 原则二：红线守门 > 正向鼓励

几乎所有技能都有"红线列表"——比"请写得简洁"更有效的是"禁止使用以下表述"。ljg-paper 的十二道红线（禁用"值得注意的是"、禁用无基线率的提升百分比）比"请客观叙述"更能保证质量。

这种用法来自一个深层洞察：**LLM 的默认行为是正确的，你只需要告诉它什么是不被允许的**。红线列表本质是一种"反向规格说明"。

### 原则三：结构自由 > 格式模板

ljg-plain 最典型——它不强制使用固定格式（"请按以下模板输出"），而是说"形式跟随内容"。类比、故事、问答、渐进举例……什么合适用什么。唯一硬约束是九道红线（口语测试、禁用术语、短词、一事一句……）。

**这是一种高明的约束艺术**：约束的是输出质量（红线），而不是输出形态（模板）。模板让人填空，红线让人思考。

### 原则四：自检闭环 > 线性输出

ljg-writes 的"中文重写规则"要求：先以任何语言写草稿，然后**用母语的浑然天成重写**。ljg-book 的三道质检关卡（替换检验、指纹检验、Delta检验）是在输出前就嵌入质量门禁。

这些不是"生成完再看一遍"，而是**在生成过程中就嵌入了质量检查的闭环**。

### 原则五：认知原子可组合 > 单体技能

ljg-paper-flow 不是"一个大技能"，而是 paper + card 的流水线组合。ljg-word-flow = word + card -i。每个技能是一个**认知原子**——独立可用，但可以组合出更复杂的工作流。

**2. 技能输出标准化**

当前技能输出格式不一致——有的输出 org-mode，有的输出 Markdown，有的输出 PNG。虽然通过 `#md` 分支解决了 Markdown 兼容性，但更深层的问题是**技能间的输出协议不统一**。可以定义一个"**技能输出 schema**"：每个技能声明自己的输出类型（text / png / html / org），下游技能可以自动消费。

**3. 流水线编排的通用化**

`ljg-paper-flow` 和 `ljg-word-flow` 是硬编码的流水线。既然每个技能都是认知原子，完全可以设计一个通用的**流水线编排器**——用户用简单的 DSL 定义 `skill-a | skill-b | skill-c`，编排器自动处理输入输出传递。

### 5.2 方法论层面的优化

**4. 红线列表的版本化和积累**

各技能的红线列表是分散的——ljg-paper 有12条，ljg-writes 有自己的。但很多红线是跨技能通用的（如"禁用翻译体"、"口语测试"）。可以建立**红线知识库**，每条线标注适用范围和来源，技能通过引用复用而不是各自定义。

**5. 认知深度的用户自定义**

ljg-learn 的八维度、ljg-think 的逐层穿透，深度是固定的。但用户有时只需要"帮我快速理解"（3 层就够了），有时需要"学术级别的深度解剖"。可以引入**深度参数**——`/ljg-learn --depth 3` 只切三层，`--depth 8` 全切。

**6. 中间结果的检查点**

当前技能是"一镜到底"——从输入到最终输出之间没有检查点。对于 `ljg-think` 这种逐层穿透的技能，用户可能想在第三层停下来说"这个方向不对"。可以在关键层设置**检查点**，允许用户介入调整方向。

### 5.3 工程层面的优化

**7. 技能依赖的声明式管理**

`ljg-card` 依赖 Playwright，但这是在文档中用自然语言说明的。可以引入声明式依赖描述——`skill.yaml` 中声明 `dependencies: [playwright]`，安装脚本自动处理。

**8. 技能版本间的兼容性**

当前 `plugin.json` 中有版本号（1.17.33），但没有语义化版本策略。当技能的行为改变时（比如 ljg-learn 从 7 维改到 8 维），用户怎么知道更新会影响已有工作流？建议引入语义化版本 + changelog。

**9. 测试与回归**

6k Star 的项目竟然没有自动化测试。自定义技能的测试是 AI 领域的一个开放问题，但至少可以做两件事：**输出格式验证**（每个技能的输出是否符合 schema）和**回归测试**（给每个技能一组固定输入，检查输出是否在合理范围内变化）。

**10. 多语言输出的统一管理**

org-mode 和 Markdown 双分支是手动维护的。可以考虑用单一源格式（如 Markdown）+ 自动转换脚本生成 org-mode 版本，避免两个分支的内容漂移。`ljg-push` 已有硬门禁检查 README 一致性，但内容本身的一致性还没保障。

## 6. 对 AI 技能工程的三层启示

### 启示一：技能 = 认知框架，不是执行模板

ljg-skills 最大的启示是：**一个高质量的 AI 技能不是一个 Prompt 模板，而是一个认知框架**。

模板告诉你"按这个格式输出"，框架告诉你"用这种方式思考"。模板产出千篇一律的填空文，框架产出有深度的独特洞见。

区分标准很简单：**去掉格式约束后，技能是否还能指导 LLM 产出高质量内容？**能，就是框架；不能，就是模板。

### 启示二：红线 > 绿灯

在约束 LLM 行为方面，"禁止做X"比"请做Y"有效得多。原因在于 LLM 的默认行为已经是"尽可能全面、礼貌地回答"。你需要的是**剪掉不想要的部分**，而不是要求它做它已经在做的事。

ljg-skills 的红线列表是一种**反向规格说明**的艺术——你不需要告诉 LLM "写得像人"，你只需要告诉它"不要用以下方式写"，然后 LLM 会自动找到更自然的表达。

### 启示三：认知原子可组合 > 单体巨技能

一个"无所不能"的超级技能，不如一组各司其职的认知原子。原因有三：

1. **可测试**：每个原子的输出质量可以独立验证
2. **可组合**：原子之间可以流水线组合，产生新的工作流
3. **可精化**：对一个原子的改进不影响其他原子

这与 Unix 哲学一脉相承：**做好一件事的小工具，比做所有事的大工具更有生命力**。

ljg-skills 不是"又一个 Prompt 库"。它是一套**将 LLM 从通用聊天工具改造为高保真认知工具**的方法论体系。核心贡献不是 21 个具体的技能实现，而是三条可迁移的设计原则：

1. **思维模具 > 执行脚本**——设计认知框架，而不是填空模板
2. **红线 > 绿灯**——用反向禁止约束质量，而不是用正向描述请求输出
3. **认知原子可组合 > 单体巨技能**——做好一件事的小工具，通过流水线组合出复杂工作流

这些原则不仅适用于 Claude Code 技能设计，也适用于所有 LLM 辅助知识工作的场景——从个人笔记系统到团队知识管理，从学术研究到产品设计。当你下次写 Prompt 时，不妨问自己：**我是在设计一个模板，还是在设计一个认知框架？**
