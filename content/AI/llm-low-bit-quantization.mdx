把一个大模型塞进一张显卡，先要过显存这一关。70B 参数按 FP16 存，每个参数 2 字节，合计 140GB。一张 H100 80GB 放不下。换成 4bit，每个参数半个字节，权重降到 35GB，看起来一张卡就装下了。

低比特量化的核心思想，是把连续的浮点数映射到一组有限的格点上，再为每个格点区间记一个缩放系数。存储时只存格点编号和系数，计算时再还原成浮点。位宽越低，格点越少，省下的字节越多，误差也越大。

把 GPTQ、AWQ、SmoothQuant 的论文和 llama.cpp 的量化源码放在一起核对，几个常被混着说的数就露出来了。4bit 权重的有效位宽通常是 4.x 位，Q4_K_M 的文件平均位宽更高，70B 模型的实际文件大小和 35GB 差了一截。

这篇文章从一笔显存账开始，讲清低比特量化省的是容量、带宽还是算力，权重和缩放系数怎么排，以及同一个 4bit 在这张卡上快、换一张卡未必快的原因。

## 先把显存账算清楚

70B 指参数数量，乘上每个参数的字节数才是显存。FP16 每个参数 2 字节，140GB 是这么来的。INT4 每个参数半个字节，35GB 是这么来的。两个数都只算权重，不含 KV cache、激活、框架和通信缓冲。

4bit 存 70B 权重，名义上 35GB。实际文件会大一些。以 group 128 为例，每 128 个权重共享一个 FP16 scale，scale 本身占 16 位，摊到每个权重是 0.125 位；如果再用 4 位 zero point，摊到每个权重是 0.03125 位。加在一起，每个权重的有效位宽是 4.15625 位，70B 权重约 36.4GB。

llama.cpp 的 Q4_K_M 更直接。Llama 3.1 70B 的 FP16 权重约 140GB，Q4_K_M 文件是 43.1GB，相对 FP16 约 3.25 倍压缩。Q4_K 的基础块是 4.5 位每权重，M 版本还会给部分张量更高精度，所以文件平均位宽高于 4.0。

这 43.1GB 也不是全部。70B 模型按 80 层、8 个 KV 头、head_dim 128、FP16 估算，每个 token 的 KV cache 约 320KB；8K 上下文就是约 2.6GB。权重、KV、激活、临时缓冲加在一起，才是那张卡真正要放下的东西。

GPTQ 论文里有一个更极端的例子。OPT-175B 压到 3bit 后约 63GB，加上 2048 token 的 KV cache 约 9GB，能放进一张 80GB A100。FP16 版本要 5 张 80GB 卡才跑得下。模型能不能上线，先看这笔容量账。

第一笔账的结论很朴素。低比特量化先把模型从放不下变成放得下，再把省下的空间换成长上下文、更大的 batch，或者更小的卡。速度是第二笔账。

## 解码为什么盯着显存带宽

推理分两段。prefill 一次处理整段提示词，decode 逐 token 生成。自回归解码一次生成一个 token。每生成一个 token，模型要把几乎所有权重读一遍，和当前激活做矩阵向量乘。batch 为 1 时，同一个权重只被用一次，算完就放下。

70B 模型 FP16 权重 140GB，H100 SXM 的 HBM3 带宽 3.35TB/s。按带宽上限算，读一遍权重需要 41.8 毫秒，一秒钟最多 23.9 个 token。换成名义 4.0 位的 35GB，读一遍 10.4 毫秒，上限 95.7 个 token。两个数都是理论上限，没算 KV cache、kernel 启动、通信和显存碎片。

这组数解释了一件事。decode 阶段的算术强度只有约 1 FLOP/byte。dense 70B 模型每个 token 约 140 GFLOPs 的计算，对应 140GB 的权重读取，比值就是 1。按稠密 FP16 算，H100 的算力带宽比在几百 FLOP/byte 的量级，decode 离算力上限很远，瓶颈落在搬权重上。

batch 会改变这个账。batch 为 B 时，同一份权重被 B 个请求复用，算术强度大约乘 B。FP16 下 B 到几百，或者 4bit 下 B 到几十，才可能从带宽瓶颈转向算力瓶颈。那时只压权重不够，激活也要压，或者换低精度 tensor core。

这也是 W4A16 和 W8A8 的分工。W 后面的数字是权重位宽，A 后面的数字是激活位宽。W4A16 主要省权重字节，适合小 batch 的 decode。W8A8 把激活也压到 8bit，能用 INT8 tensor core，适合 prefill 和大 batch 的吞吐。两种方案对应两个瓶颈。

KV cache 是另一笔。序列越长、batch 越大，KV cache 越大。长上下文场景里，KV cache 可能超过权重本身。只压权重，KV 还在 FP16，显存和带宽的账都算不平。

回到三个账本。容量账最直接，权重和 KV 占的字节少了，模型能装下或者 batch 能开大。带宽账决定 decode 的 token/s 上限，每 token 读的字节少了，上限就提高。算力账要苛刻一些，只有激活也压下去、硬件有低比特 tensor core，才会省计算时间。三笔账分开算，才不会把存储收益当成加速收益。

## 低比特的几种精度

低比特是一组格式。位宽相同，指数位、尾数位、缩放方式不同，误差和硬件支持也不同。

| 格式 | 位宽 | 指数/尾数 | 关键范围 | 常见用途 |
|---|---|---|---|---|
| FP16 | 16 | 5/10 | 最大 65504 | 推理默认 |
| BF16 | 16 | 8/7 | 范围同 FP32，精度低 | 训练和推理 |
| FP8 E4M3 | 8 | 4/3 | 最大 448 | 前向权重和激活 |
| FP8 E5M2 | 8 | 5/2 | 最大 57344 | 梯度和大范围量 |
| INT8 | 8 | 无 | 256 个均匀格点 | W8A8 |
| INT4 | 4 | 无 | 16 个均匀格点 | W4A16 |
| NF4 | 4 | 无 | 16 个正态分位点 | QLoRA |
| FP4 E2M1 | 4 | 2/1 | 正负 6 以内，16 个值 | NVFP4 和 MXFP4 |
| 三值 | 约 1.58 | 无 | -1、0、1 | BitNet |

看这张表，先分三组。FP16 和 BF16 是 16bit 基线。FP8 是 8bit 浮点，靠指数位保留动态范围。INT8 和 INT4 是均匀格点，靠 scale 把范围映射到 256 或 16 个档位。NF4 和 FP4 是 4bit 的两种极端，一个按正态分布排格点，一个用浮点指数换动态范围。

位宽只说明存储占几位，不说明有效精度。INT4 的 16 个格点是均匀的，权重集中在零附近时，零附近的档位不够密，尾部的大值又占掉了量程。NF4 把这 16 个格点按正态分位点排，零附近更密，所以 4bit 的 NF4 在正态权重上比 INT4 更准。FP4 的 E2M1 把 2 位给指数，动态范围大了，尾数只剩 1 位，单值精度更粗，需要块缩放来补。

硬件支持也要看。FP8 在 Hopper 和 Ada 上有原生 tensor core，INT8 在更老的卡上就有，FP4 要 Blackwell。格式存在，不等于你的卡能加速。

## 4bit 里到底存了什么

把量化想成一排音量旋钮。每个旋钮本来是连续的，现在只允许停在 16 个档位。刻度由这一组旋钮里最大的那个决定。一个特别大的旋钮会把刻度撑大，旁边的小旋钮就都挤在低档位。把旋钮分组，每组单独定刻度，小旋钮就能用自己的刻度。分组越细，刻度越贴合，每组要多存一个刻度值。这个比方只解释量程和分组，不解释浮点格式的指数位，也不解释 kernel 怎么解包。

数学上，对称量化只存一个 scale。`q = clamp(round(w / s), -8, 7)`，还原是 `w' = q * s`。非对称量化多存一个 zero point，`q = clamp(round(w / s) + z, 0, 15)`，还原是 `w' = s * (q - z)`。

拿四个权重做例子。假设一组权重是 `[0.12, -0.05, 0.31, -0.28]`，对称 INT4 的 scale 取组内最大绝对值除以 7，`s = 0.31 / 7 = 0.0443`。

| 权重 | 除以 scale | 取整 | 还原 | 误差 |
|---|---|---|---|---|
| 0.12 | 2.71 | 3 | 0.133 | +0.013 |
| -0.05 | -1.13 | -1 | -0.044 | +0.006 |
| 0.31 | 7.00 | 7 | 0.310 | 0 |
| -0.28 | -6.32 | -6 | -0.266 | +0.014 |

四个权重还原成 `[0.133, -0.044, 0.310, -0.266]`。这一组里最大的 0.31 刚好落在第 7 档，最小的 -0.28 落在第 -6 档。

如果这一组里混进一个 3.1，scale 会变成 0.443。0.12 除以 0.443 约等于 0.27，取整后是 0，-0.05 也变成 0，0.31 只落到 1，-0.28 落到 -1。两个小权重被抹掉，另外两个也只剩下符号和 1 个档位。这就是离群值对量化的破坏，也是分组存在的原因。

分组越细，越不容易被一个离群值拖累。代价是 scale 变多。`b + 16 / g` 是每组 g 个权重、FP16 scale、对称量化的有效位宽公式，`b` 是权重位宽，`g` 是组大小。4bit、g=128 时是 4.125 位；g=32 时是 4.5 位；g=16 时是 5 位。组越小，精度越好，文件越大。

Q4_K 是一个把 scale 开销花得更细的例子。它把 256 个权重组成一个超级块，超级块里再分 8 个 32 权重的子块。每个子块有一份 6 位 scale 和一份 6 位 min，超级块再存两个 FP16 的全局 scale。整个块占 144 字节，256 个权重，平均 4.5 位。

144 字节的构成是 2 字节 d、2 字节 dmin、12 字节的 6 位 scale 和 min、128 字节的 4bit 权重。`12 * 8 / 256` 是 0.375 位，`4 * 8 / 256` 是 0.125 位，加上 4 位权重，正好 4.5 位。

浮点 4bit 走另一条路。E2M1 只有 1 位符号、2 位指数、1 位尾数，能表示的正数是 0、0.5、1、1.5、2、3、4、6。它自带一点动态范围，单靠 4 位还是太粗，所以外面再套一层块缩放。

MXFP4 每 32 个值共享一个 8 位 E8M0 指数，有效位宽是 `4 + 8 / 32 = 4.25`。NVFP4 每 16 个值共享一个 FP8 E4M3 缩放，再加一个每张量的 FP32 缩放，有效位宽是 `4 + 8 / 16 = 4.5`。两者的元素格式都是 E2M1，块布局和缩放类型不同，checkpoint 不能直接混用。

| 存法 | 元素位宽 | 分组 | 缩放开销 | 有效位宽 |
|---|---|---|---|---|
| INT4 对称 | 4 | 128 | FP16 scale | 4.125 |
| INT4 非对称 | 4 | 128 | FP16 scale 加 4bit zero | 4.156 |
| Q4_K | 4 | 256，8 个 32 子块 | 6bit scale 和 min，加 FP16 超级块 | 4.5 |
| MXFP4 | E2M1 | 32 | E8M0 8bit | 4.25 |
| NVFP4 | E2M1 | 16 | E4M3 8bit，加 FP32 每张量 | 4.5 |

4bit 是一个家族。文件里真正占多少位，要看元素位宽、分组、缩放类型和有没有 zero point。把 4bit 直接当成 4.0 位，算出来的显存会偏小。

## 只压权重，先让模型装得下

最先成熟的是 W4A16，权重 4bit，激活 16bit。它只改存储和权重读取，计算还是 FP16。对 decode 这种带宽瓶颈，这一步最直接。

实现低比特量化有两条路。PTQ 在训练后做，用校准集统计权重和激活，成本低，适合大多数推理部署。QAT 在训练时模拟量化，让模型提前适应低精度，成本高，适合 FP4、三值和精度要求高的场景。下面先看 PTQ 里最常见的几类权重方法。

GPTQ 的做法是逐层量化，把一层权重量化后的输出误差压到最小。它把 `||WX - W'X||^2` 作为目标，用近似二阶信息决定每个权重怎么取整，量化一列之后，把误差补偿到还没量化的列上。为了让 175B 模型跑得动，它按 128 列一块做惰性更新，用 Cholesky 分解稳住数值。

论文里的配置是 128 条 2048 token 的 C4 校准样本，OPT-175B 量化大约 4 个 GPU 小时。4bit 的 OPT-175B 在 WikiText-2 上 PPL 8.37，FP16 是 8.34；3bit 是 8.68。A100 上 3bit 的平均每 token 延迟约 3.25 倍加速，A6000 上约 4.5 倍。

AWQ 换了一个观察角度。它发现权重不是同等重要，按激活幅度找出的 0.1% 到 1% 显著通道，保住它们就能明显降低量化误差。AWQ 不把这些通道留成 FP16，而是给它们乘一个大于 1 的 scale，再把对应激活除以同一个 scale，数学上等价，硬件上仍然是整组 4bit。

它用一个网格搜索找 scale，不需要反向传播，也不做逐层重构。论文里 Llama-2 70B 的 INT4 g128 在 WikiText-2 上 PPL 是 3.41，FP16 是 3.32；3bit 是 3.74。TinyChat 在桌面和移动 GPU 上相对 Hugging Face FP16 实现有 3 倍以上加速。

AutoRound 换了一个优化对象。它由 Intel 提出，核心算法叫 SignRound。GPTQ 在取整之后补偿误差，AWQ 在取整之前调 scale，AutoRound 把每个权重往哪边取整和 weight clipping 的上下界直接当成可学习变量。

具体做法是，先按 RTN 得到初始量化权重，再给每个权重一个落在 `[-0.5, 0.5]` 的扰动 `V`，用它决定取整方向；同时学习两个缩放参数 `alpha` 和 `beta`，控制 weight clipping 的范围。对每个 block，比较原模块输出和量化后模块输出，用 SignSGD 更新 `V`、`alpha`、`beta`，让量化后的输出接近原输出。训练只更新这几个参数，不改原始权重；量化完成后，rounding 和 clipping 都固化进 checkpoint，推理没有额外开销。

论文里的默认配置是 200 步、学习率 `5e-3`，官方工具链默认用 128 条校准样本。它借了 QAT 的做法，让模型在量化过程中适应低精度，又保留 PTQ 训练后一次完成的低成本，所以比完整 QAT 便宜，精度比 RTN 高。论文报告 4bit 在多数场景接近无损。2bit 下，11 个零样本任务的平均准确率比各基线高 6.91 到 33.22 个百分点，不同模型和基线差距很大。

应用场景主要落在几处。2bit 到 4bit 的权重量化，尤其是 2bit、3bit 这些 RTN 和早期 PTQ 容易失真的区间，是它最有优势的区间。它也能导出成 AutoRound 原生格式、GPTQ、AWQ 或部分 GGUF 格式，量化结果可以接到已有的 vLLM、llama.cpp 或 Intel 运行时。CPU、Intel GPU、CUDA 混合环境，或者需要 mixed-bit、lm_head 量化的模型，也可以用它。

边界也要说清楚。AutoRound 的主线是权重量化，激活离群值和 KV cache 要另找方法。要压激活，仍然要看 SmoothQuant、LLM.int8 或 FP8；要压 KV，仍然要看 KIVI 这类方法。AutoRound 需要校准集和逐 block 的轻量训练，2bit 仍然会掉精度，3bit 和 5bit 到 7bit 的 kernel 支持也不如 4bit 普遍。官方博客给出的轻量模式数据是 72B 模型在 A100 上约 37 分钟，属于厂商自测，换模型和 recipe 会变。

这些方法都把误差留在了权重侧。代价也很具体。GPTQ 依赖校准集，校准分布和线上分布差太远会过拟合；从 3bit 开始，PPL 和任务准确率的退化会更明显，模型之间的差异也更大。AWQ 的 per-channel scale 需要 kernel 支持，换框架可能退化成慢路径。

还有一笔常被忽略的开销。4bit 权重不能直接和 FP16 激活做 tensor core 乘，kernel 要先解包、乘 scale、转成 FP16，再做矩阵乘。AWQ 论文算过，解一个 4bit 权重需要 1 次移位、1 次按位与、1 次 FMA 缩放，而解出来的权重只做 1 次 FMA。解包本身可能比计算还贵，所以权重打包方式、kernel 融合和 SIMD 布局会直接影响实际速度。

GPTQ 论文也把边界写得很清楚。它的加速来自减少显存搬运，不减少浮点计算量。batch 变大、计算变成瓶颈之后，W4A16 的收益会变小。

把这几种方法放进工程，流程通常是先选 group 和位宽，再用领域校准集跑逐层量化，然后把 embedding、lm_head、首尾层和 norm 留在高精度，导出 checkpoint，最后在目标框架里跑 kernel。PTQ 的优点是快，缺点是精度上限受校准集和格式限制。要压到三值，通常得走 QAT；FP4 可以走 PTQ，也可以走 QAT，看精度要求。

## 激活更难压，但压下去省的是算力

权重是静态的，可以离线校准。激活是动态的，随输入变化，还可能带离群值。LLM.int8 在 6.7B 以上的模型里看到幅度超过 6 的离群特征，约占 0.1%，集中在最多 7 个隐藏维度。SmoothQuant 在 OPT-13B 的激活里看到比大多数值大约 100 倍的离群通道。

直接做 per-tensor INT8，一个离群通道就把量程撑满，其他通道只剩两三个有效档位。SmoothQuant 表里，OPT-175B 的朴素 W8A8 平均准确率是 35.5%，FP16 是 66.9%。

LLM.int8 的办法是把离群维度单独拿出来，用 FP16 算，剩下 99.9% 的值用 INT8。它用向量级 scale，给每个内积一对行列缩放系数。BLOOM-176B 的显存降到 1.96 分之一，精度基本不变。代价是混合精度分解本身有开销，小模型上可能比 FP16 还慢。

SmoothQuant 的办法是迁移。它把激活的离群值按通道除一个 scale，把同样的 scale 乘到权重上，数学上等价。scale 取 `max(|X|)^alpha / max(|W|)^(1-alpha)`，alpha 在 0.5 附近时，激活和权重的量化难度比较平衡。这样权重和激活都能走 INT8 GEMM。

论文里 OPT-175B 的 W8A8 平均准确率 66.8%，FP16 66.9%；FasterTransformer 上 1.56 倍加速，显存减半；530B 模型能放进一个 8 张 A100 80GB 的节点。代价是校准和 alpha 调参，GLM-130B 这种离群值更重的模型要把 alpha 调到 0.75，静态 per-tensor 的 O3 方案在 BLOOM 上会掉 0.8 个百分点。

W8A8 的收益和 W4A16 不一样。它省的是权重和激活的字节，还能用 INT8 tensor core 降低计算成本。prefill 和大 batch 场景里，计算占比高，W8A8 更容易体现出来。小 batch decode 仍然是带宽瓶颈，W8A8 的收益没有 W4A16 那么直接。

## FP8 和 FP4，硬件开始接管

INT8 之后，硬件把低精度做进了 tensor core。H100 SXM 的 FP8 tensor core 标称 3958 TFLOPS，FP16 是 1979 TFLOPS，两个数都带稀疏。FP8 的字节是 FP16 的一半，算力密度翻倍。FP8 有两个常用格式，E4M3 最大 448，E5M2 最大 57344。E4M3 精度高一点，适合前向的权重和激活；E5M2 范围大一点，常用于梯度。

FP8 论文在 175B 规模的训练实验里，用 E4M3 和 E5M2 匹配了 16bit 训练的结果。推理侧，FP8 权重加 FP8 激活就是 W8A8 的浮点版本，Hopper 和 Ada 有原生支持，Ampere 没有。

Blackwell 把 4bit 也接进来了。FP4 的元素格式 E2M1 只有 16 个值，最大 6，单靠它表示不了权重的动态范围，所以通常要配缩放，块缩放是目前的主流做法。MXFP4 是 OCP 的标准，32 个值一个块，块缩放是 8 位 E8M0，只能表示 2 的幂。NVFP4 是 NVIDIA 的格式，16 个值一个块，块缩放是 FP8 E4M3，再加一个每张量的 FP32 缩放。

两种格式的有效位宽分别是 4.25 和 4.5。它们都是 4bit 元素，checkpoint 却不通用。MXFP4 的缩放是 2 的幂，硬件实现便宜；NVFP4 的缩放更细，块更小，精度更好，代价是缩放乘法和格式绑定。

NVIDIA 的博客给了 NVFP4 的一组数。相对 FP16，模型内存约 3.5 倍压缩；相对 FP8，约 1.8 倍；DeepSeek-R1-0528 从 FP8 转到 NVFP4，关键语言任务的精度下降在 1% 以内，AIME 2024 上还高了 2 个点。这些是 NVIDIA 自测，换模型、换校准集要重跑。

硬件支持决定这些格式能不能变成速度。vLLM 的文档里，FP8 W8A8 在 Ada 和 Hopper 上支持，NVFP4 需要 Blackwell，MXFP4 在部分后端支持。TensorRT-LLM 的支持矩阵也把 NVFP4、MXFP4、FP8、W4A16、W4A8 分开列。

还有一个容易踩的坑。vLLM 在 kernel 不支持请求的激活量化时，会默认回退成 weight-only。W4A4 可能实际跑成 W4A16，文档说这种回退不会额外掉精度，但实际方案和 benchmark 口径不同。日志里会有一条警告，必要时可以开严格模式让启动直接失败。

看一个 FP4 方案，先确认三件事。卡是不是原生支持，kernel 是不是真的走了这条路径，checkpoint 的缩放格式和运行时是不是匹配。任何一个对不上，4bit 只剩下存储收益。

## 训练时适配，和 KV cache 这一笔

有些低精度方案从训练阶段就改。QLoRA 把基座权重压成 4bit NF4，再用 BF16 的 LoRA 适配器微调。NF4 的 16 个格点按正态分布的分位点排，零附近更密，适合零均值正态的权重。它用 64 个权重一个块，块常数再做一次 8bit 量化，把常数开销从 0.5 位降到 0.127 位。65B 模型可以在单张 48GB 卡上微调，4bit 基座约 41GB。

QLoRA 省的是微调显存。它的前向仍然要把 4bit 权重解成 BF16 再算，推理速度不是它的主目标。

更彻底的是 QAT。BitNet b1.58 把权重限制在 -1、0、1，理论上每个权重 1.58 位。论文报告，同规模、同训练 token 的模型，PPL 和下游任务能追平 FP16。这个结果的前提是从零训练，让它适应三值约束。把已有模型直接三值化，通常不会得到同样的结果。

KV cache 也可以单独压。KIVI 用 2bit 量化 KV，key 按通道分组，value 按 token 分组。论文报告峰值内存降到 2.6 分之一，batch 能到 4 倍，吞吐提升 2.35 到 3.47 倍。代价是长上下文精度和 kernel 支持，2bit KV 在有些模型上会掉精度。

这些方案可以叠加，但叠加之后误差也会累积。权重 4bit、激活 FP8、KV 2bit 同时开，单看每一项都还行，合起来可能在某类任务上掉得很厉害。上线前要按组合测，不能只测单项。

把前面提到的方法按侧重点排一遍，会看到它们各自在解不同的约束。下面这张表把对象、位宽、侧重点和代价放在一起。

| 算法 | 对象 | 位宽 | 侧重点 | 关键动作 | 主要代价 |
|---|---|---|---|---|---|
| RTN | 权重 | 2 到 8bit | 成本最低 | 按最近格点取整 | 低比特精度差 |
| GPTQ | 权重 | 3 到 4bit | 低比特精度 | 逐层二阶误差补偿 | 校准集，3bit 退化 |
| AWQ | 权重 | 4bit | 通用性和部署 | 按激活幅度选显著通道，per-channel scaling | kernel 支持，校准 |
| AutoRound | 权重 | 2 到 4bit | 极低比特精度 | SignSGD 优化 rounding 和 clipping | 逐 block 调优，校准 |
| SmoothQuant | 权重和激活 | W8A8 | 激活可量化 | 把激活离群值迁移到权重 | alpha 调参，校准 |
| LLM.int8 | 权重和激活 | W8A8 | 保精度和内存 | 离群维度用 FP16 分解 | 混合精度开销 |
| QLoRA | 权重 | NF4 | 微调显存 | 正态分位格点，双重量化 | 只适合微调 |
| KIVI | KV cache | 2bit | 长上下文容量 | key 按通道，value 按 token | 长上下文精度 |
| FP8 | 权重和激活 | W8A8 | 硬件算力 | E4M3 和 E5M2 加缩放 | Hopper 和 Ada 支持 |
| NVFP4 | 权重和激活 | 4bit | 硬件算力和带宽 | E2M1 加 16 值块，FP8 和 FP32 缩放 | Blackwell 专用 |
| BitNet | 权重 | 三值 | 极限压缩 | 从零训练三值权重 | 需要训练和硬件支持 |

看这张表，先问当前瓶颈。权重占显存、decode 带宽不够，优先看 GPTQ、AWQ、AutoRound 这类权重量化方案。激活和算力是瓶颈，看 SmoothQuant、LLM.int8，或者 FP8、FP4 这类硬件格式。长上下文下 KV cache 占满显存，看 KIVI。要在小卡上微调，看 QLoRA。要把权重压到三值，看 BitNet 这类训练时方法。

## 这些数字怎么读

把前面出现的数字挑几个，放在一张表里。

| 数字 | 出处 | 口径 | 容易误读的地方 |
|---|---|---|---|
| 70B FP16 140GB | 自算 | 仅权重，十进制 GB | 不含 KV、激活和框架 |
| Q4_K_M 70B 43.1GB | llama.cpp | GGUF 文件，混合精度 | 别读成 35GB，也别读成 4.0 位 |
| GPTQ 3.25 倍 | GPTQ 论文 | OPT-175B 3bit，A100，batch 1 | 只覆盖这个模型和序列 |
| AWQ 3 倍以上 | AWQ 论文 | TinyChat，4bit，HF FP16 基线 | 换成通用 serving 会变 |
| AutoRound 72B 37 分钟 | AutoRound 博客 | A100，light 模式，厂商自测 | 换模型和 recipe 会变 |
| SmoothQuant 1.56 倍 | SmoothQuant 论文 | OPT-175B W8A8，FasterTransformer | 这是 W8A8 口径 |
| NVFP4 3.5 倍 | NVIDIA 博客 | 相对 FP16，厂商自测 | 厂商自测，等待第三方复现 |
| KIVI 2.35 到 3.47 倍 | KIVI 论文 | 2bit KV，Llama、Falcon、Mistral | 这是 KV cache 口径 |

这张表里最容易被忽略的是口径。GPTQ 的 3.25 倍是 OPT-175B、3bit、A100、batch 1、128 token 生成的平均每 token 延迟。AWQ 的 3 倍是 TinyChat 对比 Hugging Face FP16。SmoothQuant 的 1.56 倍是 W8A8 在 FasterTransformer 上的上下文阶段。AutoRound 的 37 分钟是 72B 模型在 A100 的 light 模式，属于厂商自测。这几组数字的模型、硬件、batch、序列和基线都不一样。

第二个容易忽略的是有效位宽。4bit 权重的文件通常高于 4.0 位，Q4_K_M 还会更高。算显存时用 4.0 位，结果会偏小；算带宽时用 4.0 位，结果会偏乐观。

第三个是精度指标。PPL 是平均指标，代码、数学、长尾知识、长上下文里的退化不一定在 PPL 上显出来。量化论文常报 PPL 和几个零样本任务，自己的业务任务要单独测。

第四个是运行时。论文里的 kernel 和框架里的 kernel 可能不是一套。W4A16 在 vLLM、TensorRT-LLM、llama.cpp 里的实现不同，batch 和序列一变，瓶颈可能从带宽转到调度、KV cache 或通信。

论文数字可以拿来判断方向，不能拿来当上线承诺。先在自己的模型、校准集、序列长度和 batch 上重跑，再看 TTFT、TPOT、吞吐和任务准确率。

## 落地时先做什么

先定瓶颈。单请求 decode 慢，先看 W4A16；大 batch 吞吐上不去，先看 W8A8 或 FP8；长上下文显存不够，先看 KV cache 量化。

先跑一个 W4A16 基线。group 128 起步，精度掉了再试 64 或 32，或者把 embedding、lm_head、首尾层、norm 留在高精度。2bit、3bit 下 GPTQ 和 AWQ 掉得厉害时，可以换 AutoRound 再试一轮。

校准集用线上分布。GPTQ 用 128 条 2048 token 的 C4，AWQ 用 Pile，SmoothQuant 用 512 条 Pile。自己的领域数据更合适，别只用通用语料。

评测分三层。PPL 和零样本任务看整体，代码、数学、长上下文看薄弱面，业务集看真实影响。

看运行时日志。确认实际跑的量化方案、有效位宽、有没有回退、KV cache 是什么精度。

留一条 FP16 或 BF16 回退路径。量化版本在某个 batch、某条长请求或某类输入上出问题，能切回去。

## 结语

看一个低比特量化方案，可以先问三件事。它省的是容量、带宽还是算力，误差落在权重、激活还是 KV，运行时有没有对应的 kernel。三个问题答完，再看论文里的倍数。

70B 模型从 140GB 降到 43.1GB，省下的空间可以换更长的上下文、更大的 batch，或者一张更小的卡。选哪一种，取决于你的瓶颈在哪。论文里的 3.25 倍、1.56 倍、2.35 倍各有各的前提，上线前拿自己的模型、校准集、序列长度分布和 batch 重跑一遍。
