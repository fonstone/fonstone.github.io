## 1. 为什么 Agent 需要上下文数据库

<MermaidDiagram chart={`mindmap

      mem["记忆散落在代码/向量库"]

      blackbox["检索链路不可解释"]

AI Agent 的能力受制于上下文质量。传统 RAG 把所有内容压扁成向量片段，在一个平坦的索引上做相似度匹配——这在简单问答下可用，但在 Agent 长任务中暴露四大困境：

| 困境 | 根因 | 后果 |
|------|------|------|
| 碎片化 | 记忆在代码、资源在向量库、技能在脚本 | 无法统一管理、权限和生命周期 |
| Token 成本爆炸 | 扁平 RAG 全量灌入 | 每次请求耗费大量 token，噪声淹没信号 |
| 检索黑盒 | 传统 RAG 检索链路不可观察 | 出错时无法调试、无法优化 |
| 记忆停滞 | 只记录用户交互、无任务记忆 | Agent 无法从任务执行中积累经验 |

**OpenViking 的核心命题**：把"给 Agent 准备上下文"从零散的向量库/脚本，升级为一套可运营的基础设施——**上下文数据库**。

OpenViking 创新性地采用**文件系统范式**管理上下文。核心抽象是 `viking://` 协议的虚拟文件系统，所有上下文类型被映射为目录和文件：

```
viking://
├── resources/              # 资源：项目文档、代码仓库、网页等
│   ├── my_project/
│   │   ├── docs/
│   │   │   ├── api/
│   │   │   └── tutorials/
│   │   └── src/
│   └── ...
├── user/                   # 用户：个人偏好、习惯等
│   └── memories/
│       ├── preferences/
│       │   ├── writing_style
│       │   └── coding_habits
│       └── ...
└── agent/                  # Agent：技能、指令、任务记忆等
    ├── skills/
    │   ├── search_code
    │   ├── analyze_data
    │   └── ...
    ├── memories/
    └── instructions/
```

**为什么文件系统是更好的抽象？**

| 文件系统特性 | 对应 Agent 上下文 | 优势 |
|-------------|-----------------|------|
| 目录层级 | 上下文分类、子分类 | 天然的组织结构 |
| 文件路径 | 唯一 URI 标识 | 确定性定位 |
| 读写权限 | 上下文权限隔离 | 多租户安全 |
| 递归遍历 | 逐层检索 | 先粗后细，降低 token |
| 变更通知 | 上下文更新 | 实时同步 |

### 5.2 检索策略对比

| 策略 | 传统扁平 RAG | OpenViking 目录递归 |
|------|-------------|-------------------|
| 搜索空间 | 全局向量索引 | 先缩目录，再搜内容 |
| 定位精度 | 相似度 Top-K | 目录+语义双维度 |
| 上下文完整性 | 孤立片段 | 理解信息所在的全局上下文 |
| 可解释性 | 黑盒 | 轨迹可视化 |
| Token 效率 | 全文灌入 | L0/L1 逐层加载 |

### 6.1 资源 (resources)

资源是 Agent 的"知识库"——项目文档、代码仓库、网页内容等外部材料。通过 `add-resource` 命令导入：

```bash
# 导入 GitHub 仓库
ov add-resource https://github.com/volcengine/OpenViking

# 导入本地文件
ov add-resource /path/to/project-docs

# 导入网页
ov add-resource https://docs.example.com/api
```

导入后自动触发解析 → 树构建 → L0/L1 生成 → 向量索引。

### 6.2 用户记忆 (user/memories)

用户记忆存储个人偏好、习惯和项目上下文。会话结束后由系统自动提取并更新：

```bash
# 查看用户偏好
ov ls viking://user/memories/preferences/

# 读取特定偏好
ov read viking://user/memories/preferences/coding_habits
```

### 6.3 Agent 上下文 (agent/)

Agent 上下文包括技能（skills）、任务记忆（memories）和指令（instructions），是 Agent 自我演化的核心：

```bash
# 查看 Agent 已掌握的技能
ov ls viking://agent/skills/

# 搜索特定技能
ov find "代码搜索" --uri viking://agent/skills/
```

## 7. 会话自迭代：Agent 越用越聪明

<MermaidDiagram chart={`sequenceDiagram
    participant U as 用户
    participant A as Agent
    participant OV as OpenViking
    participant MEM as 记忆存储

    U->>A: 提问/下发任务
    A->>OV: 搜索上下文
    OV-->>A: 相关记忆 + 资源
    A->>A: 执行任务
    A-->>U: 返回结果

    Note over A,OV: 会话结束，触发记忆提取

    A->>OV: memcommit (提交会话)
    OV->>OV: 分析任务结果
    OV->>MEM: 更新 user/memories
    OV->>MEM: 更新 agent/memories
    MEM-->>OV: 确认更新

    Note over A,OV: 下次对话，记忆更丰富

    U->>A: 新任务
    A->>OV: 搜索(含上次记忆)
    OV-->>A: 更精准的上下文
    A-->>U: 更好的结果
`}/>

会话自迭代的三个关键步骤：

1. **会话记录**：记录完整对话、工具调用、推理过程
2. **记忆提取**：异步分析任务结果和用户反馈，提取偏好、实体、事件
3. **记忆更新**：自动写入 `viking://user/memories/` 和 `viking://agent/memories/`

### 8.5 与 OpenCode / Claude Code 集成

OpenViking 提供 MCP 端点，可以直接作为 OpenCode 或 Claude Code 的记忆后端：

1. OpenViking Server 与 OpenCode 同进程启动
2. Agent 通过 `memsearch`、`memread`、`membrowse` 等工具访问 `viking://` URI
3. 会话结束时通过 `memcommit` 提交记忆
4. 下次会话自动加载历史偏好和技能

## 10. OpenViking vs 传统 RAG：什么时候选什么

    Q2 -->|否| Q4{"需要可观察的检索链路?"}
    
    Q4 -->|是| OV
    Q4 -->|否| Q5{"需要跨会话记忆?"}
    Q5 -->|是| OV_H["OpenViking<br/>(只用记忆功能)"]
    Q5 -->|否| SIMPLE["简单向量库<br/>+ RAG"]
    
    Q3 -->|是| OV_R["OpenViking<br/>(只用资源功能)"]

| 场景 | 推荐 | 原因 |
|------|------|------|
| 多类型上下文（资源+记忆+技能） | OpenViking | 文件系统范式统一管理 |
| 长 Agent 任务、上下文持续增长 | OpenViking | 会话压缩 + L0/L1 降本 |
| 需要调试检索链路 | OpenViking | 轨迹可视化 |
| 代码/文档天然有层级结构 | OpenViking | 目录递归检索 |
| 独立短文档、无层级语义 | 传统向量库+RAG | 更轻量简单 |

## 11. 设计哲学总结

<MermaidDiagram chart={`flowchart LR
    subgraph 核心理念["OpenViking 设计哲学"]
        D1["文件系统范式<br/>→ 统一管理"]
        D2["分层加载<br/>→ 降低成本"]
        D3["目录递归检索<br/>→ 提高精度"]
        D4["轨迹可视化<br/>→ 可观测"]
        D5["会话自迭代<br/>→ 自演化"]
    end

    D1 --> OUT1["告别上下文碎片化"]
    D2 --> OUT2["91% Token 成本降低"]

    D5 --> OUT5["Agent 越用越聪明"]

    style 核心理念 fill:#e1f5fe
`}/>

OpenViking 把 Agent 的上下文管理从"散装 RAG"升级为"可运营的基础设施"。五个核心设计对应五个核心问题：

1. **文件系统范式** → 统一管理 → 解决碎片化
2. **L0/L1/L2 分层** → 按需加载 → 降低 Token 成本
3. **目录递归检索** → 先粗后细 → 提高检索精度
4. **轨迹可视化** → 全链路追溯 → 可观测、可调试
5. **会话自迭代** → 记忆演化 → Agent 越用越聪明
