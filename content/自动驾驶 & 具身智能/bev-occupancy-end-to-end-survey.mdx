# BEV + Occupancy + 端到端 Transformer 智能驾驶算法综述

## 一、引言与研究背景

### 1.1 自动驾驶感知范式的演进

自动驾驶感知经历了从2D检测 → 单目/多目3D检测 → BEV感知 → Occupancy网络 → 端到端大模型的演进路径。早期方法依赖2D图像检测后接几何投影，深度估计误差大、跨相机一致性差。随着Transformer架构的引入，BEV（Bird's Eye View，鸟瞰图）空间成为连接感知与规划的统一表征，Occupancy Network进一步填补了BEV在垂直方向和细粒度建模上的空白，端到端Transformer则将感知、预测、规划乃至控制统一到一个可微网络中，实现了真正意义上的联合优化。

### 1.2 三类技术的定位与关系

| 技术 | 核心作用 | 解决的问题 |
|------|----------|-----------|
| BEV感知 | 将多传感器特征映射到统一的俯视坐标系 | 跨相机融合、尺度歧义、遮挡推理 |
| Occupancy Network | 体素级3D场景占用建模 | 通用障碍物检测、不规则物体、无标注长尾场景 |
| 端到端Transformer | 统一感知-预测-规划的联合建模 | 模块化流水线误差累积、人工接口设计瓶颈 |

三者并非互斥，而是逐层递进、相互增强的关系：BEV提供结构化空间先验，Occupancy提供更稠密的几何表征，端到端Transformer则打通上下游的信息流。

## 二、BEV感知技术体系

### 2.1 BEV的核心思想

BEV的核心在于将多视角/多模态传感器的特征统一到一个以自车为中心的俯视栅格空间中。这一空间具有尺度一致性好、物理意义明确、便于下游任务（车道线、可行驶区域、轨迹规划）使用的优势。

### 2.2 主流BEV范式分类

#### 2.2.1 显式深度估计流派（LSS系列）

Lift-Splat-Shoot (LSS) 是BEV感知的开山之作，其核心流程为：

1. **Lift**：为每个像素预测离散深度分布，将2D图像特征"提升"到3D视锥空间
2. **Splat**：将视锥点云栅格化累加到BEV平面
3. **Shoot**：在BEV空间执行下游检测/分割任务

该流派的代表工作包括：
- **LSS** (ECCV 2020)：首次提出可微分BEV池化
- **BEVDet** (arXiv 2021)：引入时序融合与尺度归一化
- **BEVDepth** (ECCV 2022)：利用激光雷达监督深度分支，显著提升深度精度
- **BEVDet4D** (CVPR 2022)：加入时序信息，通过 ego-motion 对齐历史BEV特征

> **优点**：深度可解释性强，训练稳定
> **缺点**：深度离散化带来量化误差，计算开销随深度分辨率增长

**BEVFormer** (ECCV 2022) 是最具代表性的工作之一，其特点包括：

- **空间交叉注意力**（Spatial Cross-Attention）：每个BEV query通过预定义的相机可视性掩码，只与可见的图像区域做attention
- **时序自注意力**（Temporal Self-Attention）：将当前帧BEV query与上一帧BEV特征通过ego-motion对齐后进行self-attention，实现时序建模
- **可变形注意力**（Deformable Attention）：降低计算复杂度，聚焦于采样点而非全局

![BEVFormer 整体架构](/images/autonomous-driving-survey/bevformer-arch.png)

*BEVFormer 架构图：BEV queries 通过 Spatial Cross-Attention 聚合多相机图像特征，通过 Temporal Self-Attention 融合历史 BEV 特征，最终输出用于 3D 检测与地图分割的统一 BEV 表征。图片来源：Li et al., ECCV 2022*

**PETR** (ECCV 2022) 系列则通过给图像特征添加3D位置编码（3D PE），让query在attention计算时隐式感知空间位置，简化了pipeline。

> **优点**：无显式深度瓶颈，全局建模能力强
> **缺点**：训练收敛慢，对数据量和正则化要求较高

#### 2.2.3 基于MLP的隐式映射流派

HDMapNet → VectorMapNet → MapTR 等高清地图构建工作，以及 BEVFusion 中的camera-to-BEV分支，采用MLP直接学习2D→3D的映射函数。这类方法通常配合深度监督或多模态监督，在轻量化部署上有优势。

### 2.3 多模态BEV融合

**BEVFusion** (ICRA 2023 / NeurIPS 2022 两篇同名工作) 提出了统一的BEV融合框架：

- **Camera-to-BEV**：通过LSS或Transformer生成视觉BEV特征
- **LiDAR BEV**：将点云体素化后提取BEV特征
- **融合策略**：早期融合（特征级concat）、动态融合（attention加权）、自适应门控

多模态融合的关键在于处理异构特征的语义对齐与空间对齐，以及应对传感器失效（如摄像头眩光、激光雷达雨天噪声）的鲁棒性问题。

## 三、Occupancy Network 技术体系

### 3.1 为什么需要Occupancy

传统3D目标检测存在几个根本性局限：

1. **类别封闭集问题**：只能检测训练集中定义的类别，无法处理未知障碍物（如路上掉落的货物）
2. **规则形状假设**：bounding box假设物体是规则几何体，对异形物体（树枝、碎石堆）建模不准确
3. **稀疏表征**：仅对目标物体建模，忽略背景中大量自由空间的语义信息

Occupancy Network通过体素级的二元/多类占用预测，提供了稠密的3D场景表征，天然解决了上述问题。

### 3.2 Occupancy的基本定义

给定场景，Occupancy网络输出一个三维体素网格，每个体素包含：

- **占用概率**：p ∈ [0, 1]
- **语义类别**（可选）：c ∈ [0, C]
- **运动状态**（可选）：v ∈ R³

### 3.3 主流Occupancy方法

#### 3.3.1 基于TSDF/NeRF的隐式建模

- **MonoScene** (CVPR 2022)：首个单目Occupancy预测工作，采用3D U-Net解码器直接回归体素占用
- **OccDepth** (ICRA 2023)：利用深度监督辅助Occupancy学习，通过2D-3D一致性约束提升性能
- **OpenOccupancy** (ICCV 2023)：构建了大规模Occupancy benchmark，提出了LiDAR-camera融合的baseline方法

#### 3.3.2 基于Transformer的稀疏Occupancy

Occupancy Transformer 类方法将Occupancy视为一组稀疏queries，通过cross-attention从图像特征中聚合信息：

- **TPVFormer** (CVPR 2023)：Tri-Perspective View，将3D空间分解为三个正交的平面（XY、XZ、YZ），大幅降低计算量
- **VoxFormer** (CVPR 2023)：两阶段方法，先用深度引导的2D backbone生成稀疏占用种子，再用3D Transformer扩散到全空间
- **SurroundOcc** (ICCV 2023)：多尺度体素特征融合，从粗到细逐步细化占用预测

#### 3.3.3 工业界代表性方案

- **Tesla Occupancy Network** (AI Day 2022)：采用稀疏体素表示，支持任意形状的障碍物检测，输出分辨率达200m×200m×8m，推理速度10Hz+
- **NVIDIA Hydra** (CVPR 2023)：多相机视频输入，结合NeRF-style的体渲染进行监督
- **华为ADS 2.0 / 3.0**：GOD（General Obstacle Detection）网络，本质就是Occupancy思想的工程落地

### 3.4 Occupancy的监督信号来源

| 监督来源 | 说明 | 优缺点 |
|----------|------|--------|
| LiDAR voxel化 | 将激光点云栅格化为真值 | 精确但有遮挡盲区，稀疏 |
| NeRF体渲染 | 通过多视角图像重建光度损失 | 稠密但对纹理依赖强 |
| 深度图监督 | 利用单目/立体深度估计结果 | 成本低但深度噪声大 |
| 自动标注+人工校验 | 工业界主流方案 | 质量高但成本高 |

### 3.5 Occupancy与BEV的关系

Occupancy可以看作是BEV在Z轴方向上的延伸。BEV是2.5D（每个XY位置只有一个高度值），Occupancy是真正的3D体素表征。实践中两者常联合使用：BEV负责结构化元素（车道、交通灯、车辆框），Occupancy负责通用障碍物与自由空间建模。

## 四、端到端Transformer架构

### 4.1 端到端自动驾驶的定义与动机

传统自动驾驶采用模块化流水线：感知 → 预测 → 规划 → 控制，每个模块独立优化，通过人工设计的接口传递信息。这种架构存在：

1. **误差累积**：前一模块的误差不可逆转地传播到下游
2. **信息瓶颈**：手工设计的接口（如检测框、轨迹点）丢弃了大量中间特征
3. **目标不对齐**：各模块的损失函数与最终驾驶行为（安全性、舒适性）不完全一致

端到端自动驾驶旨在用一个神经网络直接从传感器输入映射到规划/控制信号，通过整体驾驶行为指标（如规划轨迹的合理性）反向传播，实现全局最优。

### 4.2 端到端Transformer的演进路线

#### 4.2.1 早期探索（Imitation Learning）

- **ALVINN** (1989)：最早的端到端驾驶，浅层神经网络
- **NVIDIA PilotNet** (2016)：CNN直接映射图像到方向盘转角
- **Conditional Imitation Learning** (CoRL 2017)：引入导航指令作为条件输入

这些方法本质是行为克隆（Behavior Cloning），泛化性差，缺乏因果推理能力。

#### 4.2.2 中间表征流派（Intermediate Representation）

为了兼顾端到端的联合优化与可解释性，许多工作在输入输出之间引入了显式的中间表征：

- **NEAT** (ICLR 2022)：预测未来BEV语义图，再规划轨迹
- **ST-P3** (ECCV 2022)：同时预测BEV语义、占据栅格和未来轨迹
- **UniAD** (CVPR 2023)：统一感知、预测、规划的端到端Transformer，引入query-based的模块间信息传递

**UniAD** 是里程碑式的工作，其架构包含：
1. **TrackFormer**：多目标跟踪
2. **MapFormer**：地图元素检测
3. **MotionFormer**：多智能体运动预测
4. **OccFormer**：占用栅格预测
5. **PlanFormer**：自车轨迹规划

各模块通过共享的BEV query进行通信，整个网络用多任务损失联合训练。

#### 4.2.3 大语言模型+自动驾驶（LLM4AD）

- **DriveGPT / GPT-Driver**：将规划问题建模为语言建模，用LLM生成轨迹token序列
- **DriveLM**：多模态LLM，接受图像+语言指令，输出驾驶决策
- **LMDrive**：闭环端到端系统，LLM作为高层决策器，底层由传统规控执行

这类方法在常识推理、长尾场景理解、人机交互方面有独特优势，但实时性和确定性仍是挑战。

#### 4.2.4 VLA（Vision-Language-Action）范式

最新的端到端系统开始向VLA靠拢，即将视觉、语言、动作统一到一个Transformer中，如：

- **OpenDriveLab的DriveTransformer**：统一tokenize所有输入（图像patch、地图元素、交通信号、导航指令），用decoder-only架构生成规划token
- **Wayve LINGO**：自然语言解释驾驶决策的端到端系统，实现"explainable driving"

### 4.3 端到端Transformer的关键技术

#### 4.3.1 Tokenization策略

端到端Transformer需要将异构输入统一为token序列：

| 输入类型 | Tokenization方式 |
|----------|-----------------|
| 图像 | Patch embedding（ViT风格）或CNN特征flatten |
| 点云 | Pillar/voxel特征或point-wise embedding |
| 地图 | 矢量化的polyline编码（VectorNet风格） |
| 导航指令 | 文本token（BERT/RoPE编码） |
| 历史轨迹 | 轨迹点坐标MLP编码 |

#### 4.3.2 注意力机制设计

- **Hierarchical Attention**：先模态内self-attention，再跨模态cross-attention，降低复杂度
- **Sparse Attention**：只对感兴趣区域（ROI）计算attention，如BEV grid中有关障碍物的位置
- **Causal Masking**：在规划生成时施加因果掩码，确保自回归生成的合法性

#### 4.3.3 多任务损失设计

端到端系统的损失函数通常为多任务加权组合，其中权重的平衡是关键难点，常用方法包括：
- 手动调参（grid search）
- 不确定性加权（Uncertainty Weighting）
- 梯度归一化（GradNorm）
- 动态调整（根据训练阶段变化）

#### 4.3.4 闭环训练与仿真

端到端系统在开环数据集（nuScenes、Waymo）上容易过拟合到专家轨迹，闭环评估至关重要：

- **CARLA simulator**：主流的闭环评测平台
- **World Model**：如GAIA-1、DriveDreamer，学习驾驶世界的动力学模型，用于生成虚拟训练数据
- **RLHF / RLAIF**：用人类反馈或AI反馈微调规划策略

### 4.4 代表性端到端Transformer工作汇总

| 方法 | 年份 | 核心贡献 | 局限性 |
|------|------|----------|--------|
| ST-P3 | 2022 | BEV+规划联合学习 | 预测头较简单 |
| UniAD | 2023 | 全栈模块统一Transformer | 计算量大，推理慢 |
| VAD | 2023 | 矢量化场景建模，轻量化 | 泛化性待验证 |
| GenAD | 2024 | 生成式端到端，diffusion-based规划 | 实时性挑战 |
| Hydra-MDP | 2024 | 多模态规划候选+评分 | 依赖候选生成质量 |
| Ego-MLP | 2024 | 极简端到端baseline | 表达能力有限 |

## 五、BEV + Occupancy + 端到端的一体化架构

### 5.1 三者融合的必然性

随着自动驾驶向L3/L4迈进，单一技术已无法满足需求：

- **BEV** 提供了结构化、语义丰富的俯视表征，适合车道、交通标识等高精地图元素的解析
- **Occupancy** 提供了稠密、通用的3D几何表征，适合任意形状障碍物的检测与避障
- **端到端Transformer** 提供了从感知到规划的全局优化框架，消除了模块间的信息损失

三者的融合不是简单叠加，而是在统一的Transformer架构中实现特征共享与任务协同。

### 5.2 一体化架构的设计模式

#### 5.2.1 共享BEV Backbone + 多任务Head

最直观的方案：用一个共享的BEV特征提取网络（如BEVFormer的encoder），在其上挂载多个任务头：

    Input["Multi-Camera Images"] --> Encoder["Shared BEV Encoder"]

    Encoder --> D2["Map Segmentation"]

    Encoder --> D4["Motion Prediction"]
    Encoder --> D5["Trajectory Planning"]

    style Encoder fill:#e1f5fe,stroke:#0288d1

**优点**：参数共享，训练高效
**缺点**：任务冲突（task conflict），BEV分辨率固定难以同时满足各任务需求

#### 5.2.2 分层级联架构

更高级的方案采用分层设计：

1. **底层**：BEV特征提取（空间对齐、时序融合）
2. **中层**：Occupancy精细化建模（高分辨率体素）
3. **上层**：端到端规划（以BEV+Occupancy为context）

Occupancy作为桥梁：BEV提供宏观布局，Occupancy提供微观几何，规划模块同时消费两者。

#### 5.2.3 Query-centric统一架构

以UniAD为代表的query-centric架构，将一切抽象为query：

- **感知query**：对应场景中每个动态物体
- **静态query**：对应地图元素
- **占用query**：对应体素空间
- **规划query**：对应自车的未来轨迹点

所有query在同一个Transformer中通过attention交互，形成统一的场景理解。

### 5.3 典型一体化系统案例

#### 5.3.1 Tesla FSD v12

虽然Tesla未公开详细架构，但从技术演讲与专利推测：

- 多相机视频输入 → HydraNet backbone
- BEV特征提取 → 占用网络 → 规划网络
- 完全端到端训练，从视频直接输出转向、加速、制动指令
- 取消了手工编码的规则模块，全部由神经网络驱动

#### 5.3.2 国内头部玩家方案

- **华为ADS 3.0**：GOD（通用障碍物检测）+ RCR（道路拓扑推理）+ PDP（预测决策规控）三位一体
- **小鹏XNGP**：XNet（BEV感知）+ XOcc（占用网络）+ XPlanner（端到端规划）
- **理想AD Max**：Occupancy + BEV融合，配合大模型认知增强

## 六、关键技术挑战与前沿方向

### 6.1 计算效率与实时性

端到端Transformer + Occupancy的计算开销巨大。当前的前沿优化方向：

- **稀疏卷积/稀疏注意力**：只对非零体素计算
- **蒸馏与量化**：将大模型蒸馏为轻量级学生网络，INT8/FP16量化部署
- **硬件感知架构设计**：针对NVIDIA Orin、地平线J5等芯片定制算子
- **Early Exit**：根据场景复杂度动态调整计算深度

### 6.2 长尾场景与安全性

端到端系统的黑盒特性使得安全性保障困难：

- **Corner Case挖掘**：生成式世界模型用于合成罕见场景
- **不确定性估计**：Bayesian Transformer、Deep Ensemble等方法量化模型置信度
- **安全guardrail**：保留最小化的规则兜底逻辑（fallback controller）
- **形式化验证**：尝试对规划输出进行可达性分析（reachability analysis）

### 6.3 数据闭环与自动标注

Occupancy真值获取成本极高，数据闭环成为核心竞争力：

- **Auto-labeling pipeline**：LiDAR+SLAM+多帧融合生成伪Occupancy真值
- **Active Learning**：主动选择信息量最大的样本进行人工标注
- **Sim2Real**：高保真仿真生成带Occupancy真值的数据，迁移到实车

### 6.4 世界模型（World Model）的兴起

2024年以来，世界模型成为自动驾驶的新热点：

- **GAIA-1** (Wayve)：视频生成模型，学习驾驶世界的时空动力学
- **DriveDreamer、Drive-WM**：可控制的驾驶视频生成，用于数据增强
- **GenAD**：将规划建模为在世界模型中搜索最优轨迹的过程

世界模型的价值在于：提供无限的合成数据、支持反事实推理（counterfactual reasoning）、实现闭环训练。

### 6.5 基础模型与泛化性

借鉴NLP领域的Foundation Model思路：

- **预训练+微调**：在大规模无标注驾驶数据上预训练BEV/Occupancy backbone，再在特定车型/场景上微调
- **多域适应**：同一模型适配高速、城区、泊车等不同场景
- **跨车型迁移**：从小算力车型学到的表征迁移到大算力车型

### 7.2 核心指标

**感知层面**：
- mAP、NDS（nuScenes Detection Score）
- IoU（Occupancy体素交并比）
- RayIoU（射线投射IoU，更符合传感器观测）

**规划层面**：

- 闭环成功率（Route Completion, Driving Score）

- 场景通过率（Scenario Pass Rate）

## 八、总结与展望

### 8.1 技术演进的底层逻辑

从BEV到Occupancy再到端到端Transformer，背后的驱动力是对场景理解的不断深入与对人工设计依赖的不断减少：

- **BEV**统一了空间表征，消除了跨相机/跨模态的几何歧义
- **Occupancy**补齐了几何建模的细粒度与通用性
- **端到端Transformer**打通了上下游的信息流，让整个系统朝着最终的驾驶目标共同优化

### 8.2 未来3-5年的发展趋势

1. **从"感知+规划"向"世界模型+搜索"演进**：端到端不再只是从输入到输出的映射，而是学会世界的内在规律，在想象中推演多种可能后果后做出决策
2. **多模态大模型全面渗透**：VLM/VLA将承担更多高层认知任务（场景理解、意图推断、人机交互），底层则由高效的专用Transformer处理实时感知与规划
3. **仿真与真实世界的界限模糊**：生成式世界模型将提供接近真实的闭环训练环境，大幅降低实车路测成本
4. **安全与可解释性并重**：监管压力下，端到端系统必须提供决策依据（attention map、counterfactual explanation），并与规则系统形成冗余备份
5. **算力下沉与边缘智能**：随着车载芯片算力提升（千TOPS级），更复杂的Transformer模型将直接在车端运行，云端更多承担训练与数据挖掘角色

### 8.3 结语

BEV + Occupancy + 端到端Transformer的组合，代表了当前自动驾驶算法的最高水平，也是通向L4/L5级自动驾驶最具前景的技术路线。然而，技术的天花板不在于模型规模，而在于对物理世界因果关系的理解与泛化能力。未来的突破很可能来自世界模型的成熟、多模态基础模型的普及，以及对安全性的系统性工程保障。学术界与工业界的协同创新，将继续推动这一领域向前发展。
