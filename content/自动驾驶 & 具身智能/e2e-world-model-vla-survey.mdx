# 端到端规划控制 + 世界模型 + VLA：自动驾驶大模型技术全景综述

## 一、引言

### 1.1 从模块化到一体化的范式转移

过去十年，自动驾驶规划控制的主流范式是分层流水线：感知 → 预测 → 规划 → 控制，每层独立优化，通过人工设计的接口（检测框、轨迹点、代价地图）传递信息。这一架构在工业界证明了可行性，但其结构性缺陷日益凸显：

- **误差级联**：感知的漏检/误检不可逆地影响规划，规划的错误又传导到控制
- **信息压缩瓶颈**：检测框丢失了物体的外观、姿态、上下文语义；代价地图丢弃了原始传感器中的高频信息
- **目标错位**：各子模块的损失函数（如检测mAP、轨迹平滑度）与最终驾驶目标（安全到达目的地）并不直接对齐
- **规则工程的复杂性**：海量手写规则覆盖corner case，导致系统脆弱、维护成本高

端到端规划控制（End-to-End Planning & Control）试图用一个可微网络直接从传感器映射到驾驶动作，从根源上消除上述瓶颈。世界模型（World Model）则通过学习驾驶世界的时空动力学，为端到端系统提供闭环训练环境和反事实推理能力。VLA（Vision-Language-Action）模型引入自然语言作为语义桥梁，赋予自动驾驶常识推理、指令跟随和人机交互能力。三者正加速融合，构成了下一代自动驾驶算法的核心骨架。

## 二、端到端规划控制技术体系

### 2.1 端到端规划的三类范式

端到端规划控制的方法论大致可分为三条主线：模仿学习（IL）、强化学习（RL）、混合方法（IL+RL+搜索）。

#### 2.1.1 模仿学习流派

核心思想：学习人类驾驶员的行为模式，最小化规划轨迹与专家轨迹的差异。

**早期工作**：
- **ALVINN** (1989)：三层神经网络，输入图像直接输出方向盘转角，开创性但极其简陋
- **NVIDIA PilotNet** (2016)：CNN架构，百万级驾驶数据训练，证明端到端在高速公路场景的可行性
- **Conditional Imitation Learning - CIL** (CoRL 2017)：引入导航指令（直行/左转/右转）作为条件输入，解决"路口该往哪走"的问题

**局限性**：
- **协变量偏移**（Covariate Shift）：测试时遇到训练分布外状态，误差累积导致偏离专家分布
- **因果混淆**（Causal Confusion）：模型可能学到虚假相关性
- **多模态性缺失**：专家轨迹是单一的，但合法驾驶行为往往有多种

**改进方向**：
- **DAgger**：交互式收集数据，让专家在模型犯错的状态下进行标注，缓解协变量偏移
- **多模态规划**：用混合密度网络（MDN）或离散化轨迹候选（Anchor-based）建模多峰分布
- **成本函数学习**：不直接模仿轨迹，而是学习一个可微分的成本函数，再通过优化器求解最优轨迹

#### 2.1.2 强化学习流派

核心思想：通过与环境交互获得奖励信号，学习最大化长期累积奖励的策略。

挑战：自动驾驶的真实世界交互成本极高（事故风险），因此RL在自动驾驶中的应用主要集中在仿真训练+Sim2Real迁移。

**代表性工作**：
- **CARLA Leaderboard 上的RL方案**：在CARLA仿真中用SAC、TD3等off-policy算法训练驾驶策略
- **Safety Gym / HighwayEnv**：简化的 highway 场景，用于验证RL算法的安全性
- **Offline RL / IRL**：从离线驾驶数据中学习，避免在线交互的风险。如 GAIL 用对抗训练从专家数据中学习奖励函数

#### 2.1.3 混合范式：学习成本函数 + 轨迹优化

这是近年来最有影响力的方向之一，核心思想是不学策略，学"什么是一条好轨迹"的评判标准：

![UniAD 全栈端到端架构](/images/autonomous-driving-survey/uniad-pipeline.png)

*UniAD 整体流水线：多相机图像经 BEV Encoder 提取特征后，依次经过 TrackFormer、MapFormer、MotionFormer、OccFormer，最终由 PlanFormer 输出自车规划轨迹。图片来源：Hu et al., CVPR 2023*

**MP3** (ICCV 2021)：预测未来 occupancy flow，定义可微分轨迹成本（碰撞成本、车道跟随成本、舒适度成本），用梯度下降优化初始轨迹。

**NMP** (CVPR 2019)：CNN预测cost volume，在cost volume上做可微分轨迹优化。

**ST-P3** (ECCV 2022)：联合学习BEV语义、occupancy、未来轨迹，轨迹解码器消费BEV+Occ特征，输出多模轨迹。

**UniAD** (CVPR 2023 Best Paper)：将感知、预测、规划统一在一个Transformer中。规划模块以track/motion/map/occ的query表征为输入，输出自车未来轨迹。

**VAD** (ICCV 2023)：

![VAD 矢量化端到端架构](/images/autonomous-driving-survey/vad-arch.png)

*VAD 架构图：将场景中的所有元素（车辆、车道线、地图）矢量化为 token 序列，输入 Transformer 编码后输出矢量化规划轨迹，避免了 BEV 栅格的固定分辨率限制。图片来源：Jiang et al., ICCV 2023*

VAD 的核心创新在于将整个驾驶场景进行矢量化编码。不同于 ST-P3 和 UniAD 使用 BEV 栅格作为中间表征，VAD 将每个 agent 和地图元素表示为矢量化的 token（位置、速度、类别等属性），并通过 Transformer 的 self-attention 机制建模它们之间的交互关系。这种表示方式的优势在于：

- **参数高效**：不再需要固定分辨率的 BEV 栅格，场景表示由实体的数量而非空间范围决定
- **几何精确**：车道线的曲率、车辆的朝向等几何信息被精确保留，而不是被栅格化离散化
- **计算聚焦**：注意力计算只发生在有实体的区域，避免了在空旷的 BEV 栅格上浪费计算资源

VAD 的规划头直接输出一组轨迹点，通过一个轻量化的 MLP 解码器从 scene token 中回归得到，因此推理速度显著优于 UniAD。

**GenAD** (CVPR 2024)：将规划建模为条件生成问题。GenAD 的核心洞察是——驾驶场景中的最优轨迹选择本质上是一个多模态条件生成问题：给定相同的场景，左变道和跟车等待可能都是合理的。传统的回归式规划头只能输出一条确定的轨迹，而 GenAD 将轨迹生成建模为一个条件去噪扩散过程：

1. **前向过程**：在训练时，从真实的专家轨迹出发，逐步添加高斯噪声直至完全随机
2. **反向过程**：学习一个去噪网络，以当前场景的 BEV 特征和历史状态为条件，从随机噪声中逐步恢复出合理的轨迹
3. **条件注入**：去噪过程中的每一步都以场景上下文 embedding 为输入，使得生成的轨迹与当前场景语义一致

推理时，从纯噪声出发采样多步去噪即可得到多样化的轨迹候选，再配合一个轻量级的 scoring network 从候选中选择最优轨迹。与 anchor-based 方法相比，diffusion 方法能生成更平滑、更自然的轨迹分布，且可以通过调节去噪步数灵活控制生成质量与推理速度的权衡。

**Hydra-MDP** (CVPR 2024)：Hydra-MDP 提出了一个优雅的"多目标蒸馏"框架来学习多模态规划。其核心思想在于：虽然人类驾驶行为是多模态的（不同司机会做出不同但都合理的决策），但不太容易直接让模型学会"什么是一般的好轨迹"。Hydra-MDP 的做法是：

1. **教师策略生成**：用多个不同风格的专家策略（激进型、保守型、平衡型）在仿真器中生成大量轨迹候选
2. **候选蒸馏**：用这些多样化但都是合理的学生轨迹集合作为监督信号，训练一个学生网络
3. **评分网络学习**：同时训练一个评分网络，学习区分"好轨迹"和"坏轨迹"——训练数据中的正样本来自教师策略 + 人工偏好标注，负样本来自随机扰动和失败案例
4. **推理**：学生网络输出 K 条候选轨迹，评分网络为每条轨迹打分，选取得分最高者执行

这种方法本质上是将"如何定义好轨迹"这一主观问题转化为"如何区分好和坏"的偏好学习问题，大幅降低了对专家标注的精确性要求，同时保留了驾驶行为的多模态特性。

### 2.2 端到端规划的关键技术组件

#### 2.2.1 场景表征（Scene Representation）

| 表征方式 | 代表工作 | 优点 | 缺点 |
|----------|---------|------|------|
| BEV栅格 | ST-P3, UniAD | 结构规整，卷积友好 | 分辨率固定，远处精度低 |
| 矢量化 | VectorNet, VAD | 精确建模几何，参数高效 | 对拓扑变化敏感 |
| Token序列 | GPT-Driver, DriveTransformer | 统一接口，大模型友好 | 序列化损失空间关系 |
| Occupancy体素 | OccNet, Tesla Occ | 稠密几何，通用障碍物 | 计算量大，内存占用高 |
| 稀疏点云 | PointPillar-based E2E | 保留3D几何 | 稀疏性导致上下文有限 |

趋势：混合表征正在成为主流——BEV提供宏观布局，矢量化map提供精确拓扑，Occupancy提供稠密几何，三者共同服务于规划模块。

#### 2.2.2 轨迹表示与解码

**参数化曲线**：多项式曲线、样条曲线、贝塞尔曲线

**离散点序列**：固定频率的未来轨迹点，端到端Transformer直接回归这些点的offset

**Diffusion-based轨迹生成**（新兴方向）：将轨迹去噪过程建模为reverse diffusion，条件包括当前场景BEV特征、导航指令、历史状态。生成多样化的合理轨迹，再由scorer选择最优。

#### 2.2.3 多模态规划与不确定性

**隐式多模态**：模型内部用mixture of experts或multi-head attention产生多样输出，训练时用Winner-Takes-All loss

**显式多模态**：并行生成N条候选轨迹，每条轨迹配一个confidence score，推理时取top-K或加权平均

**不确定性量化**：Bayesian Neural Networks、Deep Ensemble等方法

#### 2.2.4 闭环训练策略

| 方法 | 核心思想 | 代表工作 |
|------|---------|----------|
| DAgger | 在线收集错误状态下的专家标注 | CIL-Dagger |
| Model-based RL | 用世界模型rollout，在想象中训练 | Dreamer, GAIA-1 |
| CARLA仿真 | 在仿真器中闭环评测+训练 | Roach, LBC |
| 重标注+重采样 | 对失败场景过采样 | nuPlan |
| 对抗性场景生成 | 主动生成困难场景训练模型 | AdvSim, MeshDrive |

nuPlan 是目前最重要的闭环规划benchmark之一，提供了大规模真实驾驶日志+可交互仿真器。

#### 2.2.5 安全与可解释性

- **安全层**：在神经网络输出后接规则化的安全检查模块
- **注意力可视化**：Transformer的attention map显示模型关注区域
- **反事实解释**：世界模型可以生成"如果...那么..."的解释
- **形式化验证**：用数学方法证明在某些输入集合下，规划输出始终满足安全约束

## 三、世界模型（World Model）技术体系

### 3.1 世界模型的定义与动机

世界模型是对环境动力学的概率性建模：即在状态 s 下执行动作 a 后，世界如何演化到下一状态 s'，同时产生什么样的观测 o'。

在自动驾驶中，世界模型的作用包括：
1. **闭环训练平台**：让端到端规划策略在"想象"中反复试错，无需真实路测
2. **数据增强引擎**：生成现实中罕见的长尾场景（极端天气、异常障碍物）
3. **反事实推理**：评估"如果采取不同动作，结果会怎样"，用于安全验证
4. **预测模块**：预测其他交通参与者的未来行为，服务于规划

### 3.2 世界模型的演进脉络

#### 3.2.1 早期：RNN-based动力学模型

**RSSM（Recurrent State Space Model）** —— Dreamer 系列 (ICLR 2020/2021/2023)：

RSSM 是 Dreamer 系列的核心组件，它巧妙地将世界模型的状态空间分解为两个互补的部分：

- **确定性状态**（Deterministic State）：用 GRU 或 LSTM 建模，负责记住过去若干时间步的事件序列。例如，"前车从 3 秒前开始刹车"这一信息需要跨时间步传递，由确定性状态负责
- **随机状态**（Stochastic State）：用 VAE-style 的变分推断建模，负责捕捉当前时刻的不确定性。例如，"前车可能刹车也可能不刹车"的歧义性，由随机状态的分布来表征

RSSM 的推理过程如下：

1. 上一时刻的确定性状态 h(t-1) 和随机状态 z(t-1) 通过 RNN 得到当前时刻的确定性先验 h(t)
2. 从 h(t) 出发，通过一个先验网络 p(z(t) | h(t)) 预测当前时刻的随机状态
3. 同时，当前观测 o(t)（即图像帧）通过后验网络 q(z(t) | h(t), o(t)) 给出更准确的随机状态估计
4. 训练目标是最小化先验和后验之间的 KL 散度，同时用重建损失让模型学会从状态恢复观测

这种"确定+随机"的双重设计让 RSSM 能够同时建模可预测的确定性演化（如车辆沿车道前行）和不可预测的随机事件（如行人突然横穿）。

![DreamerV3 架构](/images/autonomous-driving-survey/dreamer-arch.png)

*DreamerV3 世界模型架构：通过 RSSM 在隐空间中建模状态演化，支持 model-based RL 的闭环训练。图片来源：Danijar Hafner*

![RSSM 状态空间模型](/images/autonomous-driving-survey/rssm-arch.png)

*RSSM 的确定性与随机状态双重设计：确定性状态（GRU）负责时序记忆，随机状态（Latent Distribution）负责不确定性建模。两者结合使世界模型既能预测确定性演化又能表达随机事件。图片来源：Danijar Hafner*

DreamerV3 的关键创新还在于引入了无偏的 KL 平衡机制和自由信息量（Free Bits）约束，使得世界模型在大规模视觉场景中训练更稳定。通过在 latent space 中进行 model-based RL，Dreamer 系列在 Atari 游戏和 DM Control 等任务上取得了超越 model-free RL 方法的样本效率。

局限：RSSM 用 RNN 建模时序，长程依赖能力有限，且生成的视频帧分辨率较低，难以直接用于真实的自动驾驶场景。

#### 3.2.2 中期：扩散模型+Transformer的生成式世界模型

2023年是自动驾驶世界模型的爆发之年：

**GAIA-1** (Wayve, 2023)：

![GAIA-1 架构](/images/autonomous-driving-survey/gaia1-arch.png)

*GAIA-1 世界模型架构：用 VQ-VAE 将视频压缩为离散 token，GPT-style Transformer 自回归生成，支持动作与文本条件控制。图片来源：Wayve*

GAIA-1 是世界模型领域里程碑式的工作，它首次展示了大规模生成式世界模型在自动驾驶中的可行性。其架构由三个核心组件构成：

**1. 世界模型编码器（World Model Encoder）**：对输入的视频帧序列进行压缩。GAIA-1 使用 VQ-VAE 将每一帧图像编码为离散的视觉 token，这些 token 以自回归的方式编码了视频帧中的空间结构和时序变化。文本描述和动作指令被编码为条件 token，用于指导后续的视频生成。

**2. 时序先验网络（Temporal Prior Network）**：一个 GPT-style 的 Transformer，以自回归的方式在 token 空间中预测未来帧的 token 序列。它基于：
- 当前和历史帧的视觉 token（观测信息）
- 动作 token（油门、转向等控制指令）
- 文本 token（场景描述或驾驶指令）

通过最大化下一个 token 的似然进行训练。这个 Transformer 本质上学到了"给定我的观测和我的动作，世界最可能如何演化的概率分布"。

**3. 视频解码器（Video Decoder）**：将 Transformer 预测的离散 token 序列解码回像素空间的视频帧，得到最终的可视化驾驶视频输出。

GAIA-1 的条件控制能力是其最突出的特性——通过改变动作和文本输入，可以生成同一场景的不同未来演化（"如果加速会怎样" vs "如果刹车会怎样"），这使其天然适用于反事实推理和数据增强。

*GAIA-1 的三阶段生成流程：VQ-VAE 将视频压缩为离散 token，Transformer 在 token 空间自回归预测未来，最后解码为像素级视频。*

- 输入：视频帧 + 文本描述 + 动作（油门/转向）
- 架构：VideoGPT-style，用VQ-VAE将视频压缩为离散token，再用GPT-style Transformer自回归生成
- 能力：生成多样且物理合理的驾驶视频，支持条件控制
- 意义：首次展示了大规模生成式世界模型在自动驾驶中的可行性

**DriveDreamer** (ICCV 2023)：双分支架构，前景+背景分别建模，引入HDMap作为结构先验。

**Drive-WM** (CVPR 2024)：基于扩散模型的多视角视频生成，支持多相机输入的时空一致性生成，可用于端到端规划策略的闭环训练。

**ADriver-I** (2024)：视频预测模型作为世界模型，与规划模块联合优化，形成"预测-规划"闭环。

#### 3.2.3 世界模型的架构范式对比

| 范式 | 代表方法 | 建模对象 | 优缺点 |
|------|---------|----------|--------|
| Latent RSSM | Dreamer系列 | latent state transition | 紧凑高效，但生成质量有限 |
| Autoregressive Transformer | GAIA-1 | 视频token序列 | 长程一致性强，但推理慢 |
| Diffusion Model | DriveDreamer, Drive-WM | 像素/潜空间去噪 | 生成质量高，可控性好 |
| Hybrid | 最新趋势 | 多层抽象 | 综合性能最佳，但工程复杂 |

### 3.3 世界模型的关键技术挑战

#### 3.3.1 物理一致性

生成的视频必须符合物理定律：车辆不能穿墙、运动必须连续平滑。

解决方案：引入几何先验（depth、optical flow）、多任务监督、物理约束惩罚。

#### 3.3.2 长时序一致性

生成超过几秒的视频时容易出现漂移。

解决方案：分层生成（关键帧+插值）、递归生成+状态记忆、双向注意力。

#### 3.3.3 动作可控性

世界模型必须响应不同的动作输入，生成对应的未来演化。

解决方案：Classifier-free guidance、动作token化、多尺度动作建模。

#### 3.3.4 Sim2Real Gap

缓解策略：域随机化、对抗性域适应、混合训练（真实+生成数据）、不确定性感知。

### 3.4 世界模型在自动驾驶中的具体应用

**作为闭环训练环境**：端到端规划策略可以在世界模型中"做梦"（dreaming），通过数千次rollout积累经验：

**作为数据增强引擎**：对于长尾场景，世界模型可以合成大量变体，改变障碍物类型、环境条件、相对速度和距离。

**作为预测模块**：世界模型隐式建模所有agent的联合演化，自动捕捉交互关系。

## 四、VLA（Vision-Language-Action）模型体系

### 4.1 VLA的本质：语义桥梁

VLA模型的核心价值在于引入自然语言作为语义抽象层，将低级的像素/点云信号与高级的驾驶决策连接起来：

1. **常识推理**：语言模型内置了关于世界的常识
2. **指令跟随**：能够理解并执行自然语言导航指令
3. **可解释性**：可以输出决策的自然语言解释
4. **人机交互**：乘客可以用自然语言与车辆对话
5. **零样本泛化**：通过语言描述处理训练中从未见过的新场景

### 4.2 VLA在自动驾驶中的技术演进

#### 4.2.1 早期：视觉问答 + AD

DriveQA 等早期工作将驾驶场景建模为VQA任务，主要用于场景理解，尚未直接输出驾驶动作。

#### 4.2.2 中期：LLM-as-Planner

**GPT-Driver** (CoRL 2023)：用GPT-3.5/4作为高层规划器，将场景信息用自然语言描述，LLM输出规划决策，底层由传统控制器执行。

**DriveLM** (NeurIPS 2023)：

![DriveLM GVQA 架构](/images/autonomous-driving-survey/drivelm-pipeline.jpg)

*DriveLM 的整体流水线：将驾驶任务建模为 Graph Visual Question Answering（GVQA），通过多轮视觉问答逐步完成从感知到推理到决策的推理链条。图片来源：DriveLM*

DriveLM 的核心贡献是提出了 **Graph Visual Question Answering（GVQA）** 范式。它将驾驶决策过程分解为一系列结构化的视觉问答，形成一个推理图（Reasoning Graph）：

1. **感知层 Q&A**："图像中是否有行人？行人在什么位置？车的速度是多少？"
2. **推理层 Q&A**："行人是否在横穿马路？我的车是否应该减速？右侧车道是否有车？"
3. **决策层 Q&A**："基于以上分析，我应该减速让行还是继续直行？"

这个推理链的设计使得驾驶决策过程完全可解释——每个决策都可以追溯到具体的感知证据和推理步骤。DriveLM 基于 BLIP-2 和 Vicuna 架构，训练数据来自 nuScenes 的人工标注指令-响应对以及通过规则自动生成的结构化 QA 数据。

**LMDrive** (CVPR 2024)：

![LMDrive 架构](/images/autonomous-driving-survey/lmdrive-arch.png)

*LMDrive 闭环端到端 VLA 系统架构：视觉编码器 + LLM + 控制模块，支持自然语言指令驱动的驾驶。图片来源：LMDrive*

- 闭环端到端VLA系统
- 用LLaVA风格的架构，将图像编码为visual tokens，与文本tokens拼接后输入LLM
- 输出控制信号（转向、加速、制动）
- 在CARLA中实现了语言指令驱动的驾驶

#### 4.2.3 近期：端到端VLA Transformer

**DriveTransformer** (OpenDriveLab, 2024)：将所有输入统一tokenize，decoder-only Transformer架构，输出规划token序列。

**LINGO** (Wayve, 2023)：语言增强的端到端驾驶系统，在FSD-style的端到端网络上增加语言解码头，可以同时输出驾驶动作+决策解释。

**EMMA** (Waymo, 2024)：Gemini架构在自动驾驶上的适配，多摄像头输入，输出3D检测、车道图、规划轨迹。

**Senna** (港科大, 2024)：双系统架构——快系统（端到端规划）+ 慢系统（VLM推理）。

### 4.3 VLA的关键技术组件

#### 4.3.1 视觉编码器

| 视觉编码器类型 | 代表 | 特点 |
|--------------|------|------|
| ViT | CLIP-ViT, EVA | 全局建模强，与大模型兼容性好 |
| ConvNeXt/Swin | 传统CNN现代化变体 | 局部归纳偏置，训练稳定 |
| BEV-aware Encoder | BEVFormer backbone | 输出BEV特征，直接服务于规划 |
| 多尺度Encoder | FPN-style | 兼顾远近目标的识别 |

#### 4.3.2 语言接口设计

**文本化描述**：直接兼容现有LLM，但信息密度低，空间关系表达不精确。

**结构化提示**：精确、紧凑、机器可读，但需要精心设计。

**视觉token + 语言token联合输入**：图像经ViT编码为visual tokens，文本经tokenizer编码后拼接输入LLM，是目前端到端VLA的主流方案。

#### 4.3.3 动作空间设计

| 动作层级 | 输出形式 | 代表工作 |
|---------|----------|----------|
| 高层语义动作 | "直行"、"左变道" | GPT-Driver |
| 中层轨迹 | 未来轨迹点序列 | DriveTransformer, EMMA |
| 底层控制量 | 转向角/加速度/制动 | LMDrive（CARLA仿真） |
| 混合输出 | 轨迹+自然语言解释 | LINGO, DriveLM |

#### 4.3.4 训练策略

**Stage 1**：视觉-语言对齐预训练
**Stage 2**：驾驶场景指令微调
**Stage 3**：闭环强化学习（可选）
**Stage 4**：人类反馈强化学习（RLHF）

### 4.4 VLA的局限性与挑战

**幻觉问题**：LLM可能编造不存在的物体或场景属性。缓解方案包括grounding机制、不确定性校准、规则兜底。

**实时性挑战**：LLM推理延迟高。解决方案包括蒸馏、缓存、异步架构、硬件加速。

**数据稀缺**：高质量（图像、指令、规划、解释）四元组数据稀缺。解决方案包括自动标注、仿真合成、众包采集。

**评估难题**：需要新benchmark如DriveLM Challenge、LingoQA、NuPrompt。

## 五、三者融合：端到端 + 世界模型 + VLA

### 5.1 融合的必要性

| 组件 | 短板 |
|------|------|
| 端到端规划 | 黑盒、安全性难保障、数据饥渴、泛化性有限 |
| 世界模型 | 自身不做决策，需要搭配policy才能发挥作用 |
| VLA | 实时性差、幻觉风险、计算开销大 |

**融合后的协同效应**：
- 世界模型为端到端规划提供无限的训练场
- VLA为端到端规划注入常识推理和语义理解
- 端到端规划为VLA和世界模型提供明确的优化目标和评测标准

### 5.2 融合架构的典型模式

#### 5.2.1 双系统架构（Fast-Slow Architecture）

#### 5.2.2 世界模型驱动的VLA训练

VLA模型需要大量交互数据进行强化学习，但真实路测昂贵且危险。世界模型提供了一个安全的虚拟训练场：

1. 世界模型学习真实驾驶数据的分布
2. VLA模型在世界模型中rollout，获得（状态，动作，奖励）轨迹
3. 用RL从rollout中更新VLA的policy
4. 周期性地在真实数据中验证，防止sim2real drift

代表：Wayve的整体技术路线（GAIA-1 + LINGO）

#### 5.2.3 端到端规划中的隐式世界模型

一些端到端Transformer在训练过程中隐式地学会了世界模型。UniAD中的MotionFormer预测其他agent的未来轨迹，本质上就是一个世界模型的特例。

#### 5.2.4 VLA作为世界模型的控制器

世界模型生成视频，VLA理解视频并做出决策，形成完整的生成-理解-行动闭环。

### 5.3 融合系统的训练范式

#### 5.3.1 联合训练 vs 分步训练

**分步训练**（主流）：先训练世界模型，再训练VLA，最后训练端到端规划。

**联合训练**（前沿）：所有组件共享backbone，通过多任务loss联合优化。

#### 5.3.2 课程学习

| 阶段 | 场景复杂度 | 训练目标 |
|------|-----------|----------|
| 1 | 高速巡航 | 车道保持、跟车 |
| 2 | 城市道路 | 红绿灯、路口通行 |
| 3 | 密集交互 | 无保护左转、行人避让 |
| 4 | 极端场景 | 恶劣天气、施工路段 |
| 5 | 长尾case | 罕见障碍物、异常行为 |

### 5.4 融合系统的评估框架

**功能性指标**：规划精度、指令遵循率、场景通过率

**安全性指标**：碰撞率、违规率、不确定性校准程度、安全层介入频率

**智能性指标**：常识推理正确率、解释合理性、长尾场景处理能力

**效率指标**：推理延迟、计算资源消耗、能耗

**推荐Benchmark**：nuPlan、CARLA Leaderboard、DriveLM、OpenLoop + ClosedLoop

## 六、前沿方向与开放问题

### 6.1 世界模型的下一个突破点

**4D Occupancy World Model**：将Occupancy作为世界模型的建模对象，直接预测未来3D体素占用，是更有物理意义的路径。

**因果世界模型**：引入因果推理的世界模型能更好地泛化到新场景。

**多智能体世界模型**：需要建模多agent的交互博弈。

### 6.2 VLA的下一个突破点

**具身语言模型**：真正理解物理世界的约束，需要LLM与物理引擎/几何推理模块的深度结合。

**个性化VLA**：通过自然语言交互学习乘客偏好，在规划中体现。

**多轮对话式驾驶**：持续的自然语言交互而非一次指令。

### 6.3 端到端规划的下一个突破点

**Diffusion-based Planning的规模化**：蒸馏diffusion模型为单步模型、硬件友好加速。

**可证明安全的端到端系统**：将形式化验证方法引入深度学习。

**端到端控制**：从图像直接输出转向、油门、制动。

### 6.4 三者的终极融合形态

## 七、总结

端到端规划控制、世界模型、VLA模型代表了自动驾驶算法从"规则驱动"向"数据驱动"、从"分模块优化"向"全局联合优化"、从"纯几何感知"向"语义+常识推理"的深刻转变。

端到端规划控制正在从开环模仿走向闭环生成，从单一轨迹走向多模态分布，从黑盒不可控走向可解释可验证。世界模型正在从简单的视频生成走向物理一致性的4D场景演化建模，成为端到端系统不可或缺的"虚拟练车场"。VLA模型正在从实验室的视觉问答走向车端的实时语义推理，赋予自动驾驶以常识和沟通能力。

三者的融合不是简单的拼凑，而是深度的协同：世界模型让端到端规划在想象中成长，VLA让端到端规划拥有智慧的大脑，端到端规划则是最终的执行者。这一融合架构正在重新定义什么是"自动驾驶的大脑"。

未来的3-5年，我们将看到：
1. 世界模型从研究走向工程化落地，成为自动驾驶数据闭环的核心组件
2. VLA从辅助角色走向与端到端网络深度融合，形成快慢双系统的标准架构
3. 端到端规划从demo走向量产，L3/L4级功能在越来越多的车型上落地
4. 行业格局从"谁的规控规则写得更好"转向"谁的数据闭环和模型规模更强"

这场变革的本质，是用通用人工智能（AGI）的技术范式重构自动驾驶。当驾驶的每一个环节都可以用数据驱动的方式学习和优化时，自动驾驶的真正规模化落地就不再遥远。
