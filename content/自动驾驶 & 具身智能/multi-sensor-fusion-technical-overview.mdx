# 自动驾驶多传感器融合技术全景梳理

## 一、每个传感器都有短板，融合是补短板

一辆智能驾驶汽车靠摄像头、激光雷达、毫米波雷达、IMU、GNSS 感知环境。单看每一类都有短处。摄像头认得颜色和交通标识，逆光、夜晚容易失效。激光雷达输出厘米级精度的三维点云，雨雾天气性能掉得很快。毫米波雷达测距测速稳定，不受昼夜影响，分辨率低，分不清对面是人是墙。多传感器融合就是把多路异构数据整合成统一的全局环境模型，供后头的预测和规划取用。

这篇内容的起点是小红书上一组五张长图，作者是车企求职陪跑Seven，账号主业是车企求职辅导。我把图里写到的技术点对照论文和厂商公开资料查了一遍，能核实的下面都写了来源，只有作者一家说法的我会单独交代。

硬件怎么布置，跟着探测距离和覆盖角度走。前视摄像头管远距离道路识别，环视摄像头绕车身一圈，负责泊车。激光雷达装在车顶或车头，取 3D 空间信息。毫米波雷达在保险杠四角各装一个，恶劣天气下顶替视觉做障碍物探测。超声波雷达在低速、近距离补盲。IMU 和 GNSS 不感知物体，它们输出车自身的位置姿态。整车传感器相互补盲，这正是布置图想强调的。

传感器输出的数据格式彼此不通。图像是像素，点云是带坐标的反射点，毫米波给的是目标级距离速度，IMU 给角速度加速度。输出频率也不齐。那组图里给的例子是激光雷达 10Hz、摄像头 30Hz、IMU 高达 100-1000Hz。数据没对上时刻就拿去算，同一个障碍物会对应到车在不同时刻的位置，目标直接错位，这是融合要解决的第一个难点。

## 二、融合之前的同步，时间和空间都要做

各个传感器独立工作，采集时刻和坐标系各不相同。做融合之前先回答两个问题，数据在哪个时刻，目标在哪个坐标系。

空间同步靠外参标定。标定每个传感器相对车身的安装位置和旋转角，把图像、点云、雷达目标全部转到车身坐标系。标定误差会一路传导到融合结果，目标漂移、位置错位都可能从这里来。时间同步把各路数据拉到同一个时刻，高频数据取最近帧或插值，低频数据用运动模型往前推。两块都做完，后续融合才有立足点。

标定这件事在工程上有现成开源工具。OpenCalib 是 PJLab-ADG 团队开源的多传感器标定工具箱，Apache-2.0 协议，配套论文 arXiv 2205.14087，覆盖相机内参、lidar2camera、radar2camera、lidar2imu 等标定项，还有跑在线标定的 SensorX2car 分支。做融合项目前，标定环节可以直接站在它上面搭，不用从头搓。

## 三、三种融合层级，取舍都在明处

按数据在哪一步汇合，行业分成数据级前融合、特征级中融合、目标级后融合三类。三类各有代价，下面对着图讲。

后融合又叫决策级融合。每个传感器先各自跑完整套感知算法，各自输出障碍物目标列表，包含位置、尺寸、速度、类别。融合模块只接这些结构化结果，做目标关联、加权融合、目标跟踪。好处是各路感知流程独立，坏一个传感器，整套系统不至于一起停摆，工程实现也简单，早期量产车型大量用。代价是原始信息在各路内部已经丢掉，融合只能对着结构化结果做，精度上限摆在那里。

前融合也叫数据级融合。图像像素、激光点云还没做目标检测就拼接在一起，送进统一网络。理论上保留的原始信息最多，代价也最突出，原始数据量巨大，算力消耗高，对时间同步和标定精度的要求苛刻，噪声容易互相干扰。目前量产落地少，更多用在科研场景。前融合里有一支常见流派是点级融合，把图像语义打到点云上，代表工作是 PointPainting，CVPR 2020，方法是把图像语义分割的类别得分投影到每个激光点上，再喂给点云检测网络，PointRCNN、VoxelNet、PointPillars 三个点云检测器都因为这一手在 KITTI 和 nuScenes 上明显涨点。BEVFusion 论文把这类方法批评了一遍，说投影到点的过程把相机特征的语义密度扔掉了。

![PointPainting 三阶段流程](/images/sensor-fusion/pointpainting-fig2-overview.png)

*图来自 PointPainting 论文 Figure 2（Vora et al., CVPR 2020）。上排是三个阶段，图像语义分割、把类别得分投影到激光点、点云检测网络输出结果*

这张图的读法看三个阶段。图像先进语义分割网络，拿到逐像素类别得分。激光点再投影到分割结果上，每个点按它落进哪个像素被涂上对应类别得分，点云从纯几何带上语义。涂完的点云交给纯激光雷达检测网络，PointRCNN、VoxelNet、PointPillars 这类模型直接使用。融合发生在点这一级，所以叫点级前融合。

中融合是特征级融合，当前量产主流。各路网络先各自提取中间层特征，再把视觉特征和点云特征投影到统一的 BEV 鸟瞰空间完成融合，之后做目标检测和分割，代表方案是 BEVFusion。它保留了原始特征里的好东西，算力开销又压得住，华为 ADS、小鹏 XNGP 等主流智驾系统被公认走在这条路上。

这个说法要交代一下边界。华为和小鹏都没有把融合流程完整公开，那张图说两家都采用特征级融合，我只能理解为行业公认的判断，无法逐字核实。BEV 特征融合成为量产感知的主流方向，这一条写进论文和各家发布会的公开口径，可信度高。

## 四、BEV 特征融合的原理与工程实现

BEV 空间是给规划用的。LSS 论文把自动驾驶感知的目标写得很直接，从多个传感器提取语义表示，融进同一个鸟瞰坐标，供运动规划取用。BEV 是自车为中心、范围固定的俯视栅格，尺度一致，车道线、障碍物、可行驶区域这些下游要的东西都摆在一个平面上。

![LSS 的多视图输入与 BEV 语义输出](/images/sensor-fusion/lss-fig1-hook.jpg)

*图来自 LSS 论文 Figure 1（Philion & Fidler, ECCV 2020）。左侧是环视相机输入，右侧是网络直接在 BEV 坐标系输出的语义图，蓝色是车辆分割，橙色是可行驶区域，绿色是车道线，预测结果又投影回左侧输入图像上*

这张图把 BEV 感知的形态一次讲完。网络不输出图像坐标系里的框，直接输出鸟瞰坐标里的语义图，规划要的车道线、可行驶区域、车辆都在同一个平面上，和自车位置一一对应。

相机特征怎么进 BEV，LSS 给了最早的端到端答案，三步。Lift 把每张图像单独抬成视锥特征，每个像素同时预测一组深度概率，深度分布和特征做外积，一个像素变成一条竖着铺开、深度方向有 D 层的特征线。Splat 把所有相机的视锥栅格化进同一个 BEV 网格，重叠区域做池化。Shoot 在 BEV 上挂任务头，检测、分割，还能把模板轨迹射进代价图直接做规划。整条流水线可微，从相机到 BEV 一路反传，训练时整组相机一起学，论文里特别提到这种端到端训练让它对标定误差有鲁棒性。

![Lift-Splat-Shoot 整体流程](/images/sensor-fusion/lss-fig4-outline.png)

*图来自 LSS 论文 Figure 4（Philion & Fidler, ECCV 2020）。左侧是 n 路相机图像和内外参，Lift 阶段为每张图生成视锥点云，Splat 阶段按内外参把视锥栅格化到 BEV 平面，最后 BEV 卷积网络处理栅格输出结果*

论文自己的流程图比文字更清楚。注意 Lift 阶段每路相机各生成一个视锥，Splat 阶段才把多路视锥汇到同一个 BEV 平面，跨相机融合发生在这一步，相机再多也只是多几个视锥。

![LSS 的 lift 步骤](/images/sensor-fusion/lss-fig3-lift.png)

*图来自 LSS 论文 Figure 3。每个像素同时预测一个 D 类深度分布和一条 C 维上下文向量，射线上每个点的特征由两者的外积给出*

Lift 的数学动作在代码里就是深度分布和特征的广播相乘，原理示意如下，LSS 仓库里为了速度用了别的高效实现，这里是教学版本。

```python
import torch

def lift(features, depth_probs):
    # features:   H x W x C      图像特征
    # depth_probs: H x W x D     每个像素落在 D 个深度桶上的概率
    # 深度概率沿深度轴外扩，特征沿深度轴复制，逐元素相乘
    return depth_probs.unsqueeze(-1) * features.unsqueeze(-2)  # H x W x D x C
```

LSS 的官方代码在 nv-tlabs/lift-splat-shoot，论文里车辆分割的 IoU 是 32.07，仓库复现到 33.03，入口是 main.py，数据准备到训练评估的命令都写在 README 里。

LSS 显式预测深度，BEVFormer 走另一条路。它在 BEV 上铺一层网格状查询，每个查询点投影到各相机图像取对应特征，用可变形交叉注意力聚合，时序上把历史 BEV 特征按自车运动配准后再自注意力融合。纯相机配置在 nuScenes 测试集拿到 56.9% NDS，比当时最好方法高 9.0 个百分点，和激光雷达基线持平，速度估计和低能见度下的召回都有明显改善。这个数字的落点是，纯视觉方案在指标上够到了带激光雷达的水平，车企砍掉激光雷达的可行性多了一条证据。

![BEVFormer 总体架构](/images/sensor-fusion/bevformer-fig2-model.png)

*图来自 BEVFormer 论文 Figure 2。a 是编码器层的三个零件，网格状 BEV queries、时序自注意力、空间交叉注意力，b 里每个 BEV 查询只和它投影到的图像兴趣区交互，c 里时序自注意力把当前查询和历史 BEV 特征关联起来*

架构图里最该看的是 b。每个 BEV 查询点投到各相机平面上，命中哪些相机的哪些区域就从那里取特征，没命中的区域网络根本不看，计算量因此可控，这也是它能纯相机跑出 56.9% NDS 的一个原因。

相机流和点云流在 BEV 汇合，BEVFusion 把这条路推到量产尺度。两路各自提取 BEV 特征，融合模块在 BEV 栅格上做融合，任务头直接挂上。官方仓库在 nuScenes 验证集上的数字能看清融合的账。3D 检测 mAP 和 NDS，融合模型 68.52 和 71.38，纯相机基线只有 35.56 和 41.21，纯激光雷达 64.68 和 69.28。地图分割 mIoU，融合 62.95，相机 57.09，激光雷达 48.56。低配纯视觉方案在 BEV 检测上差一大截，融合把这条最弱的感知通道补了起来。激光雷达单独表现已经很好，融合的边际收益主要在语义任务和恶劣场景这类视觉短板的地方。

![BEVFusion 与点级融合的方法对比](/images/sensor-fusion/bevfusion-fig1-teaser.png)

*图来自 BEVFusion 论文 Figure 1。上排是点级融合，把相机特征投影到激光点上，下排是 BEVFusion，两路特征在 BEV 空间汇合*

这张图画的是设计思路分歧。点级融合把相机特征压进点云，语义密度在投影里丢掉一部分，BEVFusion 让相机和激光两路特征都到 BEV 平面汇合，相机的语义和激光的几何结构都保留下来。论文引言批评的正是上排的做法。

![BEVFusion 总体架构](/images/sensor-fusion/bevfusion-fig2-overview.png)

*图来自 BEVFusion 论文 Figure 2。多模态输入各自经过视图转换进入统一 BEV 空间，BEV 编码器融合特征，任务头输出不同感知结果*

架构图的信息流是直线。相机和激光两条流各自做视图转换进 BEV，融合发生在 BEV 栅格特征上，任务头从融合后的特征出结果，检测、分割、地图任务共用同一份融合特征。那组小红书长图里引用的 BEVFusion 框架图，就是这张图。

落地情况也写进了仓库。工程上最要紧的一步是优化视图转换里的 BEV pooling，论文把延迟降了超过 40 倍，对比图里能看到原因。BEVFusion 2023 年并入 MMDetection3D 的 projects，2024 年进了 NVIDIA DeepStream。NVIDIA 的 CUDA-BEVFusion 在 Jetson Orin 上做到 25 FPS，配合 INT8 加速。想读配置，仓库里有 `configs/nuscenes/det/transfusion/secfpn/camera+lidar/swint_v0p075/convfuser.yaml`，展开能看到相机编码器和激光编码器两路组织方式。想读实现，从 `mmdet3d/ops/bev_pool` 这个自定义算子看起。

![相机到 BEV 视图转换的耗时对比](/images/sensor-fusion/bevfusion-fig3-vtransform.png)

*图来自 BEVFusion 论文 Figure 3。a 标出视图转换是融合的瓶颈，原实现单场景要 2 秒，b 是优化的 BEV pooling，用区间归约和预计算栅格关联，c 和 d 是加速前后的耗时对比*

40 倍这个数字在图里看得见。原实现把视图转换拖到两秒级，单帧推理根本跑不动，优化后从两秒级降到几十毫秒级，BEV 特征融合这才配得上车载芯片的实时预算。

## 五、目标关联与状态估计的原理与代码

融合层把不同传感器报出的同一个障碍物归到一起，再持续估算它的位置、速度，这一步叫目标跟踪。跟踪里两个零件，数据关联和状态估计，算法都是半个多世纪前定的型。

数据关联解的是指派问题。把轨迹预测和本轮检测两两算代价，距离近、IoU 高的代价小，排成代价矩阵，再求全局代价最小的一一配对。匈牙利算法是解这个问题的经典方法，Kuhn 在 1955 年提出，Munkres 在 1957 年给出改进版本，现代实现能到 O(n^3) 量级，工程上直接调现成实现。SciPy 的 `linear_sum_assignment` 就是这个问题的求解器，文档写明实现是改进版 Jonker-Volgenant 算法（Crouse，IEEE TAES 2016），矩形矩阵也能处理，官方示例的用法和下面这段一致。

```python
import numpy as np
from scipy.optimize import linear_sum_assignment

# 三辆被跟踪车辆（行）与三个本轮检测（列）的代价矩阵
cost = np.array([[0.2, 0.9, 1.0],
                 [0.8, 0.3, 0.6],
                 [1.1, 0.7, 0.4]])

row_ind, col_ind = linear_sum_assignment(cost)
print(list(zip(row_ind, col_ind)))        # 指派结果
print(cost[row_ind, col_ind].sum())       # 最小总代价
```

先过滤再指派是通用做法。门控可以用马氏距离，也可以用 IoU 阈值。SORT 用的就是 IoU，卡尔曼预测框和检测框算 IoU，低于阈值的配对先排除，再跑匈牙利指派。SORT 论文在 ICIP 2016 发布，代码在 abewley/sort，更新率 260 赫兹，比同期跟踪器快二十多倍。它还提醒了一件重要的事，检测质量对跟踪结果影响巨大，换检测器最多带来 18.9% 的提升，关联算法再精巧也补不回来检测的洞。

状态估计的主件是卡尔曼滤波，Kalman 1960 年提出。它维护状态向量和协方差矩阵，协方差表示对状态的信任程度。预测步用运动模型把两者往前推，F 是状态转移矩阵，Q 是过程噪声。更新步把观测拉进来，H 把状态映射到观测空间，R 是观测噪声，卡尔曼增益按两边的协方差大小分配信任，观测越可靠，增益越偏向新观测。常量速度模型下五个式子三行代码，示意如下。

```python
import numpy as np

dt = 0.1
F = np.array([[1.0, dt], [0.0, 1.0]])    # 常量速度模型
H = np.array([[1.0, 0.0]])                # 只观测位置
Q = np.eye(2) * 0.1
R = np.array([[0.5]])

x = np.array([[0.0], [5.0]])              # 位置, 速度
P = np.eye(2)

def predict(x, P):
    x = F @ x
    P = F @ P @ F.T + Q
    return x, P

def update(x, P, z):
    y = z - H @ x                         # 新息
    S = H @ P @ H.T + R
    K = P @ H.T @ np.linalg.inv(S)        # 卡尔曼增益
    x = x + K @ y
    P = (np.eye(2) - K @ H) @ P
    return x, P
```

车辆运动模型带转角，状态转移是非线性的，工程里用扩展卡尔曼滤波，对模型在当前位置做一阶线性化，算法骨架还是同一套预测更新。上面两个代码块都是教学示意，不是某个仓库的原文，但公式和函数名跟标准教科书一致，跑起来能直接看到滤波效果。

## 六、完整系统的四层架构

把整车感知融合系统摊开看，是四层结构。传感器硬件层出原始数据，摄像头、激光雷达、毫米波雷达、IMU、GNSS、超声波都在这一层。预处理层做时间同步、空间标定、点云去畸变、图像预处理。多传感器融合层按方案执行前中后融合，输出统一环境模型，障碍物、车道线、可行驶区域都收拢在这里。上层把这些交给预测模块和决策规划模块，最终落到控制指令。

量产系统几乎不用单一融合。BEV 特征融合扛主感知的目标检测，毫米波雷达和超声波走后融合兜底，GNSS+IMU 做信号级融合定位，多路并行，单独一路出问题还有别的顶着。混合架构从硬件成本到安全余量做了取舍。

## 七、工程难点与技术趋势

融合的工程难点很具体。极端天气下传感器性能下降，大雨大雾强光夜晚，融合要动态调整各路置信权重。标定会漂移，车辆震动、碰撞把外参顶偏，需要在线标定实时修正，OpenCalib 里的 SensorX2car 就是给这种场景准备的。算力是硬约束，BEV 效果好，给车载芯片的压力也大，BEVFusion 那套优化正是往这个方向打。目标漏检误检没根除，不同传感器对异形障碍物的识别结果不一致，匹配容易失败。

趋势上几条线很清楚。BEV 特征融合继续往主流走，纯后融合的量产占比收缩。Transformer 大规模进入融合，跨模态注意力把图像、点云、雷达的特征对到一起。4D 毫米波雷达多了俯仰维度，更多参与特征级融合，补恶劣天气的短板。融合和定位在加深耦合，感知结果反过来辅助定位校正，不再单方向流动。端到端融合还在探索，原始多传感器数据直接进网络出驾驶行为，减少人工规则依赖，离大规模量产还远。

多传感器融合没有一套标准答案。后融合便宜可靠、精度受限，前融合信息完整、算力难扛，特征级融合居中，成了量产的落脚点。读完三层取舍和混合架构，遇到车企宣传自家融合方案时，先问一句融合在哪一层、标定怎么维护、失效时信任谁，这比记产品名更有用。
