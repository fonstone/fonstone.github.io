# 世界动作模型 WAM 的一周，原理拆解与最新论文观察

8 月 9 日到 11 日，arXiv cs.RO 三天收到 290 条提交。我把列表过了一遍，具身智能方向里 8 篇稿件围着同一个词转，WAM，World Action Model，世界动作模型。HarnessWAM、JEPA-WAM、SG-WAM 三个名字直接带 WAM，TempoWAM 藏在副标题里，WorldSimProbe 和 WA-SpecDec 分别查 WAM 的仿真与加速，ELWM 和 VANE 也在同一套框架里做文章。三天 8 篇，主题密集到这种程度，逐篇拆开看值得。

## WAM 从两条线汇来

世界模型只学环境动力学，输入状态和动作，输出未来的视频或潜状态，本身不决定机器人该干什么。VLA 反过来，输入观测和语言指令，直接输出动作，模型内部没有显式的环境演化。WAM 把两边合进一个模型，输入当前观测和任务指令，输出未来帧和一段动作 chunk。JEPA-WAM 的摘要先把两条路都批评了一遍，视频生成式 WAM 部署成本高，潜空间 WAM 又常把预测用的表示和动作生成用的表示分开。它的做法是在预训练的 V-JEPA 空间里建 WAM，用一个共享预测器耦合潜状态转移预测和连续动作生成。预测目标带空间结构，同时覆盖当前与未来，保留密集的 patch 级对应关系。

潜空间 WAM 有两个设计问题，预测什么目标，预测监督怎么和动作生成接上。JEPA-WAM 的论文把已有做法过了一遍，要么复用视频生成器的中间特征，要么把未来观测压成少量潜 token，预测监督和动作生成始终各走各的。它的答案是选 V-JEPA 2.1 空间，预测目标是转移本身而非绝对未来状态，再用共享预测器把转移预测和动作生成接到同一个骨干上，转移监督直接塑造动作骨干。推理时潜转移预测整个拆掉，只留动作生成。

合并没有把执行问题消掉。HarnessWAM 的摘要把它概括成 prediction-deliberation gap，预测与深思的缺口。WAM 的预测和动作生成都是有限时域的，复杂任务要跨阶段的全局规划，失败后要恢复，这两样它都不具备，执行结果更无人验证。

## HarnessWAM 给 WAM 外包执行层

VLM 驱动的 Task Manager 维护一个证据接地的场景信念和一个结构化任务图，场景里哪些事实被观测确认过、哪些还是猜测，都有记录。capability-conditioned executable-space projection 把开放词汇的语义计划压成原子技能序列，技能要满足任务依赖和本体状态约束，还要落在底层 WAM 的能力边界内。

执行时跑双时间尺度反馈环。轻量进度估计器高频检查动作是否在推进任务，Task Manager 只在关键里程碑被事件触发，综合当前观测、任务状态和交互历史决定继续推进还是补充观测，必要时发起局部恢复，计划也可以改。子任务失败后机器人恢复状态接着执行，先前积累的场景知识还在。

为什么不每步都让 Task Manager 决策，论文给了两条理由。每步调用 VLM 计算太贵，任务级决策还容易被瞬时的视觉波动带偏。快循环只做执行和进度估计，慢循环由语义事件触发。进度估计器的输出只是证据，从来不直接推进任务图。任务图只允许修改未执行的后缀，已执行部分保持历史不变，新观测只能改未来分支。

数字在 RoboMemArena 和 RoboCerebra 两个基准上。RoboMemArena 全任务成功率 59.6%，子任务 69.9%。RoboCerebra Ideal 全任务 23.7%。后面 23.7% 还会出现。

## TempoWAM 决定何时重规划

动作 chunk 的行使方式本身也有问题。WAM 每次推理生成一段 chunk，机器人先执行固定前缀再重规划。TempoWAM 的摘要指出固定执行窗口和实际执行动态失配，chunk 可靠性随任务阶段变化，困难阶段长窗口累积误差，简单阶段短窗口照样触发没必要的重规划。chunk 靠不靠得住要看执行结果，不看步数。

TempoWAM 是即插即用的执行方案，不碰 WAM 参数。Recurrent Progress Monitor 从当前观测、任务指令和剩余动作估计任务进度，执行历史也喂进去。Adaptive Execution Protocol 判断这段 chunk 是否真在推进任务，决定是否重规划。训练与部署的差距用一个任务相关校准因子补，因子在线自适应。

进度判断比的是速率不是总量。同一段 0.05 的进度，20 步的任务里算慢，200 步的任务里很正常。TempoWAM 把观测到的进度率对任务要求的进度率，用校准因子把监控器输出和真实执行状态对齐。校准分两级，离线阶段按演示片段用最小二乘拟合，部署后在线自适应，episode 内用 EMA 跟，episode 间看成功率，低于目标就多重规划，高于目标就省调用。没有演示数据的任务，离线校准缺失，靠两级在线适应慢慢补。

RPM 的规模论文写得很具体。GRU 核心加动作编码器，配两层 MLP 投影，共 2.27M 参数，占骨干 FastWAM 的 0.038%。监控器换掉整条执行策略，成本接近零。论文还做了对照，固定 12 步重规划虽然把调用次数翻倍，成功率反而下降，说明问题不在重规划频率，在触发时机。

![chunk 可靠性随任务阶段变化](/images/wam-survey/tempo-fig1.png)

*TempoWAM 论文 Figure 1，Click Bell 任务三种固定执行窗口下的动作 L2 误差，困难阶段长窗口累积误差，简单阶段短窗口产生多余调用。作者 Feng Ye 等，arXiv 2608.09492*

数字在 LIBERO、RoboTwin、真实机器人三个场地。真实机器人上简单任务 WAM 推理次数降 26.9% 且成功率不变，困难任务成功率涨 13.3 个百分点。推理次数直接对应控制周期和功耗，这是部署时最先看到的数字。

## ELWM 把物理写进潜状态

补了执行协议，模型自己的预测还得过物理关。ELWM 的论点直接，现有潜世界模型学不受约束的未来表示，物理被隐式吸收，形不成可复用的物理知识。它把潜状态显式结构化成携带能量和动量，靠耗散端口和控制端口保证转移严格因果。训练输入是 RGB-D 加惯性的多模态交互历史。

端口哈密顿量的结构论文给了完整定义。潜转移由反对称算子加耗散项组成，控制端口负责外部注入。潜能量的变化等于注入的功减去非负的耗散功率，两边都为零时能量守恒。动量有对应的性质，哈密顿量沿某个潜方向不变、该方向又没有外力和耗散，对应动量分量就守恒。加速度由控制端口解释，摩擦由耗散项解释。潜惯量用 Cholesky 分解参数化，能量非可分离时的更新用隐式中点离散梯度，数值上保持结构。

![ELWM 与 PC-NTF 系统总览](/images/wam-survey/elwm-fig1.png)

*ELWM 论文 Figure 1，动作-响应能力经 ELWM 预测未来运动和潜物理动力学，PC-NTF 结合神经时间场输出导航策略，完整执行过程产生避障、物理知情的导航。作者 Yapeng Liu 等，arXiv 2608.09876*

规划侧配套 PC-NTF，Physics-Conditioned Neural Time Fields，用 Eikonal 方程把 ELWM 集成进到达时间场，产出物理知情的导航策略。留出场景上的数字见表。两套基线的含义不同，NRMSE 一项比的是通用潜模型，其余四项比的是 Active Neural Time Fields。

PC-NTF 把规划责任拆成两半。Active Neural Time Fields 从场景几何学到达时间场，提供全局的下降方向和候选动作集。ELWM 对每个候选动作预测短时执行后果，PC-NTF 在到达时间场里查预测终点，把交互进度换算成物理遍历延迟，作为动作相关的阶段代价。几何部分不用为每种物理条件重训，物理修正按候选在线变化。

## WorldSimProbe 先给仿真器打分

WAM 被当作可扩展的预测仿真器用，前提是它真的像仿真器。WorldSimProbe 的摘要指出现有评估看重视觉质量和任务结果，不直接测仿真忠实度。论文形式化了一个 Observable Simulator Contract，可观测仿真器契约，两条要求，提供的动作必须引起对应的 agent 运动，环境响应必须锚定在实际发生的运动上。

围绕契约建了五个套件。局部控制敏感度和全局轨迹变化查动作到运动这一半，多源动作换控制源补盲区，交互接地和动力学查环境响应那一半。每个套件配专门评估器，沿动作到运动到环境响应这条链定位失败环节。六个开源 ACWM 在 RoboTwin、ManiSkill、LIBERO 上跑了 18000 多个实例。

动作实现本身是多维的，既要有对细粒度扰动的敏感度，也要扛得住不同控制源和执行风格。交互接地的失败模式论文审计得很具体。50 例失败全部是假阳性，模型生成了没有接触支撑的交互，论文管这叫接触幻觉。支持的接触没能触发环境响应的情况一例都没有。模型倾向多编交互，不倾向漏编。

结论是系统性的。控制变化下动作实现普遍退化，交互接地和动力学有结构化失败，基准信号与人工判断、下游结果一致。落到工程上，很多 WAM 生成的视频好看，动作和运动之间对不上，拿它当仿真器训策略，训出来的东西不可信。WorldSimProbe 把 18000 多次实例的失败分布公开发出来，这是这周最有价值的一件可核验材料。

## SG-WAM 让指令先接地

WAM 生成未来视频和动作主要靠视觉线索。SG-WAM 的摘要解释原因，现成文本编码器把指令独立于视觉观测嵌入，两者不交汇，生成的视频和语言指令语义错位。指令指左边那杯，模型生成的是右边那杯。

补法是一个 VLM 语义规划器。它预测两类语义预视，text-grounded 的预视接地指令、锁定正确目标物体，spatial-aware 的预视提供操作要用的场景几何。预视注入 WAM 当高层语义引导，视频生成和动作预测一起跟着指令走。实验在仿真和真实世界都做，DROID 的分布外指令对比里，RGB 直出的 WAM 视线分散，SG-WAM 集中在被操作的物体上，论文用 attention 图直接展示这个差异。

问题出在指令进入生成的方式。指令只通过现成文本编码器的嵌入进入模型，CLIP、T5 这类，嵌入计算独立于视觉观测，两者不交汇。SG-WAM 的规划器往图像和指令序列后面附加可学习 query token，单次前向解码出两组语义预视。文本接地的一组和 SigLIP2 的未来帧特征对齐，空间感知的一组和 Depth Anything 3 对齐，分别承担指认目标和提供几何两件事。预视作为高层蓝图条件化视频专家，预训练生成能力不动。

## 部署端两件事，速度与适应

VLA 自回归生成控制量，在线控制延迟被反复的前向推理压住。投机解码用并行验证草稿 token 块省时间，VLA 的变体还放松 token 级接受条件，动作 token 空间的小偏差常常对应相似的连续控制。WA-SpecDec 指出放松与场景无关，自由空间里无害的偏差到接触附近就是碰撞或抓取失败。它在 prefill 阶段注入世界模型派生的物理场景感知，草稿提议和目标验证共享世界感知的 prefill 状态，接受规则不动。三种现有宽松接受方案上都保住更高成功率，同等成功率下提速 1.5 倍，近接触失败平均降 18.6%。

为什么现成的视觉特征不够，论文给了分析。VLA 的视觉骨干做的是图文预训练，训练目标不保留控制关键变量，物体位姿怎么演化、夹爪离物体多远，这类量都不在目标里。WA-SpecDec 的 World-Aware Bias 模块从当前观测算出一个空间对齐偏置，加进视觉 patch 嵌入，不新增 token。训练时挂一个下一帧潜目标辅助，推理时拆掉，只吃当前帧。接受规则原样保留，动的是草稿和目标共享的 prefill 状态，让宽松接受在接触附近也不放行危险偏差。

![世界感知投机解码动机](/images/wam-survey/spec-fig1.png)

VANE 管在线适应。测试时训练给 VLA 提供从无标注部署流适应的轻量路径，但共享适应空间会混入不兼容的任务修正，在线更新又可能在后果未知前改变后续动作。VANE 把候选更新隔离在线上策略之外，用后续观测验证，拿到未来证据支持才提交，适应变得可选择、可回退。SimplerEnv WidowX 上平均成功率比对应 TTT 基线高 3.2 个百分点。Google Robot 上的增益随任务和形态变化，论文如实写了这一句，没有把单点成功说成全行业结论。

VANE 的流程是提议、验证、提交三步。事件检测器盯注意力分布，异常时在影子副本上做更新，线上策略不受影响。更新后的提示词库用后续观测配对验证，未来证据支持才原子提交，提示词库和优化器状态一起切换。消融显示，去掉未来验证只留事件门，成功率明显回落，验证环节不是可选的。
