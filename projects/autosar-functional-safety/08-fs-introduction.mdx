## 8.1 什么是功能安全

### 8.1.1 安全的定义

功能安全（Functional Safety）并非汽车行业独有，其根源可追溯到 IEC 61508（国际电工委员会制定的通用功能安全标准）。**功能安全的核心定义是：**

> 不存在由电气/电子系统功能性行为引起的不可接受风险。

换言之，当系统出现电气或电子故障时，它必须**安全地失效**（Fail Safe），而非导致危害。这与"质量"是不同的概念——质量关乎产品是否按设计工作，安全关乎产品故障时是否会伤害人。

### 8.1.2 为什么汽车需要功能安全

现代汽车已从纯机械系统演变为**软件定义的电子系统**。一辆高端汽车包含超过 100 个 ECUs、上亿行代码，控制着转向、制动、动力总成等安全关键功能：

| 系统 | 功能安全相关？ | 潜在危害 |
|---|---|---|
| 制动系统（ABS/ESP） | 是 | 制动失效 → 碰撞 |
| 转向系统（EPS） | 是 | 转向失控 → 碰撞 |
| 自动驾驶系统（ADAS/AD） | 是 | 感知/决策错误 → 碰撞 |
| 动力总成（发动机/电机控制） | 是 | 非预期加速 |
| 信息娱乐系统 | 否（QM） | 无直接人身伤害 |
| 车窗/车门控制 | 否（QM） | 夹伤（需评估） |

ISO 26262 正是在这一背景下诞生的——它是专门针对**道路车辆**的功能安全国际标准。

## 8.2 ISO 26262 标准体系

### 8.2.1 标准的演进

ISO 26262 第一版于 **2011 年**发布，覆盖车辆总重不超过 3.5 吨的乘用车。第二版于 **2018 年**发布，显著扩展了范围：

| 方面 | ISO 26262:2011（第一版） | ISO 26262:2018（第二版） |
|---|---|---|
| 适用范围 | 乘用车 ≤ 3.5 吨 | 所有道路车辆（含卡车、巴士、摩托车） |
| 半导体指南 | 无 | 新增 Part 11：半导体指南 |
| 软件工具信赖度 | 笼统 | 新增 Part 8：软件工具置信度 |
| ASIL 分解 | 已支持 | 更加明确 |
| 自动驾驶 | 未涉及 | 新增 Part 12：摩托 + SOTIF 参考 |

### 8.3.2 安全管理

安全的实现靠的不是一两个安全工程师，而是**组织级的安全文化**。Part 2 安全管理要求：

- **安全文化**：建立从管理层到开发者的安全意识，鼓励上报安全问题
- **安全计划**：项目级的安全计划，明确活动、交付物、责任人
- **安全案例**（Safety Case）：论证系统/产品为何达到功能安全的证据集合
- **确认措施**（Confirmation Measures）：由独立人员执行的评审、审核和评估
- **分布式开发**：确保供应商也遵守 ISO 26262 要求

## 8.4 ASIL 等级定义

### 8.4.1 ASIL 是什么

**ASIL**（Automotive Safety Integrity Level）是 ISO 26262 定义的风险等级体系，分为 **A、B、C、D** 四个等级，其中：

| 等级 | 风险程度 | 典型系统 |
|---|---|---|
| **QM** | 质量即可（无安全要求） | 信息娱乐、车窗控制 |
| **ASIL-A** | 最低安全完整性 | 大灯调节（某些场景） |
| **ASIL-B** | 中等安全完整性 | 雨刮控制、座椅位置记忆 |
| **ASIL-C** | 较高安全完整性 | 自适应巡航（部分场景） |
| **ASIL-D** | 最高安全完整性 | 电子制动、转向、安全气囊 |

**ASIL-D 是最高等级**——它要求最严格的过程和设计措施。ASIL-D 系统的平均每小时危险失效概率（PMHF）必须低于 **10⁻⁸ /h**（即 10 FIT，每十亿小时失效一次）。

### 8.4.2 ASIL 与 SIL 的关系

ISO 26262 脱胎于 IEC 61508。在 IEC 61508 中，SIL（Safety Integrity Level）分为 1-4 级。两者的对应关系为：

```
IEC 61508 SIL 1 → ISO 26262 ASIL-A
IEC 61508 SIL 2 → ISO 26262 ASIL-B/C（部分对应）
IEC 61508 SIL 3 → ISO 26262 ASIL-D
IEC 61508 SIL 4 → 汽车中无直接对应（汽车安全最高为 ASIL-D）
```

ASIL-D 的要求与 SIL 3 最为接近，但 ISO 26262 针对汽车应用增加了大量具体化的流程要求（比如针对半导体、软件工具等）。

## 8.5 HARA 简介

### 8.5.1 HARA 的定义

**HARA**（Hazard Analysis and Risk Assessment）是 ISO 26262 Part 3 的核心活动。它的目标是：

> 识别系统的危害（Hazards），评估每个危害的风险等级（ASIL），定义安全目标（Safety Goals）。

HARA 包含三个核心参数，下一章会详细展开，这里先给出概览：

### 8.5.2 危害、安全目标、功能安全要求

危害分析的结果是一组**安全目标**（Safety Goals）。每个安全目标可以进一步分解为：

```
安全目标（Safety Goal）
  └── 功能安全要求（Functional Safety Requirements, FSR）
        └── 技术安全要求（Technical Safety Requirements, TSR）
              └── 硬件安全要求（HSR）+ 软件安全要求（SSR）
```

**示例：**

| 层次 | 内容 | ASIL |
|---|---|---|
| 安全目标 | 车辆制动功能不得非预期失效导致碰撞 | ASIL-D |
| FSR | 制动踏板输入信号必须在 10ms 内被正确采集 | ASIL-D |
| TSR | 制动踏板传感器接口使用 2oo2 架构 + E2E 保护 | ASIL-D |
| HSR | 使用两个独立 ADC 通道冗余采集踏板位置 | ASIL-D |
| SSR | 软件实现 E2E Profile 1 保护通信路径 | ASIL-D(D) |

**安全目标的关键特征：**

1. **最高 ASIL 等级**：继承自 HARA 中对应危害的最高 ASIL
2. **可验证**：每个安全目标都应有明确的验收标准
3. **可追溯**：安全目标向下关联 FSR/TSR，向上关联 HARA
4. **非功能性**：安全目标是"不发生某种事故"，而非"实现某种功能"

### 8.5.3 HARA 输出文档

HARA 完成后应输出以下文档：

| 文档 | 内容 |
|---|---|
| HARA 报告 | 每项危害的 S/E/C 评级、ASIL 等级、运行场景 |
| HARA 追踪矩阵 | 危害 → 运行场景 → ASIL → 安全目标 的完整追溯 |
| 安全目标列表 | 所有安全目标的正式描述（ASIL 等级） |
| 功能安全概念 | 初步的顶层安全架构设计 |

### 8.6.2 ASIL 继承与分解

安全要求的 ASIL 等级沿层次向下继承：

- FSR 的 ASIL = 安全目标的 ASIL
- TSR 的 ASIL ≥ FSR 的 ASIL（可以更高或相同）
- 如果 TSR 通过**ASIL 分解**拆分为独立冗余的要求，每个子要求的 ASIL 可以降低

ASIL 分解将在第 10 章详细讨论。
