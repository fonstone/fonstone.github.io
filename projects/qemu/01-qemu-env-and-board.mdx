## 2. 搭建 QEMU 环境（ch0–ch1）

### 2.1 引言与依赖

项目旨在真正从 0 构建嵌入式 Linux 系统，剖析芯片从上电执行第一条指令到整个系统运行的完整过程。因此不使用真实板子，而是基于 QEMU 定制模拟开发板，且不使用 QEMU 提供的快速加载 ELF 文件方式，需要下载 `qemu-6.0.0` 源码自己编写硬件 IP 模拟代码。Ubuntu 18.04 需安装：

```bash
sudo apt install ninja-build pkg-config libglib2.0-dev libpixman-1-dev \
  libgtk-3-dev libcap-ng-dev libattr1-dev libsdl2-dev device-tree-compiler \
  bison flex gperf intltool mtd-utils libslirp-dev
```

### 2.2 编写简易编译脚本

解压 QEMU 源码后编写 `build.sh`，先在不修改源码的情况下编译：

![build.sh 目录结构](/images/qemu/ch1-0.png)

```bash
SHELL_FOLDER=$(cd "$(dirname "$0")";pwd)
cd qemu-6.0.0
if [ ! -d "$SHELL_FOLDER/output/qemu" ]; then
  ./configure --prefix=$SHELL_FOLDER/output/qemu \
    --target-list=riscv64-softmmu --enable-gtk --enable-virtfs --disable-gio
fi
make -j16
make install
cd ..
```

关键编译选项含义：`--target-list=riscv64-softmmu` 只编译 RISC-V 64 位系统级模拟器；`--enable-virtfs` 启用 9p 文件共享（后续 ch17 会用到）；`--enable-gtk` 启用图形窗口。编译成功后生成 `output/qemu/bin/qemu-system-riscv64`。

> 工程内对应位置：`build.sh`、`qemu-6.0.0/` 源码目录。本节 tag：`ch1`。

### 2.3 QEMU 板卡注册机制

QEMU 并非直接使用 GObject，而是自行实现了一套借鉴 GObject 思想的**QEMU 对象模型（QOM, QEMU Object Model）**。理解 QOM 是自定义板卡、自定义外设 IP 的核心。下面结合 `quard_star_tutorial` 仓库中 `qemu-8.0.0` 的真实源码，逐层拆解一块板卡是如何从 C 源码"长"成 `-M quard-star` 可选项的。

#### 2.3.1 QOM 三要素：TypeInfo / TypeImpl / ObjectClass

QOM 用三个结构体描述一个类型：

- **`TypeInfo`**（`include/qom/object.h:412`）：类型的**静态描述**，由板卡作者在源码中声明，告诉 QOM"我叫什么、父亲是谁、实例多大、初始化函数是谁"。
- **`TypeImpl`**（`qom/object.c:39`）：TypeInfo 注册后由 QOM 内部生成的**运行时类型表项**，持有 `class`（类对象指针）、`instance_size` 等已计算好的值。
- **`ObjectClass` / `MachineClass`**：类型的**类对象**，存放方法指针与类级配置（如 `mc->init`、`mc->max_cpus`），在 `class_init` 中被填充。

Quard-Star 板卡的静态描述定义在 `hw/riscv/quard_star.c:722`：

```c
// hw/riscv/quard_star.c
static const TypeInfo quard_star_machine_typeinfo = {
    .name       = TYPE_RISCV_QUARD_STAR_MACHINE,   // "quard-star-machine"
    .parent     = TYPE_MACHINE,                     // 父类型 "machine"
    .class_init = quard_star_machine_class_init,    // 填充 MachineClass
    .instance_init = quard_star_machine_instance_init, // 实例初始化(本板为空)
    .instance_size = sizeof(QuardStarState),        // 实例大小
};
```

其中 `TYPE_RISCV_QUARD_STAR_MACHINE` 由宏展开（`include/hw/riscv/quard_star.h:47`）：

```c
#define TYPE_RISCV_QUARD_STAR_MACHINE MACHINE_TYPE_NAME("quard-star")
// MACHINE_TYPE_NAME 给字符串追加 "-machine" 后缀：
// "quard-star" -> "quard-star-machine"
```

这个后缀是 QOM 做类型查找的约定——命令行 `-M quard-star` 会被拼成 `quard-star-machine` 去 `type_get_by_name()` 查表。`QuardStarState` 则是板卡的**实例结构体**（`include/hw/riscv/quard_star.h:52`），继承自 `MachineState`，内部持有所有外设的子对象（PLIC、flash、i2c、spi、usb、gpio、dma、can、lcdc……）：

```c
struct QuardStarState {
    MachineState parent;            // 父类实例（私有部分）
    CPUClusterState r_cluster;      // 管理 CPU 簇
    CPUClusterState c_cluster;      // 计算 CPU 簇
    RISCVHartArrayState r_cpus;     // 管理 CPU hart 数组
    RISCVHartArrayState c_cpus;     // 计算 CPU hart 数组
    DeviceState *plic;              // PLIC 中断控制器
    PFlashCFI01 *flash;             // pflash
    IMXI2CState i2c[3];             // 三组 I2C
    SiFiveSPIState spi[2];          // 两组 SPI
    FWCfgState *fw_cfg;             // fw_cfg
    USBDWC3 usb;                    // USB host
    // ... can, wdt, pwm, adc, timer, eth, lcdc, gpio, dma, sdio ...
};
```

#### 2.3.2 注册链路：从 type_init 到 type_register_static

板卡源码通过 `type_init` 宏完成注册。它的展开链路是理解"谁在何时调用谁"的关键（`include/qemu/module.h:56`）：

```c
// 展开前
type_init(quard_star_machine_init_register_types)

// 展开后（include/qemu/module.h:35-39）
static void __attribute__((constructor))    // GCC 构造器属性
do_qemu_init_quard_star_machine_init_register_types(void) {
    register_module_init(quard_star_machine_init_register_types,
                         MODULE_INIT_QOM);
}
```

`__attribute__((constructor))` 使该函数在 `main()` 之前由 C 运行时自动执行，把 `quard_star_machine_init_register_types` 登记到 `MODULE_INIT_QOM` 模块初始化链表上。QEMU 主流程在启动早期调用 `module_call_init(MODULE_INIT_QOM)`，遍历该链表，最终调用：

```c
// hw/riscv/quard_star.c:730
static void quard_star_machine_init_register_types(void) {
    type_register_static(&quard_star_machine_typeinfo);
}
```

`type_register_static`（`qom/object.c:826`）把 `TypeInfo` 拷贝到一个 `TypeImpl` 并插入全局类型表 `type_table`。此时只是"登记"，尚未创建任何类对象或实例。

#### 2.3.3 类初始化：class_init 填充 MachineClass

当 QEMU 第一次需要实例化某类型时，`type_initialize`（`qom/object.c:286`）被调用，它先递归初始化父类型，`memcpy` 继承父类的类对象，再调用本类型的 `class_init`。Quard-Star 的 `class_init` 填充了 `MachineClass` 的关键字段（`hw/riscv/quard_star.c:690`）：

```c
// hw/riscv/quard_star.c
static void quard_star_machine_class_init(ObjectClass *oc, void *data) {
    MachineClass *mc = MACHINE_CLASS(oc);   // 向下转型到 MachineClass

    mc->desc = "RISC-V Quard Star board";   // -M help 显示的描述
    mc->init = quard_star_machine_init;     // ★ 板卡初始化主入口
    mc->max_cpus = QUARD_STAR_MANAGEMENT_CPU_COUNT
                 + QUARD_STAR_COMPUTE_CPU_COUNT;   // 1 + 7 = 8
    mc->min_cpus = mc->max_cpus;            // 固定 8 核
    mc->default_cpus = mc->min_cpus;
    mc->default_cpu_type = TYPE_RISCV_CPU_BASE;    // 默认 CPU 型号
    mc->numa_mem_supported = true;

    // 注册命令行可选属性：-M quard-star,mask-rom-path=...
    object_class_property_add_str(oc, "mask-rom-path",
        quard_star_get_mask_rom_path,
        quard_star_set_mask_rom_path);
    // 注册 canbus 链接属性
    object_class_property_add_link(oc, "canbus", TYPE_CAN_BUS,
        offsetof(QuardStarState, canbus),
        quard_star_check_canbus_support, OBJ_PROP_LINK_STRONG);
}
```

注意 `mc->init = quard_star_machine_init` 是**最关键的一行**——它把"板卡上有哪些 CPU、多少内存、哪些外设"的具体建板逻辑挂到 MachineClass 的 `init` 函数指针上。这个函数指针**不会**在 `class_init` 时被调用，而是在后面 `machine_run_board_init` 时才执行。

#### 2.3.4 实例化：从命令行到 object_new_with_class

QEMU 主流程（`softmmu/vl.c`）处理 `-M quard-star` 的链路如下：

关键源码节点：

1. **`select_machine`**（`softmmu/vl.c:1577`）：调用 `object_class_get_list(TYPE_MACHINE, false)` 列出所有已注册的 machine 类型，用名字 `"quard-star"` 匹配到 `MachineClass`。
2. **`object_new_with_class`**（`qom/object.c:745`）：分配 `QuardStarState` 大小的内存，调用 `object_initialize_with_type`。
3. **`object_initialize_with_type`**（`qom/object.c:505`）：先 `type_initialize`（触发 `class_init`，填充 `MachineClass`），再 `object_init_with_type`（递归调用 `instance_init`，Quard-Star 此处为空）。
4. **`machine_run_board_init`**（`hw/core/machine.c:1307`）：做 RAM/CPU 合法性检查后，调用 `machine_class->init(machine)`（`machine.c:1409`）——这一行才真正进入 `quard_star_machine_init`。

#### 2.3.5 板卡初始化主函数：quard_star_machine_init

`quard_star_machine_init`（`hw/riscv/quard_star.c:635`）是板卡作者真正"搭积木"的地方，它把外设创建函数按依赖顺序串联起来：

```c
// hw/riscv/quard_star.c:635
static void quard_star_machine_init(MachineState *machine) {
    quard_star_cpu_create(machine);                 // 1. CPU 簇 + hart 数组
    quard_star_interrupt_controller_create(machine);// 2. CLINT + PLIC(先于串口)
    quard_star_memory_create(machine);              // 3. maskrom/sram/ddr + reset_vec
    quard_star_flash_create(machine);               // 4. pflash
    quard_star_system_control_create(machine);      // 5. syscon(复位/关机)
    quard_star_rtc_create(machine);                 // 6. RTC
    quard_star_serial_create(machine);              // 7. 三组串口(依赖 PLIC 中断)
    quard_star_i2c_create(machine);                 // 8. I2C + at24c + wm8750
    quard_star_spi_create(machine);                 // 9. SPI + nor flash
    quard_star_usb_host_create(machine);            // 10. USB host
    quard_star_usb_peripheral_create(machine);      // 11. USB device
    quard_star_gpio_create(machine);                // 12. GPIO
    quard_star_dma_create(machine);                 // 13. PDMA
    quard_star_sdio_create(machine);                // 14. SDIO
    quard_star_i2s_create(machine);                 // 15. I2S 音频
    quard_star_nand_create(machine);                // 16. NAND
    quard_star_can_create(machine);                 // 17. CAN
    quard_star_wdt_create(machine);                 // 18. 看门狗
    quard_star_pwm_create(machine);                 // 19. PWM
    quard_star_adc_create(machine);                 // 20. ADC
    quard_star_timer_create(machine);               // 21. 定时器
    quard_star_eth_create(machine);                 // 22. 以太网
    quard_star_lcdc_create(machine);                // 23. LCD 控制器
    quard_star_virtio_mmio_create(machine);         // 24. 8 组 virtio-mmio
    quard_star_fw_cfg_create(machine);              // 25. fw_cfg
}
```

顺序很重要：**中断控制器必须在串口之前创建**，因为串口通过 `qdev_get_gpio_in(DEVICE(s->plic), QUARD_STAR_UART0_IRQ)` 向 PLIC 申请中断引脚；**内存必须在 reset_vec 之前创建**，因为 `quard_star_setup_rom_reset_vec` 要把复位向量写入 maskrom 的 `MemoryRegion`。

#### 2.3.6 CPU 创建：双簇 + hart 数组

Quard-Star 把 8 个核分成两个 CPU 簇（`hw/riscv/quard_star.c:144`），这是 qemu-8.0.0 版本相对原教程 6.0.0 的重要演进：

```c
// hw/riscv/quard_star.c:144  计算簇: 7 核, hartid 0~6
object_initialize_child(OBJECT(machine), "c-cluster",
                        &s->c_cluster, TYPE_CPU_CLUSTER);
qdev_prop_set_uint32(DEVICE(&s->c_cluster), "cluster-id", 0);
object_initialize_child(OBJECT(&s->c_cluster), "c-cpus",
                        &s->c_cpus, TYPE_RISCV_HART_ARRAY);
object_property_set_str(OBJECT(&s->c_cpus), "cpu-type",
                        machine->cpu_type, &error_abort);
object_property_set_int(OBJECT(&s->c_cpus), "hartid-base", 0, &error_abort);
object_property_set_int(OBJECT(&s->c_cpus), "num-harts",
                        QUARD_STAR_COMPUTE_CPU_COUNT, &error_abort);  // 7
object_property_set_int(OBJECT(&s->c_cpus), "resetvec",
                        quard_star_memmap[QUARD_STAR_MROM].base, &error_abort);
sysbus_realize(SYS_BUS_DEVICE(&s->c_cpus), &error_fatal);

// 管理簇: 1 核, hartid 7 (对应 trusted-domain)
object_initialize_child(OBJECT(machine), "r-cluster",
                        &s->r_cluster, TYPE_CPU_CLUSTER);
qdev_prop_set_uint32(DEVICE(&s->r_cluster), "cluster-id", 1);
// ... r_cpus: hartid-base=7, num-harts=1
```

`RISCVHartArrayState`（`include/hw/riscv/riscv_hart.h:32`）是 QEMU 对一组同构 RISC-V hart 的封装，`sysbus_realize` 时内部会按 `num-harts` 个数实例化 `RISCVCPU`，并把 `resetvec` 设为各自的重定向地址。这里计算簇 7 核跑 Linux，管理簇 1 核（hartid=7）跑 trusted-domain，正是后面 ch7 OpenSBI Domain 划分的硬件基础。

#### 2.3.7 内存映射：MemoryRegion 体系

QEMU 用 `MemoryRegion` 描述一片 guest 物理内存区域。Quard-Star 的整张地址表是一个静态数组（`hw/riscv/quard_star.c:45`）：

```c
static const MemMapEntry quard_star_memmap[] = {
    [QUARD_STAR_MROM]   = { 0x00000000,   0x20000 },  // maskrom 128KB
    [QUARD_STAR_SRAM]   = { 0x00020000,   0xe0000 },  // sram 896KB
    [QUARD_STAR_SYSCTL] = { 0x00100000,    0x1000 },  // syscon
    [QUARD_STAR_CLINT]  = { 0x02000000,   0x10000 },
    [QUARD_STAR_PLIC]   = { 0x0c000000, 0x4000000 },
    [QUARD_STAR_UART0]  = { 0x10000000,    0x1000 },
    // ... UART1/2, RTC, I2C×3, SPI×2, GPIO, SDIO, I2S, CAN, PWM, ADC, TIMER, ETH, LCDC, WDT
    [QUARD_STAR_FLASH]  = { 0x20000000, 0x2000000 },  // pflash 32MB
    [QUARD_STAR_DRAM]   = { 0x80000000,       0x0 },  // DDR(大小由 -m 指定)
};
```

`quard_star_memory_create`（`hw/riscv/quard_star.c:212`）把三块核心内存注册到系统地址空间：

```c
// hw/riscv/quard_star.c:212
memory_region_init_ram(main_mem, NULL, "riscv_quard_star_board.dram",
                       machine->ram_size, &error_fatal);
memory_region_add_subregion(system_memory,
    quard_star_memmap[QUARD_STAR_DRAM].base, main_mem);    // 0x80000000

memory_region_init_ram(sram_mem, NULL, "riscv_quard_star_board.sram",
                       quard_star_memmap[QUARD_STAR_SRAM].size, &error_fatal);
memory_region_add_subregion(system_memory,
    quard_star_memmap[QUARD_STAR_SRAM].base, sram_mem);    // 0x20000

memory_region_init_rom(mask_rom, NULL, "riscv_quard_star_board.mrom",
                       quard_star_memmap[QUARD_STAR_MROM].size, &error_fatal);
memory_region_add_subregion(system_memory,
    quard_star_memmap[QUARD_STAR_MROM].base, mask_rom);    // 0x0

quard_star_setup_rom_reset_vec(machine, &s->r_cpus,
    quard_star_memmap[QUARD_STAR_FLASH].base,   // start_addr = pflash 基地址
    quard_star_memmap[QUARD_STAR_MROM].base,    // rom_base
    quard_star_memmap[QUARD_STAR_MROM].size,
    0x0, 0x0);
```

`memory_region_init_ram` 创建可读写 RAM，`memory_region_init_rom` 创建只读 ROM，`memory_region_add_subregion` 把它们挂到 `system_memory`（根地址空间）的指定偏移。`MemoryRegion` 之间形成树形拓扑，QEMU 的 softmmu 在 guest 访存时按树查找目标区域。

#### 2.3.8 复位向量：reset_vec 的 10 条指令

`quard_star_setup_rom_reset_vec`（`hw/riscv/quard_star.c:92`）往 maskrom 写入 10 条 RISC-V 指令，这是 CPU 上电后执行的第一段代码：

```c
// hw/riscv/quard_star.c:104
uint32_t reset_vec[10] = {
    0x00000297,                  /* 1:  auipc  t0, %pcrel_hi(fw_dyn) */
    0x02828613,                  /*     addi   a2, t0, %pcrel_lo(1b) */
    0xf1402573,                  /*     csrr   a0, mhartid  */   // 读 hart id -> a0
    0,
    0,
    0x00028067,                  /*     jr     t0 */             // 跳转到 start_addr
    start_addr,                  /* start: .dword */             // 即 pflash 0x20000000
    start_addr_hi32,
    fdt_load_addr,               /* fdt_laddr: .dword */         // 设备树地址(这里为0)
    0x00000000,
};
if (riscv_is_32bit(harts)) {
    reset_vec[3] = 0x0202a583;   /*     lw     a1, 32(t0) */     // 32位: 加载 fdt 到 a1
    reset_vec[4] = 0x0182a283;   /*     lw     t0, 24(t0) */     // 32位: 加载跳转地址
} else {
    reset_vec[3] = 0x0202b583;   /*     ld     a1, 32(t0) */     // 64位: 加载 fdt 到 a1
    reset_vec[4] = 0x0182b283;   /*     ld     t0, 24(t0) */     // 64位: 加载跳转地址
}
```

这段代码的语义等价于：

```asm
1:  auipc  t0, %pcrel_hi(fw_dyn)   ; t0 = 当前PC
    addi   a2, t0, %pcrel_lo(1b)
    csrr   a0, mhartid             ; a0 = hart id (RISC-V ABI: 参数0)
    ld     a1, 32(t0)              ; a1 = fdt_load_addr (RISC-V ABI: 参数1)
    ld     t0, 24(t0)              ; t0 = start_addr
    jr     t0                      ; 跳转到 pflash 零地址(BL1)
```

遵循 RISC-V SBI 规范：`a0=mhartid`、`a1=fdt`，相当于一次"函数调用"把 hart id 和设备树传给下级 loader。`mask_rom_path` 属性非空时改为加载用户提供的 maskrom 镜像（`quard_star.c:131`），这是 qemu-8.0.0 版本新增的可定制复位向量入口。

#### 2.3.9 外设创建的两种范式

Quard-Star 源码展示了 QEMU 创建外设的两种典型范式：

**范式一：sysbus_create_simple（一步到位）**

适用于简单的 MMIO + 单中断外设，如 RTC、virtio-mmio：

```c
// hw/riscv/quard_star.c:267  RTC
sysbus_create_simple("goldfish_rtc",
    quard_star_memmap[QUARD_STAR_RTC].base,
    qdev_get_gpio_in(DEVICE(s->plic), QUARD_STAR_RTC_IRQ));

// hw/riscv/quard_star.c:597  virtio-mmio x8
sysbus_create_simple("virtio-mmio",
    quard_star_memmap[QUARD_STAR_VIRTIO0].base,
    qdev_get_gpio_in(DEVICE(s->plic), QUARD_STAR_VIRTIO0_IRQ));
```

`sysbus_create_simple` 内部完成 `qdev_new` + `sysbus_realize` + `sysbus_mmio_map` + `sysbus_connect_irq` 四步。

**范式二：object_initialize_child + 属性设置 + sysbus_realize（分步精细）**

适用于需要设属性、挂子设备的外设，如 I2C、SPI、USB：

```c
// hw/riscv/quard_star.c:309  I2C0
object_initialize_child(OBJECT(machine), "i2c0", &s->i2c[0], TYPE_IMX_I2C);
sysbus_realize(SYS_BUS_DEVICE(&s->i2c[0]), &error_abort);
sysbus_mmio_map(SYS_BUS_DEVICE(&s->i2c[0]), 0,
                quard_star_memmap[QUARD_STAR_I2C0].base);
sysbus_connect_irq(SYS_BUS_DEVICE(&s->i2c[0]), 0,
    qdev_get_gpio_in(DEVICE(s->plic), QUARD_STAR_I2C0_IRQ));

// 在 I2C 总线上挂从设备
s->at24c_dev = i2c_slave_new("at24c-eeprom", 0x50);
qdev_prop_set_uint32(DEVICE(s->at24c_dev), "rom-size", 8*1024);
i2c_slave_realize_and_unref(s->at24c_dev, s->i2c[0].bus, &error_abort);
```

`object_initialize_child` 把子对象纳入父对象的 ownership（父销毁时自动销毁子），`qdev_get_gpio_in` 从 PLIC 申请一根中断输入引脚——这是 QOM 设备模型的"信号连接"机制。

#### 2.3.10 自定义外设 IP：以 quard_star_syscon 为例

Quard-Star 还示范了如何自己写一个外设 IP。`hw/misc/quard_star_syscon.c` 是一个最小化的 syscon 设备，完成复位/关机控制。它同样遵循 QOM 三段式：

```c
// hw/misc/quard_star_syscon.c:133  实例初始化: 注册 MMIO
static void quard_star_syscon_init(Object *obj) {
    QuardStarSysconState *s = QUARD_STAR_SYSCON(obj);
    memory_region_init_io(&s->mmio, obj, &quard_star_syscon_ops, s,
                          TYPE_QUARD_STAR_SYSCON, 0x1000);
    sysbus_init_mmio(SYS_BUS_DEVICE(obj), &s->mmio);
}

// hw/misc/quard_star_syscon.c:142  类初始化: 注册 realize 与属性
static void quard_star_syscon_class_init(ObjectClass *klass, void *data) {
    DeviceClass *dc = DEVICE_CLASS(klass);
    dc->realize = quard_star_syscon_realize;
    device_class_set_props(dc, quard_star_syscon_properties);
}

// hw/misc/quard_star_syscon.c:151  类型描述 + 注册
static const TypeInfo quard_star_syscon_info = {
    .name          = TYPE_QUARD_STAR_SYSCON,
    .parent        = TYPE_SYS_BUS_DEVICE,    // 继承 SysBusDevice
    .instance_size = sizeof(QuardStarSysconState),
    .instance_init = quard_star_syscon_init,
    .class_init    = quard_star_syscon_class_init,
};
type_init(quard_star_syscon_register_types)  // 同样用 type_init 登记
```

`memory_region_init_io` 把 `quard_star_syscon_ops`（read/write 回调）绑到一片 MMIO 区域，guest 读写该地址时 QEMU 回调 `quard_star_syscon_read/write`。写 `0x7777` 触发 `qemu_system_reset_request`（复位），写 `0x5555` 触发 `exit(0)`（关机）——这就是后面 ch18 syscon 复位/关机功能的实现原理。

### 3.2 源码解析

**注册板卡到系统**：通过 QEMU 的类型系统注册一个名为 `quard-star` 的 machine。

**构造虚拟 CPU**：QEMU 中各 CPU 核心以线程模拟，通过 `object_initialize_child` 创建 `TYPE_RISCV_HART_ARRAY` 实例：

```c
// qemu-6.0.0/hw/riscv/quard_star.h
static const MemMapEntry virt_memmap[] = {

    [QUARD_STAR_UART0] = { 0x10000000,         0x100 },
    [QUARD_STAR_DRAM]  = { 0x80000000,           0x0 },
};
```

```c
// 创建并映射内存区域
memory_region_init_ram(main_mem, NULL, "riscv_quard_star_board.dram",
                       machine->ram_size, &error_fatal);
memory_region_add_subregion(system_memory,
    memmap[QUARD_STAR_DRAM].base, main_mem);

memory_region_init_ram(sram_mem, NULL, "riscv_quard_star_board.sram",
                       memmap[QUARD_STAR_SRAM].size, &error_fatal);
memory_region_add_subregion(system_memory,
    memmap[QUARD_STAR_SRAM].base, sram_mem);

memory_region_init_rom(mask_rom, NULL, "riscv_quard_star_board.mrom",
                       memmap[QUARD_STAR_MROM].size, &error_fatal);
memory_region_add_subregion(system_memory,
    memmap[QUARD_STAR_MROM].base, mask_rom);
```

**加载 maskrom 复位向量**：`quard_star_setup_rom_reset_vec` 将一段汇编编译生成的二进制指令写入 mrom，功能是把 hart id 加载到 `a0`、设备树基地址加载到 `a1`，然后跳转到下级代码运行地址。这遵循 RISC-V ABI 规范（a0/a1 为参数 0/1），本质相当于一次函数调用。

```c

    0,

    0x00028067,                  /*     jr     t0 */

    fdt_load_addr,               /* fdt_laddr: .dword */
```

### 4.2 添加串口支持

真实板卡初期调试串口打印是神器。添加三个串口基地址（为后续多权限域分别输出做准备）：

```c

{
```

### 4.3 添加中断控制器

RISC-V 标准中断控制器分两部分：**CLINT**（Core Local Interrupt，每核私有）和 **PLIC**（Platform-Level Interrupt Controller，所有核共用的外部中断控制器）。

```c
{
    [QUARD_STAR_CLINT] = {  0x2000000,       0x10000 },
    [QUARD_STAR_PLIC]  = {  0xc000000, QUARD_STAR_PLIC_SIZE(QUARD_STAR_CPUS_MAX * 2) },
}
```

分别用 `sifive_clint_create` 和 `sifive_plic_create` 创建，并根据 SMP 个数为每个 core 创建对应资源。

### 4.4 添加 pflash 支持

pflash 是并行 flash，目前真实器件少见，常见的是 qspi nor flash 作低阶固件载体（支持 XIP 运行基本等同 pflash）。这里用 QEMU 的 pflash 作为早期固件载体，基地址 `0x20000000`，大小 32M。

```c
static PFlashCFI01 *quard_star_flash_create(RISCVVirtState *s,
                                       const char *name,
                                       const char *alias_prop_name) {
    DeviceState *dev = qdev_new(TYPE_PFLASH_CFI01);
    qdev_prop_set_uint64(dev, "sector-length", QUARD_STAR_FLASH_SECTOR_SIZE);
    qdev_prop_set_uint8(dev, "width", 4);
    qdev_prop_set_uint8(dev, "device-width", 2);
    qdev_prop_set_uint16(dev, "id0", 0x89);
    qdev_prop_set_uint16(dev, "id1", 0x18);
    object_property_add_child(OBJECT(s), name, OBJECT(dev));
    object_property_add_alias(OBJECT(s), alias_prop_name,
                              OBJECT(dev), "drive");
    return PFLASH_CFI01(dev);
}
```

通过 `pflash_cfi01_legacy_drive` 关联到 `-drive if=pflash,bus=0,unit=0,...` 参数。最后把 `quard_star_setup_rom_reset_vec` 中 bootrom 的跳转地址改为 pflash 上的地址。本节 tag：`ch3`。

### 5.2 编写 lowlevelboot 代码

新建 `lowlevelboot/` 目录，创建 `startup.s` 与 `boot.lds`。`startup.s` 位于 pflash 零地址（物理 `0x20000000`），即 maskrom 跳转进来的入口。整个固件编译流程如下：

<MermaidDiagram chart={`flowchart LR
    A["startup.s"] -->|"gcc -x assembler-with-cpp -c"| B["startup.o"]
    B -->|"gcc -nostartfiles -T boot.lds"| C["lowlevel_fw.elf"]
    C -->|"objcopy -O binary"| D["lowlevel_fw.bin"]
    D -->|"dd 打包到 fw.bin 零偏移"| E["fw.bin (32MB)"]

```asm
// lowlevelboot/startup.s
    .section .text
    .globl _start
    .type _start,@function
_start:
    csrr    a0, mhartid        # 读取内核 hart id 到 a0
    li      t0, 0x0
    beq     a0, t0, _core0     # 仅 core0 继续，其余 core 循环等待
_loop:
    j       _loop
_core0:
    li      t0, 0x100
    slli    t0, t0, 20         # t0 = 0x10000000 (uart0 发送寄存器)
    li      t1, 'H'
    sb      t1, 0(t0)          # 写入 uart0 data 寄存器输出 'H'
    li      t1, 'e'
    sb      t1, 0(t0)
    li      t1, 'l'
    sb      t1, 0(t0)
    li      t1, 'l'
    sb      t1, 0(t0)
    li      t1, 'o'
    sb      t1, 0(t0)
    # ... 依次输出 "Hello Quard Star board!"
    j       _loop
    .end
```

`boot.lds` 链接脚本将 `.text` 段定位于 flash 内存域 `ORIGIN = 0x20000000`：

```
// lowlevelboot/boot.lds
OUTPUT_ARCH( "riscv" )
ENTRY( _start )
MEMORY { flash (rxai!w) : ORIGIN = 0x20000000, LENGTH = 512k }
SECTIONS { .text { KEEP(*(.text)) } >flash }
```

至此完成了第一阶段：从零搭建 QEMU 编译环境、注册自定义 Quard-Star 板卡、添加串口/中断/pflash 三类基础外设，并用一段裸机汇编固件验证了串口通路。这一阶段的关键在于理解 QEMU 的板卡注册机制（TypeInfo/class_init/instance_init）、内存区域（MemoryRegion）映射、以及 RISC-V 上电后的寄存器约定（a0=mhartid, a1=fdt）。
