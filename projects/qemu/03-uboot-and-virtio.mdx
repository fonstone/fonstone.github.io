## 1. U-Boot 介绍与编译（ch8）

### 1.1 U-Boot 的角色

U-Boot 在 ARM 嵌入式开发中常作为二级甚至一级 loader 引导 Linux 内核。早期仅是从非易失性存储加载内核引导，如今还拥有网络功能、固件升级等能力。本教程将 U-Boot 移植进来保证流程完整性。

U-Boot 的 **spl 功能**将其分为 bl0（XIP flash 内运行，少量内存，初始化 ddr 后加载 bl1）和 bl1（ddr 内运行）。本教程不需要 spl，因为已有前级 OpenSBI 负责 BL0 阶段功能。

### 1.2 编译

使用 `u-boot-2021.07` 版本（该版本刚提交了 fw_cfg mmio 驱动，免去了自行实现）：

```bash
cd u-boot-2021.07
make CROSS_COMPILE=$CROSS_PREFIX- qemu-riscv64_smode_defconfig
make CROSS_COMPILE=$CROSS_PREFIX- -j16
cp u-boot $SHELL_FOLDER/output/uboot/u-boot.elf
cp u-boot.bin $SHELL_FOLDER/output/uboot/u-boot.bin
```

U-Boot 同样需要设备树，重新编写 `quard_star_uboot.dts`（删除 opensbi 的 domain 相关内容，增加 `bootargs = "console=ttyS0"`），并修改 opensbi dts 中 udomain 启动地址为 `0x80200000`。

固件打包布局：

```bash
dd of=fw.bin ... seek=0   if=lowlevel_fw.bin      # BL1
dd of=fw.bin ... seek=512 if=quard_star_sbi.dtb    # OpenSBI 设备树
dd of=fw.bin ... seek=1K  if=quard_star_uboot.dtb  # U-Boot 设备树
dd of=fw.bin ... seek=2K  if=fw_jump.bin           # OpenSBI
dd of=fw.bin ... seek=4K  if=trusted_fw.bin        # 安全域固件
dd of=fw.bin ... seek=8K  if=u-boot.bin            # U-Boot
```

### 2.2 添加 platform 到 U-Boot

创建 `board/emulation/qemu-quard-star/` 目录，添加 `Kconfig`、`qemu-quard-star.c`、`Makefile`：

```c
// u-boot-2021.07/board/emulation/qemu-quard-star/Kconfig
if TARGET_QEMU_QUARD_STAR
config SYS_BOARD
    default "qemu-quard-star"
config SYS_VENDOR
    default "emulation"
config SYS_CONFIG_NAME
    default "qemu-quard-star"
config SYS_TEXT_BASE
    default 0xB0200000
config BOARD_SPECIFIC_OPTIONS
    def_bool y
    select GENERIC_RISCV
    select CMD_QFW
    select QFW_MMIO
    imply VIRTIO_MMIO
    imply VIRTIO_NET
    imply VIRTIO_BLK
    imply SYS_NS16550
    imply SYSRESET_SYSCON
endif
```

```c
// u-boot-2021.07/board/emulation/qemu-quard-star/qemu-quard-star.c
phys_size_t get_effective_memsize(void) {
    return 32*1024*1024;  // 限制 uboot reloc top 地址为 32MB
}
```

```c
// u-boot-2021.07/include/configs/qemu-quard-star.h
#define CONFIG_SYS_SDRAM_BASE     0x80000000
#define CONFIG_SYS_LOAD_ADDR      (CONFIG_SYS_SDRAM_BASE + SZ_2M)
#define CONFIG_SYS_MALLOC_LEN     SZ_8M
#define BOOT_TARGET_DEVICES(func) func(QEMU, qemu, na) func(VIRTIO, virtio, 0)
#define CONFIG_EXTRA_ENV_SETTINGS \
  "kernel_addr_r=0x84000000\0" \
  "fdt_addr_r=0x88000000\0" \
  "scriptaddr=0x88100000\0" \
  "ramdisk_addr_r=0x88300000\0" \
  BOOTENV
```

## 3. virtio 与 fw_cfg（ch10）

### 3.1 virtio

virtio 是 I/O 半虚拟化解决方案。直接调用 QEMU API 例化 virtio-mmio 设备：

```c
// qemu-6.0.0/hw/riscv/quard_star.c
[QUARD_STAR_VIRTIO] = { 0x10100000, 0x1000 }, // 八组连续

for (i = 0; i < QUARD_STAR_COUNT; i++) {
    sysbus_create_simple("virtio-mmio",
        memmap[QUARD_STAR_VIRTIO].base + i * memmap[QUARD_STAR_VIRTIO].size,
        qdev_get_gpio_in(DEVICE(virtio_plic), QUARD_STAR_IRQ + i));
}
```

设备树添加 8 个 `virtio_mmio@1010X000` 节点：

```dts
virtio_mmio@10100000 {
    interrupts = <0x1>;
    interrupt-parent = <0x11>;
    reg = <0x0 0x10100000 0x0 0x1000>;
    compatible = "virtio,mmio";
};
// ... 10101000 ~ 10107000 ...
```

### 3.2 fw_cfg

fw_cfg 是 QEMU 提供的传递参数给内核的虚拟 IP：

```c
[QUARD_STAR_FW_CFG] = { 0x10108000, 0x18 },
s->fw_cfg = fw_cfg_init_mem_wide(memmap[QUARD_STAR_FW_CFG].base + 8,
                                 memmap[QUARD_STAR_FW_CFG].base, 8,
                                 memmap[QUARD_STAR_FW_CFG].base + 16,
                                 &address_space_memory);
fw_cfg_add_i16(s->fw_cfg, FW_CFG_NB_CPUS, (uint16_t)machine->smp.cpus);
```

设备树添加 `fw-cfg@10108000 { compatible = "qemu,fw-cfg-mmio"; }`。U-Boot 需打开 `CMD_QFW` 功能。

### 3.3 测试使用

```bash
$SHELL_FOLDER/output/qemu/bin/qemu-system-riscv64 \
  -M quard-star -m 1G -smp 8 \
  -drive if=pflash,bus=0,unit=0,format=raw,file=fw.bin \
  -drive file=rootfs.img,format=raw,id=hd0 \
  -device virtio-blk-device,drive=hd0 \
  -fw_cfg name="opt/qemu_cmdline",string="qemu_vc=$DEFAULT_V" \
  -global virtio-mmio.force-legacy=false \
  --serial vc:$DEFAULT_VC --monitor vc:$DEFAULT_VC --parallel none
```

## 4. 阶段小结

本篇把 U-Boot 跑了起来并完成系统级内存重规划，同时为内核启动备齐了 virtio 块设备与 fw_cfg 参数通道。关键要点：

- **U-Boot 两阶段**：`board_init_f` 早期初始化 → `board_init_r` 驱动初始化 → main_loop
- **内存规划思维**：真实 IC 开发需早期统筹各级 boot 与固件升级的内存布局
- **virtio 半虚拟化**：QEMU 中一行 `sysbus_create_simple` 即可例化
- **fw_cfg 传参**：QEMU → guest 的轻量参数通道
