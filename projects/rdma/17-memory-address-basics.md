# 内存地址基础知识

> 注: 知乎原文403不可达，本文基于内存管理基础及RDMA地址映射机制整理

---

RDMA技术的核心优势之一就是"远程直接内存访问"。要理解RDMA是如何实现这一点的，首先需要理解计算机系统中的内存地址体系。本文从内存地址的基础概念出发，逐步深入RDMA领域特有的地址相关概念。

## 虚拟地址与物理地址

### 物理地址（Physical Address, PA）

物理地址是内存硬件级别的地址。CPU通过内存总线访问内存时，使用的是物理地址。物理地址对应着内存硬件中的具体存储单元。

在现代计算机中，物理内存被划分为固定大小的页（Page），通常为4KB。操作系统以页为单位管理物理内存。

### 虚拟地址（Virtual Address, VA）

虚拟地址是应用程序所看到的地址。每个进程拥有独立的虚拟地址空间，在32位系统中为4GB，在64位系统中理论上可达2^64字节。

应用程序操作的是虚拟地址，而硬件实际访问的是物理地址。从虚拟地址到物理地址的转换由CPU中的MMU（Memory Management Unit）负责。

```
应用程序视角:        ┌────────────────────────────┐
                    │    虚拟地址空间 (VA)        │
                    │  ┌──────┐                  │
                    │  │ 堆   │  0x7f00...        │
                    │  ├──────┤                  │
                    │  │ 栈   │  0x7fff...        │
                    │  ├──────┤                  │
                    │  │ 代码 │  0x4000...        │
                    │  └──────┘                  │
                    └───────────┬────────────────┘
                                │
                        MMU地址转换
                                │
硬件视角:            ┌──────────▼─────────────────┐
                    │    物理地址空间 (PA)         │
                    │  ┌──────┬──────┬──────┐     │
                    │  │ 页框0│ 页框1│ 页框2│ ... │
                    │  └──────┴──────┴──────┘     │
                    └────────────────────────────┘
```

### MMU与页表

MMU（Memory Management Unit）是CPU中负责地址转换的硬件单元。它通过查询页表（Page Table）来完成VA到PA的转换。

页表是操作系统维护的一种数据结构，记录了虚拟页号（VPN）到物理页框号（PFN）的映射关系。

```
虚拟地址:
┌──────────────┬──────────────┐
│   虚拟页号   │   页内偏移   │
│   (VPN)      │   (Offset)   │
└──────┬───────┴──────┬───────┘
       │              │
       ▼              │
  ┌─────────┐         │
  │  页表   │         │
  │ VPN→PFN │         │
  └────┬────┘         │
       │              │
       ▼              ▼
┌──────────────┬──────────────┐
│   物理页框   │   页内偏移   │
│   (PFN)      │   (Offset)   │
└──────────────┴──────────────┘
物理地址
```

### 多级页表

由于64位系统的地址空间巨大，使用单级页表会消耗过多的内存。现代CPU通常使用多级页表来压缩页表的存储空间，以x86-64架构为例，使用4级页表：

```
VA Bit 63-48     Bit 47-39    Bit 38-30    Bit 29-21    Bit 20-12    Bit 11-0
┌───────────┬──────────────┬──────────────┬──────────────┬────────────┬──────────┐
│  符号扩展  │   PML4索引   │   PDPT索引   │    PD索引    │    PT索引   │  偏移    │
└───────────┴──────┬───────┴──────┬───────┴──────┬───────┴─────┬──────┴──────────┘
                   │              │              │            │
                   ▼              ▼              ▼            ▼
               PML4表          PDPT表          PD表          PT表       物理页
```

每一级页表负责将虚拟地址的一部分转换为下一级页表的物理地址，最终在最后一级找到物理页框号。

## TLB（Translation Lookaside Buffer）

TLB是CPU内部的一个高速缓存，用于缓存最近使用的VA→PA映射关系。由于程序通常表现出时间局部性和空间局部性，TLB可以显著提高地址转换的速度。

如果没有TLB，每次内存访问都需要遍历多级页表，这会导致数次甚至十数次的内存访问开销。

```
CPU核心
┌─────────────────────────┐
│  MMU                    │
│  ┌─────┐    ┌──────┐   │
│  │ TLB │◄──►│ 页表 │   │
│  │(快) │    │(慢)  │   │
│  └──┬──┘    └──────┘   │
└─────┼───────────────────┘
      │
      ▼
  物理内存
```

## RDMA中的地址映射

### 传统网络的数据拷贝

在传统的网络通信（如Socket）中，数据需要经过多次拷贝：

```
发送端:  APP缓冲区(VA) → 内核Socket缓冲区(VA) → 网卡DMA(PA)
接收端:  网卡DMA(PA) → 内核Socket缓冲区(VA) → APP缓冲区(VA)
```

每一次拷贝都涉及VA↔PA的转换和CPU参与的数据搬移，这是传统网络延迟的主要来源。

### RDMA的内存注册

RDMA为了实现零拷贝，需要在通信开始前将用户缓冲区注册为Memory Region（MR）。注册MR的过程中主要完成两件事：

1. **锁定内存（Pin Memory）**：防止操作系统将注册的内存页换出到磁盘，保证VA→PA映射关系不变
2. **建立地址映射表**：将VA→PA的映射关系记录到内存中，供RDMA网卡查询

```
注册MR之前：
┌──────┐     ┌──────┐     ┌──────┐
│  VA  │ ──▶ │  PA  │     │ 磁盘 │  (页面可能被换出)
└──────┘     └──────┘     └──────┘

注册MR之后（锁定）：
┌──────┐     ┌──────┐
│  VA  │ ──▶ │  PA  │  (页面固定在物理内存中)
└──────┘     └──────┘
                │
                ▼
         ┌──────────────┐
         │  HCA映射表    │  (MTT - Memory Translation Table)
         │ VA1 → PA1    │
         │ VA2 → PA2    │
         │ VA3 → PA3    │
         └──────────────┘
```

### MTT（Memory Translation Table）

MTT是RDMA网卡维护的地址映射表。当HCA收到一个WQE（Work Queue Element）时，WQE中包含的是虚拟地址。HCA需要查询MTT将其转换为物理地址，然后通过DMA访问内存。

MTT可以存储在主机内存中（系统内存），也可以缓存在HCA的SRAM中以提高访问速度。

```
WQE中的地址信息：
┌─────────────────────────────────┐
│ 源VA:      0x7f1234567800      │
│ 目的VA:    0x7f9876543200      │
│ 长度:      4096 bytes          │
│ L_Key/R_Key: 0xabcd1234        │
└────────────┬────────────────────┘
             │
             ▼
      ┌──────────────┐
      │  MTT查询     │
      │ VA → PA转换  │
      └──────┬───────┘
             │
             ▼
      ┌──────────────┐
      │  DMA操作     │
      │ 内存读写     │
      └──────────────┘
```

### MPT（Memory Protection Table）

与MTT配套的是MPT（Memory Protection Table），用于存储内存区域的访问权限信息。MPT记录了每个MR的L_Key和R_Key、以及对应的访问权限（如本地读/写、远端读/写、原子操作等）。

当HCA收到一个内存访问请求时，会同时查询：
- **MTT**：确认虚拟地址对应的物理地址
- **MPT**：确认请求者是否有权访问该内存区域

## IOMMU与RDMA地址映射

### IOMMU简介

IOMMU（Input/Output Memory Management Unit）是连接DMA设备和内存之间的地址转换单元。类似于CPU的MMU，IOMMU负责将设备DMA地址转换为物理地址。

在没有IOMMU的情况下，DMA设备直接使用物理地址访问内存。有了IOMMU，设备使用设备虚拟地址（DMA地址），由IOMMU转换为物理地址。

```
不使用IOMMU:
  HCA ──(物理地址)──▶ 内存

使用IOMMU:
  HCA ──(I/O虚拟地址)──▶ IOMMU ──(物理地址)──▶ 内存
```

### IOMMU在RDMA中的作用

在虚拟化环境中，IOMMU的作用尤为关键。宿主机可以将物理内存分配给虚拟机，并通过IOMMU建立虚拟机看到的设备地址到真实物理地址的映射。这样虚拟机中的RDMA应用可以直接操作HCA，实现高效的IO虚拟化。

## GID和LID

### LID（Local Identifier）

LID是InfiniBand子网中用于标识端口的16位地址。在InfiniBand子网内部，数据包的路由主要依赖LID。LID由子网管理器（SM，Subnet Manager）分配，仅在子网内部有效。

LID的范围：
- 0x0000：保留
- 0x0001 - 0xBFFF：可分配给端口的LID
- 0xC000 - 0xFFFE：用于组播
- 0xFFFF：保留

### GID（Global Identifier）

GID是128位的全局标识符，用于在InfiniBand子网之间或RoCE网络中进行路由。GID基于IPv6地址格式，通常由子网前缀（64位）和端口GUID（64位）组成。

在RoCE v2网络中，GID直接使用IP地址作为路由依据。

```
GID格式 (128 bits):
┌──────────────────────────────┬──────────────────────────────┐
│       子网前缀 (64 bits)      │      端口GUID (64 bits)       │
├──────────────────────────────┼──────────────────────────────┤
│ 0xFE80:0000:0000:0000        │ 0x0002:C903:00A3:45B7        │
└──────────────────────────────┴──────────────────────────────┘
```

典型的RoCE GID：
```
GID: fe80::2:c903:a3:45b7
```

在创建AH（Address Handle）或修改QP到RTR状态时，需要指定对端的GID。对于RoCE v2，GID就是网卡的IP地址。

### P_Key（Partition Key）

P_Key是InfiniBand网络中用于隔离的16位标识符，类似于虚拟局域网（VLAN）的概念。只有具有相同P_Key的端口才能相互通信。

## RDMA中的地址相关操作

### 获取GID

在Verbs API中，获取GID的接口为：

```c
union ibv_gid gid;
ibv_query_gid(ctx, port, index, &gid);
```

其中`index`表示GID索引，因为一个端口可能配置多个GID（不同子网前缀或IP地址）。

### L_Key与R_Key

注册MR时会产生两个Key：

- **L_Key（Local Key）**：用于本端访问MR时的权限校验。当用户通过SGE（Scatter/Gather Element）指定本地内存缓冲区时，需要提供L_Key。
- **R_Key（Remote Key）**：用于远端访问本端MR时的权限校验。当对端节点发起RDMA READ/WRITE操作访问本端内存时，需要提供R_Key。

L_Key和R_Key都是32位的整数，由两部分组成：

```
Memory Key (32 bits):
┌──────────────────────────────┬──────────────┐
│      Key Handle (24 bits)    │    Key (8)   │
├──────────────────────────────┼──────────────┤
│  用于索引MTT/MPT中的条目      │  校验码/密钥 │
└──────────────────────────────┴──────────────┘
```

- **Key Handle（24位）**：HCA用这个字段快速索引到MTT/MPT中对应的条目，找到地址映射和权限信息。
- **Key（8位）**：用于校验，防止用户随意编造Key Handle来访问未经授权的内存区域。

当对端持有正确的R_Key时，HCA才允许其对对应的MR进行指定的操作（如RDMA READ/WRITE）。

## 页大小与RDMA

### 系统页大小

不同的体系结构支持不同的页大小：

| 体系结构 | 标准页大小 | 大页选项 |
|----------|-----------|---------|
| x86_64 | 4KB | 2MB, 1GB |
| ARM64 | 4KB | 2MB, 1GB |
| PowerPC | 64KB | 16MB, 16GB |

### 页大小对RDMA的影响

在注册MR时，注册的内存区域必须是页对齐的，并且注册的大小也会按页向上取整。使用大页（Huge Page）可以减少以下开销：

1. **减少页表项数量**：2MB的大页比4KB的标准页减少512倍页表项数量
2. **减少TLB缺失**：更大的页映射可以覆盖更多的内存范围
3. **减少MTT条目数**：RDMA网卡的MTT也受益于更大的映射粒度

对于需要大量注册MR的应用（如存储服务器、数据库），使用大页可以显著提升性能。

### 注册MR的页对齐要求

```c
// 注册任意地址的示例
void *buf = malloc(4096);
// 注意：malloc返回的地址不一定是页对齐的
  
// 更好的做法：使用页对齐的内存
void *buf;
posix_memalign(&buf, 4096, 4096);

// 注册MR
struct ibv_mr *mr = ibv_reg_mr(pd, buf, 4096, access_flags);
```

驱动在注册MR时，会将对齐要求之外的额外内存也锁定（页对齐），因此注册的起始地址和结束地址会被扩展到页边界。

## 地址映射示例

下面通过一个完整的示例来说明RDMA WRITE操作中的地址映射流程：

```
假设场景：节点A向节点B执行RDMA WRITE操作

准备工作：
  1. 节点B注册MR: VA_B → PA_B, 生成R_Key_B
  2. 节点B将VA_B和R_Key_B通过某种方式告知节点A
  3. 节点A注册MR: VA_A → PA_A, 生成L_Key_A

RDMA WRITE执行：
  Step 1: 节点A的APP下发WQE到SQ
          WQE内容: { 源VA_A, 目的VA_B, 长度, L_Key_A, R_Key_B }

  Step 2: 节点A的HCA查询MTT
          VA_A → PA_A (找到数据在本地内存中的物理位置)

  Step 3: 节点A的HCA通过DMA从PA_A取出数据
          组装RDMA WRITE数据包（包含VA_B和R_Key_B）

  Step 4: 数据包通过网络到达节点B

  Step 5: 节点B的HCA解析数据包，提取VA_B和R_Key_B
          → 校验R_Key_B的合法性
          → 查询MTT: VA_B → PA_B

  Step 6: 节点B的HCA通过DMA将数据写入PA_B

  整个过程：节点B的CPU完全没有参与数据传输！
```

## 总结

内存地址是计算机系统的核心概念，也是理解RDMA技术的基础。在RDMA中，虚拟地址到物理地址的转换主要由HCA（通过MTT）完成，而非CPU的MMU。这种设计使得数据传输可以完全绕过CPU，实现真正的"直接内存访问"。

理解VA/PA的差异、MTT/MPT的作用、以及GID/LID等地址概念，对于深入理解RDMA的工作原理和进行RDMA编程都至关重要。
