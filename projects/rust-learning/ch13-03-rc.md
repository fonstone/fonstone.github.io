 <h1 id="为什么需要多所有权">为什么需要多所有权？</h1>
<p>Rust 的所有权规则确保每个值都有唯一的所有者，这是内存安全的基础。但在某些场景下，这条规则会成为障碍。</p>
<p>设想我们要构建这样一个图结构：两个列表 <code>b</code> 和 <code>c</code> 需要共享同一段数据 <code>a</code>。如果我们用 <code>Box&lt;T&gt;</code> 来实现，会遇到什么问题？</p>
<pre><code class="language-rust">// 这段代码无法编译！
enum List {
    Cons(i32, Box&lt;List&gt;),
    Nil,
}
use List::{Cons, Nil};

fn main() {
    let a = Cons(5, Box::new(Cons(10, Box::new(Nil))));
    let b = Cons(3, Box::new(a)); // a 的所有权移动到 b
    let c = Cons(4, Box::new(a)); // 错误！a 已经被移走了
}</code></pre>
<p>编译错误清晰地说明了问题：</p>
<pre><code class="language-text">error[E0382]: use of moved value: `a`
  --&gt; src/main.rs:13:30
   |
12 |     let b = Cons(3, Box::new(a));
   |                              - value moved here
13 |     let c = Cons(4, Box::new(a));
   |                              ^ value used here after move</code></pre>
<p><code>Box&lt;T&gt;</code> 独占所有权，一旦 <code>a</code> 被移入 <code>b</code>，就无法再被 <code>c</code> 使用。我们可以改用引用 <code>&amp;List</code>，但这会带来复杂的生命周期标注。在这种场景下，<code>Rc&lt;T&gt;</code> 才是正确的选择。</p>
<h1 id="rct-的工作原理"><code>Rc&lt;T&gt;</code> 的工作原理</h1>
<p><code>Rc&lt;T&gt;</code> 是 <strong>Reference Counting</strong>（引用计数）的缩写。它在堆上存储数据，同时维护一个计数器，记录当前有多少个地方持有这份数据的引用。</p>
<ul>
<li>每次调用 <code>Rc::clone</code>，计数器加 1</li>
<li>每当一个 <code>Rc&lt;T&gt;</code> 值离开作用域，计数器减 1</li>
<li>当计数器归零时，数据才会被真正释放</li>
</ul>
<p>让我们用 <code>Rc&lt;T&gt;</code> 改写上面的例子：</p>
<div class="code-runner" data-full-code="use%20std%3A%3Arc%3A%3ARc%3B%0A%0A%23%5Bderive(Debug)%5D%0Aenum%20List%20%7B%0A%20%20%20%20Cons(i32%2C%20Rc%3CList%3E)%2C%0A%20%20%20%20Nil%2C%0A%7D%0Ause%20List%3A%3A%7BCons%2C%20Nil%7D%3B%0A%0Afn%20main()%20%7B%0A%20%20%20%20let%20a%20%3D%20Rc%3A%3Anew(Cons(5%2C%20Rc%3A%3Anew(Cons(10%2C%20Rc%3A%3Anew(Nil)))))%3B%0A%20%20%20%20println!(%22%E5%88%9B%E5%BB%BA%20a%20%E5%90%8E%EF%BC%8C%E5%BC%95%E7%94%A8%E8%AE%A1%E6%95%B0%20%3D%20%7B%7D%22%2C%20Rc%3A%3Astrong_count(%26a))%3B%0A%0A%20%20%20%20let%20b%20%3D%20Cons(3%2C%20Rc%3A%3Aclone(%26a))%3B%20%2F%2F%20%E8%AE%A1%E6%95%B0%20%2B1%EF%BC%8Ca%20%E5%92%8C%20b%20%E5%85%B1%E4%BA%AB%E6%95%B0%E6%8D%AE%0A%20%20%20%20println!(%22%E5%88%9B%E5%BB%BA%20b%20%E5%90%8E%EF%BC%8C%E5%BC%95%E7%94%A8%E8%AE%A1%E6%95%B0%20%3D%20%7B%7D%22%2C%20Rc%3A%3Astrong_count(%26a))%3B%0A%0A%20%20%20%20%7B%0A%20%20%20%20%20%20%20%20let%20c%20%3D%20Cons(4%2C%20Rc%3A%3Aclone(%26a))%3B%20%2F%2F%20%E8%AE%A1%E6%95%B0%20%2B1%0A%20%20%20%20%20%20%20%20println!(%22%E5%88%9B%E5%BB%BA%20c%20%E5%90%8E%EF%BC%8C%E5%BC%95%E7%94%A8%E8%AE%A1%E6%95%B0%20%3D%20%7B%7D%22%2C%20Rc%3A%3Astrong_count(%26a))%3B%0A%20%20%20%20%7D%20%2F%2F%20c%20%E7%A6%BB%E5%BC%80%E4%BD%9C%E7%94%A8%E5%9F%9F%EF%BC%8C%E8%AE%A1%E6%95%B0%20-1%0A%0A%20%20%20%20println!(%22c%20%E7%A6%BB%E5%BC%80%E5%90%8E%EF%BC%8C%E5%BC%95%E7%94%A8%E8%AE%A1%E6%95%B0%20%3D%20%7B%7D%22%2C%20Rc%3A%3Astrong_count(%26a))%3B%0A%20%20%20%20%2F%2F%20%E7%A8%8B%E5%BA%8F%E7%BB%93%E6%9D%9F%EF%BC%8Cb%20%E5%92%8C%20a%20%E7%A6%BB%E5%BC%80%E4%BD%9C%E7%94%A8%E5%9F%9F%EF%BC%8C%E8%AE%A1%E6%95%B0%E5%BD%92%E9%9B%B6%EF%BC%8C%E5%86%85%E5%AD%98%E9%87%8A%E6%94%BE%0A%7D" data-mode="run"><pre><code class="language-rust">use std::rc::Rc;

#[derive(Debug)]
enum List {
    Cons(i32, Rc&lt;List&gt;),
    Nil,
}
use List::{Cons, Nil};

fn main() {
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    println!("创建 a 后，引用计数 = {}", Rc::strong_count(&amp;a));

    let b = Cons(3, Rc::clone(&amp;a)); // 计数 +1，a 和 b 共享数据
    println!("创建 b 后，引用计数 = {}", Rc::strong_count(&amp;a));

    {
        let c = Cons(4, Rc::clone(&amp;a)); // 计数 +1
        println!("创建 c 后，引用计数 = {}", Rc::strong_count(&amp;a));
    } // c 离开作用域，计数 -1

    println!("c 离开后，引用计数 = {}", Rc::strong_count(&amp;a));
    // 程序结束，b 和 a 离开作用域，计数归零，内存释放
}</code></pre></div>
<p>这次代码可以正常运行。<code>b</code> 和 <code>c</code> 都通过 <code>Rc::clone</code> 获得了 <code>a</code> 中数据的共享所有权。</p>
<h2 id="为什么用-rcclonea-而不是-aclone">为什么用 <code>Rc::clone(&amp;a)</code> 而不是 <code>a.clone()</code>？</h2>
<p>在技术上，两种写法都能编译。但 Rust 社区<strong>强烈推荐</strong>函数式写法 <code>Rc::clone(&amp;a)</code>，原因在于<strong>语义上的清晰区分</strong>：</p>
<ul>
<li><code>deep_clone()</code> 或 <code>.clone()</code>：通常意味着对数据的<strong>深拷贝</strong>，可能非常耗时（比如拷贝整个向量）。</li>
<li><code>Rc::clone(&amp;a)</code>：仅仅是<strong>增加一个计数器的值</strong>，无论数据有多大，这个操作都是 O(1) 的轻量级操作。</li>
</ul>
<p>当你阅读代码时，看到 <code>Rc::clone</code> 可以立刻判断”这里没有性能问题”；而看到 <code>.clone()</code> 则需要停下来思考是否会触发深拷贝。</p>
<h1 id="rct-的限制"><code>Rc&lt;T&gt;</code> 的限制</h1>
<p><code>Rc&lt;T&gt;</code> 的设计做了一个重要取舍：</p>
<p><strong>它只提供不可变引用。</strong> 在任何时候，你只能对 <code>Rc&lt;T&gt;</code> 内部的数据进行只读访问。</p>
<p>这是必要的安全保障：如果允许多个所有者同时进行可变修改，就会产生数据竞争（即使在单线程中也会导致逻辑混乱）。</p>
<p>此外，<code>Rc&lt;T&gt;</code> <strong>只能用于单线程</strong>。它的引用计数操作不是原子性的，无法在线程之间安全地共享。如果你需要在多线程中共享数据，应该使用它的并发版本 <code>Arc&lt;T&gt;</code> (Atomic Reference Counting)，这将在<a href="/RustCourse/chapters/14-concurrency/00-index">并发编程</a>章节中介绍。</p>
<p>如果你既需要多所有权，又需要可变性，就需要将 <code>Rc&lt;T&gt;</code> 与下一节介绍的 <code>RefCell&lt;T&gt;</code> 组合使用。</p>
