# 教程介绍

大家好，我是博主雪云飞星。我在汽车嵌入式行业从事 AUTOSAR 和系统架构相关工作多年。在这个领域，RTOS 是一个再熟悉不过的词——FreeRTOS、AUTOSAR OS、各种商用内核，调度器、任务、中断……这些概念天天见，用得熟练，却始终隔着一层：**知道怎么用，但不知道里面是怎么跑的。**

后来开始学 Rust，发现 Rust 嵌入式方向的中文资料相当稀缺——大部分教程止步于点灯或串口输出，真正从零跑通一个调度器的完整记录几乎找不到。既然要补这个空缺，不如干脆写一个真正能跑任务调度的 RTOS，顺便把"里面是怎么跑的"这个问题彻底搞清楚。

这套教程，就是"从零写一个 Rust RTOS"过程的文字化。我们会用 Rust 在 QEMU 模拟的 ARM Cortex-R52 上，从最原始的裸机启动开始，一步一步亲手实现一个能用的简易操作系统内核——串口调试、异常向量表、系统定时器、上下文切换、优先级调度器，最后到任务间通信。

没有任何库，没有 HAL，只有你、Rust、和一块虚拟的 ARM 芯片。

**读完文章再看 参考代码工程 project_ref** ，每章都有对应的 __[project_ref](https://github.com/xyfx-fhw/RustRTOS/tree/master/project_ref)__ 参考实现。建议先自己动手写，遇到问题再参考，而不是一开始就抄答案。过一遍完整的实现过程，对理解远比直接复制代码有效。

## 这套教程会构建什么

完成本教程后，你将拥有一个运行在 QEMU 上的、由你亲手写出的简易 RTOS 内核，它具备：

- 从汇编 reset handler 启动，跳入 Rust `main`
- 通过 UART 输出调试信息（`println!` 宏）
- 处理 FIQ 定时器中断（GIC + 定时器初始化）
- 多任务上下文切换（基于 SVC 栈帧保存 / 恢复）
- 优先级抢占式调度器（sleep_ticks 真睡眠 + FIQ 自动唤醒）
- 任务间共享内存 IPC（自旋锁 + SPSC 无锁环形缓冲区）

这不是一个玩具 demo——每一章的实现都遵循真实内核的设计思路。读完之后，看 FreeRTOS 源码、看 Linux 调度器，你会觉得亲切很多。

## 这套教程不是什么

**不是生产级 RTOS 教程。** 我们的调度器没有优先级继承，没有 MPU 保护，没有 tickless idle。真实的嵌入式项目请用 FreeRTOS 或 Zephyr。

**不是 ARM 架构完整教程。** 我们只用到 Cortex-R52 的一个子集——够跑调度器就够了。寄存器 banked 机制、TrustZone 等话题只在必要时讲，不展开。

**不是 Rust 入门教程。** 本教程假设你已经能写基本的 Rust 代码。如果你还在学 Rust 基础，建议先读我的另一套教程 [Rust 互动教程](https://xyfx-fhw.github.io/RustCourse/)，再回来。

这套教程的定位只有一件事：**让你真正理解一个简易 Rust 内核是怎么跑起来的。**

# 如何学习本教程

## 前置知识

**需要的：**

- Rust 基础：所有权、借用、`unsafe`、裸指针、`static mut` 的大致概念
- 基本的 C/汇编阅读能力（不需要会写，能看懂就行）
- 知道什么是寄存器、什么是栈（大致概念，不需要深入），有基础的嵌入式开发经验

**不需要的：**

- ARM 架构知识（教程里遇到什么讲什么）
- Linux 或 OS 理论课背景（我们不依赖理论，直接动手）

如果你有 C 嵌入式或 AUTOSAR 背景，学起来会更顺——很多概念你已经在实践中见过，只是没有用 Rust 实现过。

## 完成本教程需要多长时间

**建议学习周期是 3-4 周**，每天投入 1-2 小时。

| 阶段 | 章节 | 建议时间 | 关键挑战 |
| --- | --- | --- | --- |
| 地基阶段 | 第 01-03 章 | 第 1 周 | 配置工具链、第一次看到串口输出 |
| 中断阶段 | 第 04-05 章 | 第 2 周 | 理解 ARM 异常模型、GIC 配置 |
| 调度器阶段 | 第 06-07 章 | 第 2-3 周 | 栈帧布局、SRSDB/RFEIA 汇编 |
| IPC 阶段 | 第 08-09 章 | 第 4 周 | 内存序、无锁数据结构 |

第 06-07 章是本教程最难的部分——上下文切换的汇编、16 字栈帧布局、FIQ banking 限制，第一次接触会花比较多时间。这里多花一倍时间是正常的，不要着急。

## 学习曲线与心理准备

裸机调试和普通开发有一个很不一样的地方：**程序挂掉了通常什么都不打印。**

串口没输出？可能是 UART 没初始化，可能是代码跑到非法地址了，可能是链接脚本地址错了。你要学会用二分法缩小范围，用 `println!` 打桩，用 QEMU 的 `-d int` 标志捞异常日志。这个技能没有捷径，练几次自然就有感觉。

另一个心理准备：Rust 的 `unsafe` 在这里会大量出现。裸机代码本质上就是在操作硬件寄存器和手动管理内存，这是 Rust `unsafe` 存在的合理场景，不要被它吓到，也不要滥用它——每个 `unsafe` 块都应该有明确的理由。

## 学习建议

### 先跑起来，再理解

每章都会有完整的代码示例和预期输出。建议先照着敲进去跑通，看到预期输出之后，再回头理解每个步骤的原理。跑不通的代码很难建立直觉，跑通之后的阅读事半功倍。

### 不要跳过汇编部分

调度器章节有几段关键汇编（`context_switch`、`fiq_handler`、`start_first_task`）。很多人看到汇编就想跳过——不要这样做。这几段代码每一行都有具体的理由，文章里会逐行解释。把它们理解透，你就真正理解了 RTOS 的核心机制。

### 用 QEMU 调试要善用 `-d int`

```bash
qemu-system-arm -machine mps3-an536 -nographic \
  -device loader,file=target/... \
  -d int 2>qemu_int.log
```

这会把所有异常和中断记录到 `qemu_int.log`，当程序卡住或崩溃时，这个文件是第一个要看的地方。
