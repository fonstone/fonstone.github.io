# 裸机程序和普通程序的区别

平时写的程序——无论是 Python 脚本还是一个 Rust 命令行工具——其实都运行在操作系统提供的"舒适环境"里：

- 操作系统帮你把程序加载进内存，设置好栈空间
- 操作系统提供系统调用，让你能读写文件、分配内存、打印输出
- 程序崩溃了，操作系统会帮你回收资源

**裸机程序（bare-metal）没有这些。** 处理器上电后，没有操作系统，没有运行时，没有任何人帮你准备环境。CPU 直接从一个固定的内存地址开始执行指令，那里有什么代码就执行什么。

可以用"搬家"来类比：普通程序像入住一间精装公寓，家具齐全、水电全通，拎包即住；裸机程序像接手一个毛坯房，四面白墙，什么都没有，你得先把水电拉好、地板铺好，才能住人。

> **提示：** 这也是为什么裸机 Rust 要写 `#[no_std]`——告诉编译器不要链接依赖操作系统的标准库（`std`），改用不依赖操作系统的 `core`。

# Cortex-R52 上电后发生了什么

当 QEMU 模拟的 mps3-an536 开发板"上电"时，Cortex-R52 处理器会做这几件事：

**第一步：跳到复位向量（Reset Vector）。** 处理器从固定地址 `0x00000000` 读取第一条指令并开始执行。这个地址就是**复位向量**——它是整个系统启动的起点。我们必须在链接脚本里确保自己的代码被放到这个地址。

**第二步：处理器处于原始状态。** 此时没有栈、没有初始化好的内存，BSS 段（存放未初始化的全局变量）内容未知，数据段（存放有初值的全局变量）还躺在 Flash 里没有被复制到 RAM。如果直接跳进 Rust 代码，任何函数调用都会因为没有栈而崩溃。

**第三步：需要我们自己做初始化。** 在跳进 Rust 之前，必须用一小段汇编代码完成：

1. 设置栈指针（`SP` 寄存器）→ 有了栈，函数才能调用
2. 清零 BSS 段 → 未初始化变量才符合 C/Rust 的语义
3. 把数据段从 Flash 复制到 RAM → 有初值的全局变量才能正确使用
4. 跳转到 Rust 入口函数

这段汇编代码通常叫做 **reset handler**（复位处理程序）。

```quiz single
Q: 裸机程序和普通程序最根本的区别是什么？
- 裸机程序不能使用 Rust 编写，只能用 C 或汇编
- 裸机程序运行速度更慢，因为没有操作系统优化
+ 裸机程序没有操作系统提供运行环境，需要自己完成栈初始化、内存初始化等工作
- 裸机程序只能在真实硬件上运行，不能在 QEMU 上模拟
E: 裸机程序的本质是"没有操作系统"。这意味着程序加载、栈设置、内存初始化等一切工作都需要自己完成，而不是依赖 OS。裸机 Rust 可以正常工作，也可以在 QEMU 上运行。
```

```quiz single
Q: Cortex-R52 上电后，CPU 从哪个地址开始执行指令？
+ 固定地址 0x00000000（复位向量）
- 由操作系统动态分配的地址
- 程序的 main 函数地址
- RAM 的起始地址
E: Cortex-R52 上电后，CPU 硬件规定从 0x00000000 读取第一条指令执行，这个地址就是复位向量。我们通过链接脚本确保 reset handler 被放在这个地址。
```

```quiz single
Q: 为什么在跳进 Rust 代码之前，必须先用汇编设置栈指针？
- 因为 Rust 不支持直接操作寄存器
- 因为 Rust 的 #[no_std] 属性会禁用默认的栈分配
- 因为 QEMU 要求所有程序必须先设置栈指针
+ 因为函数调用依赖栈来保存返回地址和局部变量，没有栈就无法进行任何函数调用
E: 函数调用时，CPU 用栈来存放返回地址、函数参数和局部变量。如果栈指针（SP 寄存器）没有指向一块合法的 RAM 区域，第一次函数调用就会写入非法内存，导致程序崩溃或行为不可预期。
```

```quiz single
Q: 裸机 Rust 程序为什么要写 #[no_std]？
- 因为 std 标准库在 nightly 版本中不可用
+ 因为 std 依赖操作系统提供的功能（如文件系统、线程），裸机环境没有这些，需要换用不依赖 OS 的 core 库
- 因为 #[no_std] 能让程序编译更快
- 因为 QEMU 不支持运行链接了 std 的程序
E: std 标准库的很多功能（打印、文件操作、线程等）依赖操作系统的系统调用。裸机没有 OS，这些调用无处响应。#[no_std] 告诉编译器换用 core 库，它只提供不依赖 OS 的纯语言层面功能。
```
